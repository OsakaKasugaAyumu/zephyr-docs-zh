调试探针（Debug Probes）

非官方简体中文译本 · 英文基线 4.5.99 · B06 · 全站目录（79 篇） · B 批目录 · 本页英文原文

调试探针（debug probe）是一种专用硬件，可控制另一块开发板上 Zephyr 应用程序的执行。通常可以用它读写寄存器和内存，并在主机上用 GDB 等工具进行断点调试。有些探针还支持其他调试软件或跟踪程序执行（tracing）等高级功能。Zephyr 支持的配套主机软件见主机端烧写与调试工具。

调试探针通常通过 USB 连接主机，有些也支持通过 IP 网络或其他方式访问。探针一般通过 JTAG 或 SWD 与运行 Zephyr 的目标设备通信。它既可以是独立设备，也可以是集成在目标板上的电路。

许多受 Zephyr 支持的开发板配有第二颗微控制器，兼作板载调试探针和 USB 转串口适配器，有些还支持拖放烧写。这样无需另购外部探针，主机端也有多种调试工具可选。

多家厂商提供自己的板载探针。NXP 开发板根据运行探针固件的微控制器型号，可能采用 OpenSDA、LPC-Link2 或 MCU-Link；ST 开发板则配备ST-LINK 探针。探针微控制器可支持一种或多种与主机工具配套的固件。例如，OpenSDA 刷入 DAPLink 固件后可以与 pyOCD 或 OpenOCD 通信，刷入 J-Link 固件后则可与 J-Link 主机工具通信。

有些受支持的开发板没有板载调试探针，必须外接探针。另一些即使有板载探针，也预留了 SWD 或 JTAG 接口，允许改用外部探针。例如，板载探针可能不支持高级调试器或高速跟踪。使用外部探针时，可能需要调整跳线，避免板载探针干扰。

NXP 板载调试探针

NXP 棋盘可能有一个在船上调试探针。 这些探测器包括 MCU-Link 板载调试探针,LPC-LINK2 板载调试探针 和OpenSDA 板载调试探针。 每个这些探测器都是作为评估板上的二级微控制器执行的。 在特定的棋盘上显示的特定调试探针类型可以根据调试微控制器 SOC 确定 :

  • LPC55S69: MCU-Link 板载调试探针 (英语).

  • LPC4322: LPC-LINK2 板载调试探针 (英语).

  • MK20: OpenSDA 板载调试探针 (韩语).

例如,FRDM-K64F板有一个MK20调试微控制器,所以这个板使用OpenSDA 板载调试探针.

MCU-Link 板载调试探针

板载的MCU-Link调试探针使用LPC55S69 SOC. 这个探测器支持以下固件:

  • MCU-Link CMSIS-DAP 板载调试探针 (默认固件)

  • MCU-Link JLink 板载调试探针

这个探测器是使用MCU-Link主机工具编程的,这些工具安装在链接服务器调试主机工具. NXP建议使用NXP的MCUXpresso 安装器安装Linkserver工具.

MCU-Link CMSIS-DAP 板载调试探针

这是 MCU-Link 探针预装的固件。支持 CMSIS-DAP 的工具链均可用来调试，包括 IAR EWARM、Keil MDK、NXP 的 MCUXpresso IDE 及其 VS Code 扩展。MCU-Link 除了用于调试，还可能提供以下功能：

  1. SWO 跟踪端点：MCUXpresso 通过此虚拟设备读取 SWO 跟踪数据。详见 MCUXpresso IDE 文档。

  2. 连接目标处理器的虚拟串口（VCOM）／UART 桥接器

  3. USB 转 UART、SPI 或 I2C 接口（具体组合取决于 MCU-Link 型号和实现）

  4. 测量目标 MCU 的能耗

此调试探针兼容以下主机调试工具：

  • 链接服务器调试主机工具

安装 MCU-Link 主机工具后，按以下步骤烧写 CMSIS-DAP 固件：

  1. 确认主机上已安装 MCU-Link 实用程序。可通过安装链接服务器调试主机工具获得。

  2. 装上 DFU 跳线，再连接板上的 USB 调试端口，使 MCU-Link 微控制器进入 DFU 启动模式。该跳线也称 ISP 跳线，连接 LPC55S69 的 PIO0_5。

  3. 运行 MCU-Link 安装目录下 scripts 文件夹中的 program_CMSIS 脚本。

  4. 取下 DFU 跳线，将开发板断电后重新上电。

MCU-Link JLink 板载调试探针

这个调试探针固件提供了JLink兼容调试接口,以及USB-Serial适配器。它与以下调试主机工具兼容:

  • J- 链接调试主机工具

这些探测器没有默认安装JLink固件,必须更新. MCU-Link主机工具安装后,需要以下步骤来编程JLink固件:

  1. 确认主机上已安装 MCU-Link 实用程序。可通过安装链接服务器调试主机工具获得。

  2. 装上 DFU 跳线，再连接板上的 USB 调试端口，使 MCU-Link 微控制器进入 DFU 启动模式。该跳线也称 ISP 跳线，连接 LPC55S69 的 PIO0_5。

  3. 运行 MCU-Link 安装目录下 scripts 文件夹中的 program_JLINK 脚本。

  4. 取下 DFU 跳线，将开发板断电后重新上电。

LPC-LINK2 板载调试探针

LPC-LINK2板载调试探针使用LPC4322 SOC. 此探测器支持以下固件: 1.

  • LPC-LINK2 CMSIS DAP 板载调试探针

  • LPC-Link2 J-Link 板载调试探针

  • LPC-Link2 DAPLink 板载调试探针 (默认固件)

这个探测器是使用 LPCScrypt 主机工具编程的,这些工具安装在链接服务器调试主机工具. NXP建议使用NXP的MCUXpresso 安装器来安装Linkserver工具.

LPC-LINK2 CMSIS DAP 板载调试探针

CMSIS-DAP调试探针允许从任何兼容的工具链调试,包括IAR EWARM,Keil MDK,以及NXP的MCUXpresso IDE和MCUXpresso为VS代码扩展的调试. LPC-Link2探测器除了提供调试探测功能外,还提供了:

  1. SWO 跟踪端点：MCUXpresso 通过此虚拟设备读取 SWO 跟踪数据。详见 MCUXpresso IDE 文档。

  2. 连接目标处理器的虚拟串口（VCOM）／UART 桥接器

  3. LPCSIO 桥,提供与 I2C 和 SPI 外围设备的通信

此调试探针固件与以下调试主机工具兼容:

  • 链接服务器调试主机工具

该探测器可更新为使用CMSIS-DAP固件,其步骤如下:

  1. 确认主机上已安装 LPCScrypt 实用程序。可通过安装链接服务器调试主机工具获得。

  2. 装上 DFU 跳线，再连接板上的 USB 调试端口，使 LPC-Link2 微控制器进入 DFU 启动模式。该跳线连接 LPC4322 的 P2_6。

  3. 运行 LPCScrypt 安装目录下 scripts 文件夹中的 program_CMSIS 脚本。

  4. 取下 DFU 跳线，将开发板断电后重新上电。

LPC-Link2 J-Link 板载调试探针

说明

这个调试探针固件提供了JLink兼容调试接口,以及USB-Serial适配器。它与以下调试主机工具兼容:

  • J- 链接调试主机工具

  2. 装上 DFU 跳线，再连接板上的 USB 调试端口，使 LPC-Link2 微控制器进入 DFU 启动模式。该跳线连接 LPC4322 的 P2_6。

LPC-Link2 DAPLink 板载调试探针

LPC- Link2 DAPLink 固件是在基于 LPC- Link2 的板上发送的默认固件,但不是推荐的固件。 用户应该按照上面提供的指示更新到LPC-LINK2 CMSIS DAP 板载调试探针 固件。 关于DAPLink 固件编程的细节, 请参见NXP 安13206号。

OpenSDA 板载调试探针

板载调试探针OpenSDA基于NXP MK20 SOC. 它具有拖放编程支持功能,并支持以下调试固件:

  • OpenSDA DAPLink 板载调试探针 (默认固件)

  • OpenSDA J-Link 板载调试探针

OpenSDA DAPLink 板载调试探针

此调试探针固件与以下调试主机工具兼容:

  • pyOCD 调试主机工具

  • OpenOCD 调试主机工具

  • 链接服务器调试主机工具

这个探测器是通过DAPLink OpenSDA固件编程OpenSDA微控制器实现的. NXP 提供OpenSDA DAPLink 董事会- 特定公司软件.

在程序化固件之前安装调试主机工具。

如同所有OpenSDA调试探针一样,固件编程的步骤有:

  1. 按住复位按钮并给开发板上电，使 OpenSDA 微控制器进入引导程序（bootloader）模式。注意：进入此模式的是 OpenSDA 微控制器，而不是运行 Zephyr 应用的目标微控制器。

  2. 上电后松开复位按钮。主机会识别出名为 BOOTLOADER 或 MAINTENANCE 的 USB 大容量存储设备。如果设备名为 BOOTLOADER，请先按更新 DAPLink 引导程序（bootloader）中的说明将引导程序更新到最新版。

  3. 将 OpenSDA 固件二进制文件复制到该 USB 大容量存储设备。

  4. 将开发板断电后重新上电，这次不要按住复位按钮。主机应识别出三个 USB 设备：CDC 设备（串口）、HID 设备（调试端口）和大容量存储设备（用于拖放烧写）。

OpenSDA J-Link 板载调试探针

此调试探针兼容以下主机调试工具：

  • J- 链接调试主机工具

这个探测器是通过用 J-Link OpenSDA 固件编程 OpenSDA 微控制器实现的. Segger 提供了OpenSDA J-Link 通用公司软件 和OpenSDA J- Link 棋盘- 特定固件, 后者在可用时一般是推荐的. i. MX RT 板需要董事会特定的固件来支持其外部闪存记忆, 而通用固件则兼容所有 Kinetis 板.

在程序化固件之前安装调试主机工具。

如同所有OpenSDA调试探针一样,固件编程的步骤有:

  1. 按住复位按钮，将 USB 线插入开发板的 USB 调试端口，使 OpenSDA 微控制器进入引导程序（bootloader）模式。进入此模式的是 OpenSDA 微控制器，而不是运行 Zephyr 应用的目标微控制器。

  2. 上电后松开复位按钮。主机会识别出名为 BOOTLOADER 或 MAINTENANCE 的 USB 大容量存储设备。如果设备名为 BOOTLOADER，请先按更新 DAPLink 引导程序（bootloader）中的说明将引导程序更新到最新版。

  3. 将 OpenSDA 固件二进制文件复制到该 USB 大容量存储设备。

  4. 将开发板断电后重新上电，这次不要按住复位按钮。主机应识别出两个 USB 设备：CDC 设备（串口）和厂商专用设备（调试端口）。

J-Link 外部调试探针

赛格·J·林克是一个由外部调试探针组成的家族,包括J-Link EDU,J-Link PLUS,J-Link ULTRA+,以及J-Link PRO,它们支持来自不同硬件架构和供应商的大量设备.

此调试探针兼容以下主机调试工具：

  • J- 链接调试主机工具

  • OpenOCD 调试主机工具

在程序化固件之前安装调试主机工具。

ST-LINK/V2-1 板载调试探针

ST-LINK/V2-1 是 Nucleo 和 Discovery 系列板上的串口与调试适配器。它通过一根 USB 线在计算机（或其他 USB 主机）与嵌入式目标处理器之间建立连接，可用于调试、闪存编程和串口通信。

支持以下主机端调试工具：

  • OpenOCD 调试主机工具

  • J- 链接调试主机工具

  • STM32CubeCLT 主机烧写与调试工具

在部分 STM32 开发板上，还支持：

  • pyOCD 调试主机工具

OpenOCD 开箱即可使用；若要改用 J-Link，需要先更新探针固件。SEGGER 为 Nucleo 和 Discovery 的板载 ST-LINK/V2-1 提供固件，使其兼容 J-Link OB。之后可使用 J-Link 的大部分功能，例如快速闪存下载与调试，以及免费使用的 GDBServer。

如何将 ST-LINK/V2-1 切换为 J-Link，或恢复为 ST-LINK/V2-1 固件，请参阅 在 ST-LINK 上使用 SEGGER 固件。

使用 ST-LINK 烧写与调试

默认的 ST-LINK 支持 OpenOCD，后者配置为默认烧写与调试工具。操作如下：

# From the root of the zephyr repository
west build -b None samples/hello_world
west flash

# From the root of the zephyr repository
west build -b None samples/hello_world
west debug

将 SEGGER 固件写入 ST-LINK，并在主机安装 J-Link GDB Server 后，可按以下方式烧写与调试：

调用 CMake 时传入 -DBOARD_FLASH_RUNNER=jlink，可将默认后端从 OpenOCD 改为 J-Link。也可在应用的 CMakeList.txt 文件中加入以下语句。

set(BOARD_FLASH_RUNNER jlink)

使用 west（Zephyr 元工具）时，可用 --runner（或 -r）选项更改默认后端。

west flash --runner jlink

使用 jlink 连接到开发板上的目标并打开调试控制台。

west debug --runner jlink

west 及其选项的详细说明见West：Zephyr 的元工具（meta-tool）。

如果应用改用了 SEGGER RTT 控制台，请打开 telnet：

$ telnet localhost 19021

更新或恢复 ST-LINK 固件

可使用 STM32CubeProgrammer 工具 更新 ST-LINK 固件。遇到烧写问题时（例如使用 twister 的设备测试选项时），更新固件通常有帮助。

安装后，可通过以下命令更新已连接开发板的 ST-LINK 固件：

s java -jar ~/STMicroelectronics/STM32Cube/STM32CubeProgrammer/Drivers/FirmwareUpgrade/STLinkUpgrade.jar -sn <board_uid>

其中 board_uid 可通过 twister 的 generate-hardware-map 选项获取。twister 及其选项详见测试运行器（Twister）。

OpenOCD 弃用 ST-LINK 的 HLA 接口

2024 年 1 月，OpenOCD 弃用 ST-LINK 固件使用的旧 HLA 接口，改用通用 DAP 接口（见OpenOCD 弃用 ST-LINK HLA 接口的说明）。ST-LINK 固件从 2015 年的 v2j24 版起就支持 DAP。

使用 v0.12.0 发布标签之后的新版 OpenOCD 时，如果 ST-LINK 固件早于 v2j24，可能出现通信问题。此时建议更新固件（参阅更新 ST-LINK 固件）。若无法更新，也可修改 OpenOCD 配置脚本以继续使用旧 HLA 接口：若存在以下两行，

source [find interface/stlink-dap.cfg]
transport select dapdirect_swd

请将它们替换为这两行：

source [find interface/stlink-hla.cfg]
transport select hla_swd

NXP S32 调试探针

NXP S32 调试探针 通过标准调试端口调试 NXP S32 目标系统；与开发工作站之间可用 USB 直连，也可通过以太网远程连接。

NXP S32 调试探针面向 NXP S32 Design Studio（S32DS）以及 NXP 车用微控制器和处理器。写入固件之前，请按NXP S32 调试探针主机工具安装主机调试工具。

Black Magic Probe

Black Magic Probe 是配合 Black Magic Debug 固件使用的开源调试硬件。固件内置 GDB Server，因此可以直接从 gdb 连接到目标设备。

部分基于 STM32F103 的开发板可以运行 Black Magic Debug 固件。见Black Magic Debug 支持的硬件。
