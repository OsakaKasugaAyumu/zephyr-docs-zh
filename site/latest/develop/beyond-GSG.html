入门之后

非官方简体中文译本 · 英文基线 4.5.99 · A01 · 全站目录（94 篇） · A 批目录 · 本页英文原文

入门指南介绍了如何在 Linux、macOS 或 Windows 上搭建 Zephyr 开发环境。本文进一步说明配置时可能遇到的问题，并介绍其他可选方案。

Python 与 pip

Zephyr 广泛使用 Python 3 及其包管理器 pip[1] 来安装和运行脚本。这些脚本用于编译和运行 Zephyr 应用、搭建和维护开发环境，以及构建项目文档。

安装新包时，有些操作系统要求给 pip3 命令加上 --user 选项，后文会在相应步骤中注明。有关 pip[1] 的详情，请参阅《Python 打包用户指南》中的安装软件包，其中也有关于 --user 选项的说明。

  • 在 Linux 上，请确保 ~/.local/bin 位于 PATH 环境变量的开头，否则系统将找不到通过 --user 安装的程序。使用 --user 安装可避免 pip 与系统包管理器发生冲突；这是基于 Debian 的发行版上的默认行为。

  • 在 macOS 上，Homebrew 禁用了 --user。

  • 在 Windows 上，如需使用此选项，请参阅安装软件包中有关 --user 的说明。

在所有操作系统上，pip 的 -U 选项都会安装指定的包；若本机已安装该包且有更新版本，则更新它。需要某个包的最新版本时，建议使用此选项。（可查看 scripts/requirements.txt，确认是否要求特定的 Python 包版本。）

安装工具链

Zephyr 二进制文件由工具链（toolchain）编译和链接。工具链包含交叉编译器及其配套工具，不同于为主机操作系统开发原生软件时使用的编译器和工具。

安装 Zephyr SDK，可获取面向所有受支持架构的工具链；也可以安装 SoC 厂商或特定开发板推荐的其他工具链（请查阅相应的开发板文档）。

要让 Zephyr 构建系统使用指定工具链，可将 ZEPHYR_TOOLCHAIN_VARIANT 等环境变量（environment variables）设为受支持的值，并设置该工具链变体所需的其他变量。

更新 Zephyr SDK 工具链

更新 Zephyr SDK 时，先检查是否已设置环境变量 ZEPHYR_TOOLCHAIN_VARIANT 或 ZEPHYR_SDK_INSTALL_DIR。

  • 如果两者都未设置，默认会选择最新的兼容版 Zephyr SDK。无需更改，继续下一步即可。

  • 若已设置 ZEPHYR_TOOLCHAIN_VARIANT，构建时就会选择相应工具链。Zephyr SDK 对应的值为 zephyr。如果环境变量 ZEPHYR_TOOLCHAIN_VARIANT 的值不是 zephyr，请取消设置或将它改为 zephyr，确保选中 Zephyr SDK。

  • 若已设置环境变量 ZEPHYR_SDK_INSTALL_DIR，它将覆盖 Zephyr SDK 的默认查找位置。如果将 SDK 安装在建议位置之一，可以取消设置该变量；否则请将它设为实际安装目录。

关于这些 Zephyr 环境变量，请参阅重要环境变量。

克隆 Zephyr 仓库

Zephyr 项目源码维护在 GitHub 上的 zephyr 仓库 中。Zephyr 使用的外部模块可在其所属的 GitHub 上的 Zephyr 项目 中找到。由于这些依赖关系，使用 Zephyr 项目开发的 west 工具可以方便地获取和管理 Zephyr 及外部模块的源码。详见基础知识。

安装开发工具后，使用 west（Zephyr 的元工具） 创建并初始化工作区，从 zephyr 和外部模块仓库下载源码。这里使用目录名 zephyrproject；也可自行命名，但整个路径中都不能有空格。

west init zephyrproject
cd zephyrproject
west update

west update 命令会获取模块（外部项目），并使 zephyrproject 目录中的这些模块与本地 zephyr 仓库的代码保持同步。

警告

只要 zephyr/west.yml 有变动，就必须运行 west update。例如，拉取 zephyr 仓库、在其中切换分支或执行 git bisect 都可能导致该文件变化。

更新 Zephyr 源码

要更新 Zephyr 项目源码，请先通过 git 获取最新更改，然后按上一段所述运行 west update。还要检查 Python 依赖项是否有更新或新增。

# replace zephyrproject with the path you gave west init
cd zephyrproject/zephyr
git pull
west update
west packages pip --install

:: replace zephyrproject with the path you gave west init
cd zephyrproject\zephyr
git pull
west update
cmd /c scripts\utils\west-packages-pip-install.cmd

# replace zephyrproject with the path you gave west init
cd zephyrproject\zephyr
git pull
west update
python -m pip install @((west packages pip) -split ' ')

导出 Zephyr CMake 包

如果还没有按照入门指南完成这一步，可以将 Zephyr CMake 包 导出到 CMake 的用户包注册表。

开发板别名

同时使用多块板时，每次写出完整板名可能很不方便。可为常用目标设置别名：先编写一个内容类似下面示例的 CMake 文件，

# Variable foo_BOARD_ALIAS=bar replaces BOARD=foo with BOARD=bar and
# sets BOARD_ALIAS=foo in the CMake cache.
set(pca10028_BOARD_ALIAS nrf51dk/nrf51822)
set(pca10056_BOARD_ALIAS nrf52840dk/nrf52840)
set(k64f_BOARD_ALIAS frdm_k64f)
set(sltb004a_BOARD_ALIAS efr32mg_sltb004a)

再用 ZEPHYR_BOARD_ALIASES 指定其位置。之后就可以在 cmake -DBOARD=pca10028、west -b pca10028 等命令中使用 pca10028 这样的别名。

构建并运行应用

在受支持的主机系统上，可以构建 Zephyr 应用，将其烧写到实际硬件上运行。视操作系统而定，也可以通过 QEMU 仿真，或使用 native_sim 以主机原生程序的形式运行。更多构建说明见构建应用。

构建 Blinky

下面来构建 Blinky 示例应用。

Zephyr 应用针对特定硬件构建，这种硬件配置称为“开发板”（board）[2]。这里使用 Phytec 的 reel_board；如果使用其他板，请将构建目标 reel_board 替换为相应名称。支持的板可在支持的开发板与扩展板中查找，也可在 zephyrproject 目录下任意位置运行 west boards 列出。

  1. 进入 zephyr 仓库：

    cd zephyrproject/zephyr

  2. 为 reel_board 构建 blinky 示例：

    # From the root of the zephyr repository
west build -b reel_board samples/basic/blinky

主要构建产物位于 build/zephyr；build/zephyr/zephyr.elf 是 ELF 格式的 blinky 应用二进制文件。根据所用开发板，还可能生成其他格式的二进制文件、反汇编文件和链接映射文件（map file）。

samples 目录下的其他示例应用见示例与演示。

说明

若要将已有构建目录用于另一块板或另一个应用，请给 west build 加上 -p=auto，清除前一次构建的设置和产物。

将应用烧写到开发板并运行

对于 Zephyr 支持的大多数硬件板，运行 west flash 即可烧写；为使其正常工作，可能需要先安装并配置板卡专用工具。

更多细节见运行应用以及支持的开发板与扩展板中对应开发板的文档。

设置 udev 规则

烧写开发板需要直接访问硬件的权限，通常由烧写工具在安装时配置。在 Linux 上，如果 west flash 失败，可能需要定义 udev 规则来授予所需权限。

udev 是 Linux 内核的设备管理器。硬件设备接入或移除时，udev 守护进程负责处理由此产生的所有用户空间事件。添加规则文件，可允许非 root 用户访问指定的 USB 设备。

OpenOCD（片上调试器，On-Chip Debugger）项目提供的规则文件，已为 Zephyr 支持的大多数 Arm 板定义了相应规则。建议从其 SourceForge 仓库下载并安装该文件；如果已经安装 Zephyr SDK，SDK 目录中也有一份副本：

  • 可以下载 OpenOCD 规则文件并复制到相应位置：

    wget -O 60-openocd.rules https://sf.net/p/openocd/code/ci/master/tree/contrib/60-openocd.rules?format=raw
sudo cp 60-openocd.rules /etc/udev/rules.d

  • 或者，从 Zephyr SDK 目录复制规则文件：

    sudo cp ${ZEPHYR_SDK_INSTALL_DIR}/sysroots/x86_64-pokysdk-linux/usr/share/openocd/contrib/60-openocd.rules /etc/udev/rules.d

无论采用哪种方式，随后都要让 udev 守护进程重新加载规则：

sudo udevadm control --reload

拔下并重新接上开发板的 USB 连接，现在应已有权限访问硬件并执行烧写。更多信息请查阅对应板卡的文档（支持的开发板与扩展板）。

在 QEMU 中运行应用

如果目标架构是 x86 或 Arm Cortex-M3，可以使用 QEMU 在主机上仿真运行 Zephyr 应用。Zephyr SDK 自带 QEMU。

如果手动安装 QEMU，请确认系统能通过 PATH 环境变量找到它。

可设置 QEMU_BIN_PATH，覆盖 Twister 查找 QEMU 可执行文件的位置。如果提供此值，Twister 会验证路径是否存在；否则它通过 SDK 或其他机制查找 QEMU。

例如，可用以下命令针对 x86 仿真板配置（qemu_x86）构建并运行 Hello World 示例：

# From the root of the zephyr repository
west build -b qemu_x86 samples/hello_world
west build -t run

要退出 QEMU，请先按 Ctrl-a，再按 x。

使用 qemu_cortex_m3 可将示例的目标设为仿真的 Arm Cortex-M3。

在 Linux 主机上原生运行示例应用

部分示例可编译为 Linux 主机程序。详见原生模拟器（native_sim）。在 64 位主机操作系统上，需要安装 32 位 C 库，或将构建目标设为 native_sim/native/64。

首先，为 native_sim 构建 Hello World。

# From the root of the zephyr repository
west build -b native_sim samples/hello_world

然后运行应用。

west build -t run
# or just run zephyr.exe directly:
./build/zephyr/zephyr.exe

按 Ctrl-C 退出。

运行 ./build/zephyr/zephyr.exe --help 可列出可用选项。

可使用 gdb、valgrind 等标准工具对该可执行程序进行调试或插桩分析。

脚注

[1] (1,2)

pip 是 Python 的包安装工具。其 install 命令会先尝试复用计算机上已安装的包和依赖项；如果无法复用，pip install 会从互联网上的 Python 包索引（PyPI）下载它们。

Zephyr 的 requirements.txt 所要求的包版本可能与系统的其他要求冲突。这种情况下，可考虑为 Zephyr 开发单独创建一个虚拟环境（virtualenv）。

[2]

“开发板”这个名称如今并不总是贴切。目标可以是、也常常是运行在专用硬件板上的微处理器；但 Zephyr 也支持通过 QEMU 仿真运行针对其他架构构建的目标，支持生成主机原生二进制文件并通过 POSIX API 实现 Zephyr 驱动接口，还支持在同一物理芯片上、在不同架构的 CPU 核上运行不同的 Zephyr 二进制程序。这些硬件配置都称为“开发板”，尽管有些场景并没有一块实际的板。
