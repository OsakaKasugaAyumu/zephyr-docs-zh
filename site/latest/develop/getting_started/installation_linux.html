安装 Linux 主机依赖项

非官方简体中文译本 · 英文基线 4.5.99 · A02 · 全站目录（79 篇） · A 批目录 · 本页英文原文

以下 Linux 发行版有对应说明：

  • Ubuntu

  • Fedora

  • Clear Linux

  • Arch Linux

对于不采用滚动发布方式的发行版，其包管理器提供的软件可能不满足某些版本或依赖要求。此时请参照补充说明，从包管理器以外的来源获取所需软件。

说明

如果处于企业防火墙之后且尚未配置代理，可能需要先配置代理才能访问互联网。部分工具从环境变量 http_proxy 和 https_proxy 读取代理设置，另一些工具则使用自己的配置文件，尤其是 apt 和 git。

更新操作系统

确保主机系统已更新。

sudo apt-get update
sudo apt-get upgrade

sudo dnf upgrade

sudo swupd update

sudo pacman -Syu

安装所需工具和依赖项

以下步骤会同时安装 Ninja 和 Make；实际上只需要其中一个。

sudo apt-get install --no-install-recommends git cmake ninja-build gperf \
  ccache dfu-util device-tree-compiler wget \
  python3-dev python3-pip python3-setuptools python3-tk python3-wheel xz-utils file \
  make gcc gcc-multilib g++-multilib libsdl2-dev libmagic1

sudo dnf group install development-tools c-development
sudo dnf install cmake ninja-build gperf dfu-util dtc wget which \
  python3-pip python3-tkinter xz file python3-devel SDL2-devel \
  libusb1-devel

sudo swupd bundle-add c-basic dev-utils dfu-util dtc \
  os-core-dev python-basic python3-basic python3-tcl

Clear Linux 注重原生（native）运行的性能与安全，而非交叉编译。因此，它默认向所有用户的环境导出一组编译器和链接器标志。这些标志会使 Zephyr 的 CMake 构建产生警告或失败。要清除其中的 C/C++ 标志并修复构建，请以 root 身份运行以下命令，随后注销并重新登录：

echo 'unset CFLAGS CXXFLAGS' >> /etc/profile.d/unset_cflags.sh

注意：此命令会为系统上的所有用户取消这些 C/C++ 标志。各发行版的 bash 初始化文件会依次加载其他文件，顺序各异，较为复杂，也可能变化；Clear Linux 也不例外。如需更灵活的方案，可先查看 /usr/share/defaults/etc/profile 中的逻辑。

sudo pacman -S git cmake ninja gperf ccache dfu-util dtc wget \
    python-pip python-setuptools python-wheel tk xz file make which

CMake

需要较新版本的 CMake。使用 cmake --version 检查本机版本。若版本过旧，可通过以下几种方式获取较新版本：

  • 在 Ubuntu 上，可按说明添加 Kitware 的第三方 apt 仓库，再用 apt 获取较新版 CMake。

  • 从 CMake 项目网站下载安装打包好的 CMake。（此方式不会卸载旧版本。）

    cd ~
wget https://github.com/Kitware/CMake/releases/download/v3.21.1/cmake-3.21.1-Linux-x86_64.sh
chmod +x cmake-3.21.1-Linux-x86_64.sh
sudo ./cmake-3.21.1-Linux-x86_64.sh --skip-license --prefix=/usr/local
hash -r

    如果安装脚本将 CMake 放在 PATH 中的另一个位置，可能需要运行 hash -r。

  • 从 CMake 下载 页面下载并安装 CMake 项目提供的预编译程序。例如，将 3.21.1 版安装到 ~/bin/cmake：

    mkdir $HOME/bin/cmake && cd $HOME/bin/cmake
wget https://github.com/Kitware/CMake/releases/download/v3.21.1/cmake-3.21.1-Linux-x86_64.sh
yes | sh cmake-3.21.1-Linux-x86_64.sh | cat
echo "export PATH=$PWD/cmake-3.21.1-Linux-x86_64/bin:\$PATH" >> $HOME/.zephyrrc

  • 使用 pip3：

    pip3 install --user cmake

    此方式不会卸载旧版 CMake，而会把新版本安装到 ~/.local/bin。因此需要将 ~/.local/bin 加入 PATH。（详见Python 与 pip。）

  • 检查发行版的测试版（beta）或不稳定版软件仓库是否提供更新。

  • 在 Ubuntu 上也可以用 snap 获取可用的最新版本：

    sudo snap install cmake

更新后，用 cmake --version 确认系统找到了新安装的 CMake。也可考虑卸载包管理器提供的 CMake，以避免冲突。（用 whereis cmake 查找其他已安装版本。）

设备树编译器（Device Tree Compiler，DTC）

需要较新版本的 DTC。用 dtc --version 检查现有版本。如果版本过旧，可从源码构建较新版，也可安装 Zephyr SDK 并使用其中附带的版本。

Python

需要较新版本的 Python 3。用 python3 --version 检查现有版本。

如果版本过旧，需要安装较新版本的 Python 3。可从源码构建，或使用发行版软件仓库提供的回移植版本（如有）。建议将此 Python 隔离在虚拟环境中，避免干扰系统自带的 Python。

安装 Zephyr 软件开发工具包（SDK）

Zephyr 软件开发工具包（Software Development Kit，SDK）包含面向各个受支持架构的工具链（toolchain），还提供定制的 QEMU、OpenOCD 等主机工具。

强烈建议使用 Zephyr SDK。在某些条件下它甚至是必需的，例如在 QEMU 中对某些架构运行测试时。

要安装 SDK，请按照Zephyr SDK 安装指南中的 Linux 步骤操作。

在 Linux 上不使用 Zephyr SDK 构建

Zephyr SDK 为方便使用而提供：它包含所有 Zephyr 目标架构的工具链，构建应用或运行测试时无需额外标志。除了交叉编译器，还提供预编译的主机工具。不过，也可以按工具链一节所述改用其他工具链，不使用 SDK 的工具链构建。

如上所述，SDK 还包含预编译的主机工具。如果要同时使用这些主机工具和其他来源的工具链，必须将环境变量 ZEPHYR_SDK_INSTALL_DIR 设为 Zephyr SDK 的安装目录。如果构建时不使用这些主机工具，则必须取消设置环境变量 ZEPHYR_SDK_INSTALL_DIR。

可运行以下命令，确保该变量未设置：

unset ZEPHYR_SDK_INSTALL_DIR
