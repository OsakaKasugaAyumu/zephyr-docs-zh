基础知识

非官方简体中文译本 · 英文基线 4.5.99 · A08 · 全站目录（79 篇） · A 批目录 · 本页英文原文

本页介绍 west 的基本概念，并提供进一步阅读的参考资料。

west 的内置命令可以在同一工作区（workspace）目录下管理多个项目（projects）（Git 仓库）。

west 的工作方式如下：west init 创建west 工作区并克隆清单仓库（manifest repository）；west update 根据工作区中的清单，首次运行时克隆其中列出的项目（projects），以后运行时则更新它们。

工作区示例

如果已经按入门指南完成设置，本地的west 工作区应如下所示。本例中它包含名为 zephyrproject 的文件夹及其所有子目录：

zephyrproject/                 # west topdir
├── .west/                     # marks the location of the topdir
│   └── config                 # per-workspace local configuration file
│
│   # The manifest repository, never modified by west after creation:
├── zephyr/                    # .git/ repo
│   ├── west.yml               # manifest file
│   └── [... other files ...]
│
│   # Projects managed by west:
├── modules/
│   └── lib/
│       └── zcbor/             # .git/ project
├── tools/
│   └── net-tools/             # .git/ project
└── [ ... other projects ...]

工作区的基本概念

要理解这种结构，先了解以下基本概念。详见工作区（Workspaces）。

topdir

上图中的 zephyrproject 是工作区顶层目录（topdir）的名称。（zephyrproject 只是示例；也可以叫 z、my-zephyr-workspace 或其他名称。）

通常使用 west init 创建顶层目录及其中的一些文件和子目录。

.west 目录

顶层目录中包含 .west 目录。west 从当前工作目录开始向上查找 .west，将它的父目录作为顶层目录。如果未找到，则改从环境变量 ZEPHYR_BASE 指定的位置重新查找。

配置文件

文件 .west/config 是工作区的本地配置文件。

清单仓库（manifest repository）

每个 west 工作区恰好有一个清单仓库（manifest repository），即包含清单文件（manifest file）的 Git 仓库。本地配置文件中的 manifest.path 配置项 指定清单仓库的位置。

对于上游 Zephyr，zephyr 是清单仓库。不过，也可以配置 west 使用工作区内的任意 Git 仓库作为清单仓库，唯一要求是其中含有有效的清单文件。其他布局见支持的拓扑结构；清单文件格式详见west 清单（West Manifests）。

清单文件（manifest file）

清单文件采用 YAML 格式，用来定义项目（projects），即工作区内由 west 管理的其他 Git 仓库。其默认文件名为 west.yml；可通过本地配置项 manifest.file 更改。

通过 west update 命令，可以根据清单文件的内容更新工作区中的项目。

项目（projects）

项目是由 west 管理的 Git 仓库，在清单文件中定义，可以放在工作区内的任意位置。在上述示例中，zcbor 和 net-tools 都是项目。

默认情况下，Zephyr 的构建系统（build system）通过 west 获取工作区中所有项目的位置，以便将其中的代码作为模块（外部项目）使用。不过，模块与项目是两个不同的概念。

扩展命令

west 能识别的任何仓库（清单仓库或项目仓库）都可以定义扩展命令（extensions）。扩展命令是在该工作区内可额外使用的 west 命令。

zephyr 仓库通过这一机制提供 west build 等 Zephyr 专用命令。将它们做成扩展，使 west 的核心无需了解工作区使用的 Zephyr 版本等细节。

不受管理的文件

工作区还可以包含不由 west 管理的 Git 仓库以及其他文件和目录。除 .west、清单仓库和清单文件列出的项目外，west 基本上会忽略工作区中的其他内容。

west init 与 west update

与工作区有关的两个最重要的命令是 west init 和 west update。

west init 基础用法

此命令创建一个 west 工作区。

重要

运行 west init 后，west 不会替你改动清单仓库的内容。请用常规 Git 命令拉取新版本或进行其他操作。

通常只需运行一次，如下所示：

west init -m https://github.com/zephyrproject-rtos/zephyr --mr v2.5.0 zephyrproject

此命令将执行以下操作：

  1. 创建顶层目录 zephyrproject，并在其中创建 .west 和 .west/config

  2. 从 https://github.com/zephyrproject-rtos/zephyr 克隆清单仓库，放入 zephyrproject/zephyr

  3. 在本地 zephyr 仓库中检出 Git 标签 v2.5.0

  4. 在 .west/config 中将 manifest.path 设为 zephyr

  5. 将 manifest.file 设为 west.yml

至此，工作区基本就绪。只需再运行 west update，将其余项目克隆到工作区即可。

详见 west init。

west update 基础用法

此命令确保工作区内包含与清单文件所列项目相匹配的 Git 仓库。

重要

每当在清单仓库中检出不同版本，都应运行 west update，确保工作区中的项目仓库与新版清单的要求一致。

west update 命令通过以下步骤读取清单文件：

  1. 查找顶层目录。在前面的 west init 示例中，该目录是 zephyrproject。

  2. 加载顶层目录中的 .west/config，读取 manifest.path（如 zephyr）和 manifest.file（如 west.yml）配置项。

  3. 加载这些配置项指定的清单文件（如 zephyrproject/zephyr/west.yml）。

随后，它根据清单确定缺失项目应放在工作区的什么位置、从哪个 URL 克隆，以及本地应检出哪个 Git 版本。对于已存在的项目仓库，则就地获取并检出清单指定的相应版本。

详见 west update。
