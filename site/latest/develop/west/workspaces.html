工作区（Workspaces）

非官方简体中文译本 · 英文基线 4.5.99 · A09 · 全站目录（49 篇） · A 批目录 · 本页英文原文

本页进一步说明基础知识中介绍的west 工作区概念。

manifest-rev 分支

west 在每个项目中创建并管理一个名为 manifest-rev 的 Git 分支。它指向最近一次运行 west update 时清单为该项目指定的版本。其他工作区管理命令可将 manifest-rev 作为此次更新时上游版本的参照。manifest-rev 分支的用途之一，是让清单能用提交的 SHA 值指定项目版本。

尽管 manifest-rev 是普通的 Git 分支，west 会在下次更新时重新创建或重置它。因此，自行检出或修改此分支是危险的。例如，手动添加到这里的提交，可能在下次运行 west update 时丢失。请另建并检出一个不同名的本地分支，然后将它变基到新的 manifest-rev 上，或将 manifest-rev 合并进这个本地分支。

说明

west 不会在清单仓库中创建 manifest-rev 分支，因为它并不管理清单仓库的分支或版本。

refs/west/* Git 引用（refs）

在本地项目仓库中，所有以 refs/west/ 开头的 Git 引用（如 refs/west/foo）也由 west 保留使用。与 manifest-rev 不同，这些引用不是普通分支。这属于 west 的实现细节，不应依赖这些引用的存在或行为。

在 Git 仓库中开发

工作区中的 west“项目”都是普通 Git 仓库。默认情况下，west 只创建和更新 manifest-rev 分支以及 refs/west/ 下的引用。你自己创建的分支由你管理；只有明确使用 west update --rebase 时，west 才会对它们执行变基（rebase）。

因此，直接运行 west update 后会处于游离的 HEAD 状态：west 检出新的 manifest-rev，而你自己的分支仍停在原处。设计原因见west update 与游离 HEAD。

说明

Zephyr 模块（modules）和 west 项目不是同一概念，尽管 west 项目往往也是模块，详见模块与 west 项目的区别。以下 Git 工作流程适用于所有 west 项目，无论它们是否是 Zephyr 模块。

若已有本地更改，可采用以下工作流程：

  1. 在仓库中创建一个分支，照常向该分支提交：

    git -C <repository-path> switch --create <your-branch>

  2. 用 west update --rebase 更新工作区，再查看发生了哪些变化：

    west update --rebase
west compare

    当前分支仍保持检出状态，并会变基到新的 manifest-rev 上。只有在这种情况下，west 才会改动你自己的分支。若遇到冲突，命令会失败；照常使用 Git 解决即可。

  3. 如果不想让 west 对分支执行变基，直接运行 west update 会切离该分支（除非这样做会导致 Git 冲突）。第三种选择是 west update --keep-descendants，它不会失败。完整说明见 west update --help 中的 checked out branch behavior 选项组，以及 west update。

在游离的 HEAD 上提交

不要在 west update 留下的游离 HEAD 上提交：Git 会警告，这些提交无法从任何分支到达，以后可能被垃圾回收。请先为自己的工作创建分支；也可使用专门为“无分支”工作方式设计的其他 Git 客户端，例如 JJ。

私有仓库

west 可以从私有仓库获取代码，不需要任何 west 专用机制。

当项目的 manifest-rev 分支需要更新到新获取的提交时，west update 实际上会运行 git fetch YOUR_PROJECT_URL。能否成功获取，取决于你使用的环境。

可手动输入密码，也可使用Git 内置的凭据助手（credential helpers）之一。Git 自带凭据存储机制，因此不需要 west 为此另设功能。

以下各节说明如何在常见环境下运行 west update 而不必反复输入密码，以及如何排查问题。

通过 HTTPS 获取代码

在 Windows 上从 GitHub 获取代码时，按本页原文所述，较新版本 Git 的默认安装会在图形窗口中提示输入一次 GitHub 密码，并保存凭据供以后使用。因此首次完成后，再从 GitHub 获取代码通常就不需重复输入密码。

通常，可用 Git 的“store”凭据助手将凭据存储在磁盘上。详情见 git-credential-store 手册页。

若要对工作区中的所有仓库使用此助手，请运行：

west forall -c "git config credential.helper store"

若只对项目 foo 和 bar 使用此助手，请运行：

west forall -c "git config credential.helper store" foo bar

若要在本机默认使用此助手，请运行：

git config --global credential.helper store

在 GitHub 上，可以设置个人访问令牌（personal access token，PAT）来代替账号密码。（如果账号已启用双因素认证，这可能是必需的。即使未启用，也比以明文保存账号密码更可取。）

可按以下方式使用 Git 的凭据存储机制，以 GitHub 个人访问令牌（PAT）完成身份验证：

echo "https://x-access-token:$GH_TOKEN@github.com" >> ~/.git-credentials

如果不希望在文件系统中保存任何凭据，可以改用 git-credential-cache 将其临时保存在内存中。

若已配置好 SSH 获取方式，可使用 Git 的 URL 重写功能。以下命令让 Git 访问 GitHub 时用 SSH URL 代替 HTTPS URL：

git config --global url."git@github.com:".insteadOf "https://github.com/"

通过 SSH 获取代码

如果 SSH 密钥未设口令，通常可以直接获取代码。如果设置了口令，可使用 ssh-agent，避免每次手动输入。

GitHub 的配置及密钥创建步骤见使用 SSH 连接 GitHub。

项目的存放位置

项目可以放在工作区内的任何位置，但其路径不能“越出”工作区。

换言之，项目仓库不必位于清单仓库的子目录中，也不必是工作区顶层目录的直接子目录；但项目路径必须位于工作区内部。

可以手动将工作区内的项目仓库目录替换为指向本机其他位置的符号链接（symbolic link）；west 不会替你这样做。

支持的拓扑结构

以下是 west 支持的几种源码拓扑结构示例。

  • T1：星形拓扑，以 zephyr 为清单仓库

  • T2：星形拓扑，以 Zephyr 应用为清单仓库

  • T3：森林拓扑，使用独立的清单仓库

T1：星形拓扑，以 zephyr 为清单仓库

  • zephyr 仓库是中心仓库，在其 west.yml 中指定所需的模块（外部项目）。

  • 类比：使用 Git 子模块，zephyr 是父项目（super-project）。

这是默认布局。主线 Zephyr 的实例见工作区的基本概念。

T2：星形拓扑，以应用为清单仓库

  • 适合以单个应用为开发重点的团队。

  • 包含 Zephyr 应用的仓库作为中心仓库，在其 west.yml 中列出构建所需的其他项目，包括 zephyr 仓库和相关模块。

  • 类比：使用 Git 子模块，应用是父项目，zephyr 和其他项目是子模块。

采用此拓扑的工作区结构如下：

west-workspace/
│
├── application/         # .git/     │
│   ├── CMakeLists.txt               │
│   ├── prj.conf                     │  never modified by west
│   ├── src/                         │
│   │   └── main.c                   │
│   └── west.yml         # main manifest with optional import(s) and override(s)
│                                    │
├── modules/
│   └── lib/
│       └── zcbor/       # .git/ project from either the main manifest or some import.
│
└── zephyr/              # .git/ project
    └── west.yml         # This can be partially imported with lower precedence or ignored.
                         # Only the 'manifest-rev' version can be imported.

下面的 application/west.yml 示例使用 west 0.7 起提供的清单导入（manifest imports）功能，将 Zephyr v2.5.0 及其模块导入应用的清单文件：

# Example T2 west.yml, using manifest imports.
manifest:
  remotes:
    - name: zephyrproject-rtos
      url-base: https://github.com/zephyrproject-rtos
  projects:
    - name: zephyr
      remote: zephyrproject-rtos
      revision: v2.5.0
      import: true
  self:
    path: application

这样使用 import: 时，仍可有选择地“覆盖”个别 Zephyr 模块。示例见示例 1.3：基于 Zephyr 发行版的下游项目，使用模块派生仓库。

另一种等效方式是将 zephyr/west.yml 的内容复制到 application/west.yml，再为 zephyr 项目本身添加一条记录，如下所示：

# Equivalent to the above, but with manually maintained Zephyr modules.
manifest:
  remotes:
    - name: zephyrproject-rtos
      url-base: https://github.com/zephyrproject-rtos
  defaults:
    remote: zephyrproject-rtos
  projects:
    - name: zephyr
      revision: v2.5.0
      west-commands: scripts/west-commands.yml
    - name: net-tools
      revision: some-sha-goes-here
      path: tools/net-tools
    # ... other Zephyr modules go here ...
  self:
    path: application

（west-commands 用于构建、烧写与调试及其他 Zephyr 专用扩展命令（extensions）。使用 import 时，无需单独指定它。）

使用 import 的主要好处是无需单独追踪被导入项目的版本。上例使用 import 后，Zephyr 模块（module）的版本会由 zephyr/west.yml 的版本自动决定，而不必逐项复制并自行维护。

T3：森林拓扑

  • 适合维护多个独立应用，或维护没有“中心”仓库的下游发行版的团队。

  • 使用一个不包含 Zephyr 源码的专用清单仓库，在其中列出一组地位平等的项目。

  • 类比：使用 Google 的 repo 工具分发源码。

采用此拓扑的工作区结构如下：

west-workspace/
├── app1/               # .git/ project
│   ├── CMakeLists.txt
│   ├── prj.conf
│   └── src/
│       └── main.c
├── app2/               # .git/ project
│   ├── CMakeLists.txt
│   ├── prj.conf
│   └── src/
│       └── main.c
├── manifest-repo/      # .git/ never modified by west
│   └── west.yml        # main manifest with optional import(s) and override(s)
├── modules/
│   └── lib/
│       └── zcbor/      # .git/ project from either the main manifest or
│                       #       from some import
│
└── zephyr/             # .git/ project
    └── west.yml        # This can be partially imported with lower precedence or ignored.
                        # Only the 'manifest-rev' version can be imported.

下面的 T3 示例 manifest-repo/west.yml 使用 west 0.7 起提供的清单导入（manifest imports）功能，先导入 Zephyr v2.5.0 及其模块，再添加 app1 和 app2 两个项目：

manifest:
  remotes:
    - name: zephyrproject-rtos
      url-base: https://github.com/zephyrproject-rtos
    - name: your-git-server
      url-base: https://git.example.com/your-company
  defaults:
    remote: your-git-server
  projects:
    - name: zephyr
      remote: zephyrproject-rtos
      revision: v2.5.0
      import: true
    - name: app1
      revision: SOME_SHA_OR_BRANCH_OR_TAG
    - name: app2
      revision: ANOTHER_SHA_OR_BRANCH_OR_TAG
  self:
    path: manifest-repo

也可以像上文介绍 T2 拓扑时那样，“手动”复制 zephyr/west.yml；同样的注意事项也适用。

不支持的布局：将工作区顶层目录作为 Git 仓库

一些用户希望能把工作区的topdir本身作为 Git 仓库，如下例所示：

my-workspace/                  # workspace topdir
├── .git/                      # puts the entire workspace in a git repository
├── .west/                     # marks the location of the topdir
└── [ ... other projects ...]

这不是官方支持的拓扑。west 在设计上假定工作区顶层目录本身不是 Git 仓库。

某种类似布局也许能满足你当前的需求，但 west 后续版本的变化可能使它无法继续工作。
