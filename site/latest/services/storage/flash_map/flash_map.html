闪存分区映射（Flash map）

非官方简体中文译本 · J03 · 英文基线 4.5.99 · 全站目录（94 篇） · J 批目录 · 本页英文原文

<zephyr/storage/flash_map.h> API 通过 flash_area 结构体提供设备闪存分区的信息。

每个 flash_area 描述一个闪存分区。API 提供一份闪存分区映射（flash map），其中预定义的闪存区域都可通过全局唯一的数字 ID 访问。映射由 DTS 文件中与 “fixed-partitions” 或 “zephyr,mapped-partition” 兼容的条目生成。应用也可以在运行时创建自己的 flash_area 对象。

本文用“闪存区域”（flash area）指代由 “fixed-partitions” 或 “zephyr,mapped-partition” 描述的单个分区。

译校注 · J03-U01

分区容器和分区节点

在 fixed-partitions 布局中，容器下面的每个分区子节点才对应一个闪存区域；选择单个区域时用分区子节点的标签，不用容器的标签。另一种布局中，zephyr,mapped-partition 节点本身描述分区。

固定版本依据（2 处）

  • 该页 RST 修订 · zephyr,mapped-partition.yaml:1-12 · ecf93f117c30

flash_area 包含一个指向 device 的指针，可借助 闪存 API（flash API） 直接访问该区域所在的闪存设备。每个区域由三个量描述：所在设备、相对设备起始地址的偏移量，以及区域大小。flash_area_open() 还使用一个标识符在映射中查找相应区域。

flash_map.h 提供操作 flash_area 的函数，主要包括 flash_area_read() 和 flash_area_write()。它们封装了闪存 API，并额外检查偏移量和大小，确保操作不超出预定义区域。

<zephyr/storage/flash_map.h> 中大多数 API 函数都需要一个 flash_area 对象指针，以确定操作的区域。有两种获取方式：

  • 调用 flash_area_open() 获取指针；

  • 自行定义一个 flash_area 对象，提供有效的 device 对象指针，以及该区域在闪存设备内的偏移量和大小。

flash_area_open() 按数字标识符在映射中查找 flash_area 对象；如果找到，就返回指向该区域对象的指针。将 “fixed-partitions” 或 “zephyr,mapped-partition” 的 DTS 节点标签传给 PARTITION_ID()，即可获得区域 ID。下文说明这些标签如何由设备树定义。

译校注 · J03-U02

状态码和输出指针

调用 flash_area_open(id, &area) 时，函数返回的是状态码。返回 0 表示成功，区域指针经输出参数写入 area；返回错误时，不要把它当作已打开的区域使用。

固定版本依据（1 处）
  • 该页 RST 修订 · flash_map.h:114-127 · ecf93f117c30

与设备树（Devicetree）的关系

flash_map.h API 使用由 设备树 API 生成的数据，尤其是其中的固定与映射闪存分区。Zephyr 还约定了通过 MCUboot 引导程序（bootloader）进行设备固件升级（DFU）时使用的分区，并允许为文件系统（file systems）或其他非易失性存储（storage）定义分区。

以下设备树片段使用固定闪存分区，为 MCUboot 和数据存储划分空间。为便于阅读，示例省略了部分细节。【译校注】冻结英文示例的 compatible 写作 “zephyr.mapped-partition”（点），与本页正文的 “zephyr,mapped-partition”（逗号）不同。下方代码按原样保留，不要把这个拼写差异当作两种兼容字符串。

/ {
	soc {
		flashctrl: flash-controller@deadbeef {
			flash0: flash@0 {
				compatible = "soc-nv-flash";
				reg = <0x0 0x100000>;
				ranges = <0x0 0x0 0x100000>;

				partitions {
					ranges;
					#address-cells = <1>;
					#size-cells = <1>;

					boot_partition: partition@0 {
						compatible = "zephyr.mapped-partition";
						reg = <0x0 0x10000>;
						read-only;
					};

					storage_partition: partition@1e000 {
						compatible = "zephyr.mapped-partition";
						reg = <0x1e000 0x2000>;
					};

					slot0_partition: partition@20000 {
						compatible = "zephyr.mapped-partition";
						reg = <0x20000 0x60000>;
					};

					slot1_partition: partition@80000 {
						compatible = "zephyr.mapped-partition";
						reg = <0x80000 0x60000>;
					};

					scratch_partition: partition@e0000 {
						compatible = "zephyr.mapped-partition";
						reg = <0xe0000 0x20000>;
					};
				};
			};
		};
	};
};

分区偏移量以该分区所属闪存的起始地址为基准。

boot_partition、slot0_partition、slot1_partition 和 scratch_partition 都是为 MCUboot 定义的节点标签，但并非每种 MCUboot 配置都需要定义全部四个。详见MCUboot 文档（英文）。

storage_partition 节点供文件系统或其他非易失性存储 API 使用。

将 DTS 节点标签传给 PARTITION_ID() 即可取得闪存区域的数字 ID。例如，要取得 slot0_partition 的 ID，可调用 PARTITION_ID(slot0_partition)。

所有 PARTITION_* 宏都以 DTS 节点标签作为分区标识符。

译校注 · J03-U04

节点标签与节点标识符

宏的实参要看具体变体：PARTITION_ID(label) 接受分区的设备树节点标签，而 PARTITION_NODE_SIZE(node) 等接口接受节点标识符。不能只凭 PARTITION_ 前缀就把两者互换。

固定版本依据（2 处）
  • 该页 RST 修订 · flash_map.h:383-393 · ecf93f117c30
  • 该页 RST 修订 · flash_map.h:470-484 · ecf93f117c30

如果区域已在 DTS 文件中定义，查询其偏移量、大小或所在设备，并不需要先通过 flash_map_open() 取得 flash_area 对象指针。只要知道节点标签，就可以分别用 PARTITION_OFFSET() 查询偏移量、PARTITION_SIZE() 查询大小、PARTITION_DEVICE() 查询设备。例如，要查 storage_partition 的偏移量，只需使用 PARTITION_OFFSET(storage_partition)。【译校注】本句保留了英文原文的函数名；本页实际演示的打开函数是 flash_area_open()。

下面演示如何将 DTS 节点标签与 flash_area_open() 配合使用，取得 flash_area 对象指针：

const struct flash_area *my_area;
int err = flash_area_open(PARTITION_ID(slot0_partition), &my_area);

if (err != 0) {
     handle_the_error(err);
} else {
     flash_area_read(my_area, ...);
}
