配置持久化子系统（Settings）

非官方简体中文译本 · J06 · 英文基线 4.5.99 · 全站目录（94 篇） · J 批目录 · 本页英文原文

配置子系统（Settings）让各模块可以按设备保存配置和运行状态，在重启后仍然可用。它通过统一的 API 提供 FCB、NVS、ZMS 和文件系统等存储实现。应用开发者可以选择合适的介质，也可以在需求改变时更换介质。多个 Zephyr 组件都使用该子系统，用户应用也可以与它们同时使用。

配置项以键值对（key-value pair）的形式存储，键名用字符串表示。按照惯例，键名可按软件包和子树分层。例如，键 id/serial 表示软件包 id 的配置项 serial。

子系统提供辅助函数，可在配置值与字符串表示之间进行转换。

配置子系统的用法见 Settings API 示例：加载与保存配置（Settings API） 示例。

说明

自 Zephyr 4.1 起，不使用文件系统时，推荐的存储后端是 NVS 和 ZMS。

处理程序（Handlers）

每棵子树的配置处理程序实现一组回调函数。动态处理程序通过 settings_register() 注册；静态处理程序通过 SETTINGS_STATIC_HANDLER_DEFINE() 定义。

h_get

通过运行时后端调用 settings_runtime_get() 按名查询配置值时，会调用此函数。

h_set

通过 settings_load() 从持久化存储加载配置值，或通过运行时后端调用 settings_runtime_set() 设置配置值时，会调用此函数。

h_commit

在这次完整加载流程中，加载结束后调用 h_commit。若多项配置互相依赖，可以等相关值就绪后再统一应用。

h_export

需要写出全部当前配置时调用此函数。例如，settings_save() 尝试保存配置，或需要把配置交给用户实现的后端时。

处理程序还可以设置提交优先级 cprio，以确定各个 h_commit 回调的调用次序。例如，若某个子系统需要先初始化一项服务，其他 h_commit 回调才能使用它，就可以让该子系统先提交。

默认情况下，配置处理程序的 h_commit 回调使用 cprio = 0。如需指定其他优先级，动态处理程序使用 settings_register_with_cprio()，静态处理程序使用 SETTINGS_STATIC_HANDLER_DEFINE_WITH_CPRIO()。cprio 为整数，数值越小，优先级越高。

存储后端（Backends）

存储后端负责在存储介质与配置处理程序之间加载和保存数据，并为此实现一组回调。可读后端用 settings_src_register() 注册为数据源，可写后端用 settings_dst_register() 注册为写入目的地；同一后端也可兼任两者。当前实现支持多个读取源，但只允许一个写入目的地。

csi_load

使用 settings_load() 从持久化存储加载配置值时调用。

csi_load_one

使用 settings_load_one() 从持久化存储只加载一个配置项时调用。

csi_get_val_len

使用 settings_get_val_len() 查询持久化存储中某个值的长度时调用。

csi_save

使用 settings_save_one() 将单个配置项保存到持久化存储时调用。

csi_save_start

使用 settings_save() 或 settings_save_subtree() 开始保存所选范围内的全部当前配置时调用。

csi_save_end

使用 settings_save() 或 settings_save_subtree() 保存完所选范围内的全部当前配置后调用。

译校注 · J06-U02

后端可以不实现这两个专用回调

对单键读取和值长查询，后端若实现 csi_load_one 或 csi_get_val_len，就使用相应的专用回调；未实现时，所核版本可以通过 csi_load 和筛选回调完成操作。

Zephyr 提供的存储后端

Zephyr 提供以下存储后端：

  • 闪存环形缓冲区（FCB，CONFIG_SETTINGS_FCB）。

  • 文件系统中的文件（CONFIG_SETTINGS_FILE）。

  • 非易失性存储（NVS，CONFIG_SETTINGS_NVS）。

  • Zephyr 存储系统（ZMS，CONFIG_SETTINGS_ZMS）。

可以为配置声明多个读取源。调用 settings_load() 时，子系统会从所有已声明的源恢复配置。

写入配置只能有一个目的地。调用 settings_save() 或 settings_save_one() 时，数据都写入该处。

用 settings_fcb_src() 注册 FCB 读取源，用 settings_fcb_dst() 注册写入目的地。由于 settings_fcb_src() 还负责初始化 FCB 区域，它必须在 settings_fcb_dst() 之前调用。文件后端用 settings_file_src() 注册读取源，用 settings_file_dst() 注册写入目的地。

NVS 后端用 settings_nvs_src() 注册读取源，用 settings_nvs_dst() 注册写入目的地。

Zephyr 存储系统（ZMS）用 settings_zms_src() 注册读取源，用 settings_zms_dst() 注册写入目的地。

ZMS 后端在将配置写入持久化存储之前，会先对键名求哈希（hash）。如果保存的不同键很多，可能有多个键得到相同的哈希值，即发生碰撞；发生碰撞的可能性与所选哈希函数有关。

ZMS 后端最多能处理 2n 次碰撞，其中 n 由 CONFIG_SETTINGS_ZMS_MAX_COLLISIONS_BITS 指定。

译校注 · J06-U03

槽位数包含首个键

n 位能为同一哈希编码 2ⁿ 个槽位，首个键也占一个。例如 n = 2 时共 4 个槽位，首键之外最多还能容纳 3 个同哈希的不同键，而不是再容纳 4 个。

存储位置（Storage Location）

FCB、非易失性存储（NVS）和 ZMS 后端默认查找标签为 “storage” 的固定分区。要选择其他分区，可在设备树的 chosen 节点中设置 zephyr,settings-partition 属性。

译校注 · J06-U04

默认查找的是节点标签

FCB、NVS 和 ZMS 后端的默认选择引用设备树节点标签 storage_partition；仅给某个节点写上 label = "storage" 并不会使它被选中。要指定其他分区，可使用 chosen 的 zephyr,settings-partition。

文件后端保存配置所用的文件路径由 CONFIG_SETTINGS_FILE_PATH 选项指定。

从持久化存储加载数据

调用 settings_load() 时，子系统通过 h_set 回调把配置从存储介质加载到易失性内存。加载全部数据后，子系统调用 h_commit，通知应用配置已成功取回。

译校注 · J06-U05

提交回调不是逐键成功回执

在所核加载路径中，子系统遍历各读取源后进入提交，并不以每个 csi_load 的返回值作为进入条件。h_commit 可用来应用已经加载的配置，但被调用本身不能证明每个必需键都已成功读取。

固定版本依据（1 处）

如果只需要一项配置，可调用 settings_load_one() 将其读入调用者提供的缓冲区。

若只想知道某个配置项的值有多长，可调用 settings_get_val_len()。例如，动态分配缓冲区的应用可以先查出所需大小，再调用 settings_load_one() 读取数据。

FCB 和文件后端可能保留同一配置项的历史记录，新值追加在旧值之后。自 Zephyr 2.1 起，后端必须滤除旧记录，只把最新记录交给回调。

向持久化存储写入数据

settings_save_one() 通过存储后端将单项配置写入介质。调用 settings_save() 时，h_export 的实现可以在一次导出中通过 settings_save_one() 写出多个配置项。只有需要随 settings_save() 一起保存的键，才必须由 h_export 导出。

对于 FCB 和文件后端，只有写入请求的值与该键当前的值不同时，后端才追加记录，因此应用无需自行检查值是否有变化。同一个键在介质上可能有多条赋值记录，只有最后一条是当前值。

垃圾回收（garbage collection）

FCB 空间已满或文件占用过多空间时，后端会移除过时的键值对记录，以及不再需要的键删除记录。

安全域中的配置

当前不支持让同一个 Settings 实例同时充当安全域与非安全域的配置存储。建议安全域使用独立的 Settings 实例；如果确有需要，可按具体场景通过专用接口向非安全域提供数据。

示例：保存设备配置

本例中的配置处理程序只实现 h_set 和 h_export。从存储恢复值或首次设置值时，子系统调用 h_set；写回时则由 h_export 借助 storage_func() 将值写入存储。也可以实现其他导出方式，例如将配置输出到 shell 控制台。

#define DEFAULT_FOO_VAL_VALUE 1

static int8 foo_val = DEFAULT_FOO_VAL_VALUE;

static int foo_settings_set(const char *name, size_t len,
                            settings_read_cb read_cb, void *cb_arg)
{
    const char *next;
    int rc;

    if (settings_name_steq(name, "bar", &next) && !next) {
        if (len != sizeof(foo_val)) {
            return -EINVAL;
        }

        rc = read_cb(cb_arg, &foo_val, sizeof(foo_val));
        if (rc >= 0) {
            /* key-value pair was properly read.
             * rc contains value length.
             */
            return 0;
        }
        /* read-out error */
        return rc;
    }

    return -ENOENT;
}

static int foo_settings_export(int (*storage_func)(const char *name,
                                                   const void *value,
                                                   size_t val_len))
{
    return storage_func("foo/bar", &foo_val, sizeof(foo_val));
}

struct settings_handler my_conf = {
    .name = "foo",
    .h_set = foo_settings_set,
    .h_export = foo_settings_export
};

译校注 · J06-U06

复制示例前核对类型名

示例原样写作 int8。若目标项目没有定义这个类型别名，应核对头文件并使用目标支持的标准定宽类型 int8_t（<stdint.h>）。

译校注 · J06-U07

检查实际读回的字节数

本页两个单字节恢复示例都检查了声明长度，但 read_cb 的返回值才是实际读数。正值表示读回的字节数，0 可表示该键值对已删除；要确认读回一个字节，应检查返回值为 1，而不只是 rc >= 0。

示例：持久化运行状态

本例演示如何持久化运行状态。处理程序只定义 h_set，用于从持久化存储恢复值。

本例中，main 函数递增 foo_val，随后保存最新值。系统重启后，应用在初始化时调用 settings_load()，这样 foo_val 就能从重启前的值继续计数。

#include <zephyr/kernel.h>
#include <zephyr/sys/reboot.h>
#include <zephyr/settings/settings.h>
#include <zephyr/sys/printk.h>
#include <inttypes.h>

#define DEFAULT_FOO_VAL_VALUE 0

static uint8_t foo_val = DEFAULT_FOO_VAL_VALUE;

static int foo_settings_set(const char *name, size_t len,
                            settings_read_cb read_cb, void *cb_arg)
{
    const char *next;
    int rc;

    if (settings_name_steq(name, "bar", &next) && !next) {
        if (len != sizeof(foo_val)) {
            return -EINVAL;
        }

        rc = read_cb(cb_arg, &foo_val, sizeof(foo_val));
        if (rc >= 0) {
            return 0;
        }

        return rc;
    }


    return -ENOENT;
}

struct settings_handler my_conf = {
    .name = "foo",
    .h_set = foo_settings_set
};

int main(void)
{
    settings_subsys_init();
    settings_register(&my_conf);
    settings_load();

    foo_val++;
    settings_save_one("foo/bar", &foo_val, sizeof(foo_val));

    printk("foo: %d\n", foo_val);

    k_msleep(1000);
    sys_reboot(SYS_REBOOT_COLD);
}

译校注 · J06-U08

计数回绕与持久化的前提

foo_val 是 uint8_t，值为 255 时再加一会回到 0。示例没有检查加载和保存的返回值；只有保存及随后恢复都成功，重启后才能从保存的值继续计数。

示例：实现自定义后端

本例演示如何注册一个简单的自定义后端处理程序（CONFIG_SETTINGS_CUSTOM）。

static int settings_custom_load(struct settings_store *cs,
                                const struct settings_load_arg *arg)
{
    //...
}

static int settings_custom_save(struct settings_store *cs, const char *name,
                                const char *value, size_t val_len)
{
    //...
}

/* custom backend interface */
static struct settings_store_itf settings_custom_itf = {
    .csi_load = settings_custom_load,
    .csi_save = settings_custom_save,
};

/* custom backend node */
static struct settings_store settings_custom_store = {
    .cs_itf = &settings_custom_itf
};

int settings_backend_init(void)
{
    /* register custom backend */
    settings_dst_register(&settings_custom_store);
    settings_src_register(&settings_custom_store);
    return 0;
}
