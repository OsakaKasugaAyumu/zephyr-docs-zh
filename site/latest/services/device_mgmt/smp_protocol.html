简单管理协议规范（SMP Protocol Specification）

非官方简体中文译本 · K03 · 英文基线 4.5.99 · K 批目录 · 本页英文原文

本文描述简单管理协议（Simple Management Protocol，SMP）。MCUmgr 用它向设备发送请求并接收设备的响应。

SMP 是应用层协议。本文不涉及底层传输层。

说明

此处的 SMP 是 MCUmgr 的简单管理协议，与蓝牙的安全管理器协议（Security Manager Protocol，同样缩写为 SMP）无关。MCUmgr 的 SMP 可以通过蓝牙传输。

帧：消息的封装（Frame）

每帧由帧头和数据组成。如果底层传输支持分片，帧头中的Data Length字段可用于重组。多字节字段采用大端字节序（即网络字节序），帧格式如下：

说明

原始规范要求 SMP 应能接收小端和大端两种帧；实际上，MCUmgr 库的实现固定按大端字节序解释网络侧数据。

数据是可选的；Data Length为零时，帧中不含数据。数据编码取决于目标管理组及命令 ID。

各字段及其含义如下：

字段

说明

Res

保留字段，当前未使用，必须始终设为 0。

Ver（版本）

表示使用的协议版本。设为 0b01 表示使用新版 SMP，其错误码更详细，并在映射中返回；否则保持 0b00，以使用旧版 SMP。0b10 和 0b11 留作将来使用，不应使用。

OP

mcumgr_op_t，用于区分向设备写入信息还是从设备读取信息，以及数据包是发给 SMP 服务端的请求还是服务端给出的响应。

Flags

预留作标志位。目前尚未定义任何标志，此字段应设为 0。

Data Length

Data字段的长度。

Group ID

mcumgr_group_t，详见管理组标识符。

Sequence Num

帧序列号，每发一个请求帧就加一。响应的序列号应与对应请求的序列号相同。

Command ID

Group内的命令。

Data

数据载荷的大小由Data Length指定。载荷是可选的：Data Length可为零，表示帧头之后没有数据。

说明

Data的内容取决于 OP、Group ID 和 Command ID 的值。

除用户组（编号 64 及以上）外，上述各组的载荷一律使用 CBOR 编码。编号 64 及以上的组可自行定义数据通信格式。

最小响应

无论发出什么命令，只要请求的另一端有 SMP 客户端，就应给出响应，内容依次为帧头和一个 CBOR 映射。只有没有 SMP 服务或设备不响应时，才允许没有响应。

译校注

K03-U01 · 谁应对请求作出响应

这次交互由客户端发出请求，由服务端处理并返回响应。原句把处理请求的对端称为“客户端”，与同页对操作码的说明不一致。

固定版本依据（2 处）

  • smp.c · L478–495 · a2fcb6cf3e39

译校注

K03-U02 · 先确定管理组，再解释载荷

标准管理组的响应按 CBOR 映射解释；若用户自定义管理组采用了自己的载荷格式，就要按该组的约定解码，不能无条件按 CBOR 映射解析。

  • smp.c · L313–326 · a2fcb6cf3e39

最小响应的 SMP 数据

最小响应如下：

{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}

{
    (str)"rc"       : (int)
}

其中：

“err” -> “group”

组专属错误码所属的 mcumgr_group_t 管理组。仅在使用 SMP 版本 2 且返回错误时出现。

“err” -> “rc”

组专属错误码的索引。在 SMP 版本 2 中，仅当该值非零（表示错误）时出现。

“rc”

mcumgr_err_t，仅在值非零（表示错误）时出现；适用于 SMP 版本 1，或 SMP 版本 2 中 SMP 自身的错误。

原文称，命令成功时会返回空映射。仅在出错时才返回 rc 或 err；因此，只返回空映射或响应中没有这两个字段时，可将请求视为成功。对于 SMP 版本 2，与协议本身有关、而非特定管理组的错误仍以 rc 错误返回，客户端必须能处理这两种错误。

译校注

K03-M01 · 成功响应不一定是空映射

这里描述的是没有结果字段的最小成功响应，不能把“映射为空”当成成功的必备条件。例如，回显命令成功时会在映射中返回 r 字段。
