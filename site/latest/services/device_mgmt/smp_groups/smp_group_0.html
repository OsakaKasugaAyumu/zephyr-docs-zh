K05-U01 · prio 不一定按无符号数编码

示意中的 uint 不是唯一编码。启用 CONFIG_MCUMGR_GRP_OS_TASKSTAT_SIGNED_PRIORITY 时，处理器按有符号数编码优先级；只接受无符号数的客户端会漏掉负优先级。

译校注

K05-M01 · runtime 不能直接按系统节拍换算

原文写作“ticks”。在所核实现中，启用线程运行统计时，runtime 取自 execution_cycles；其他配置下可能填零，也可能省略。不能直接用系统节拍频率把这个字段换算成秒。

固定版本依据（1 处）
  • os_mgmt.c · L268–287 · a5c6d164bf88

译校注

K05-U02 · tid 不是持久的线程标识

这里的 tid 来自本次线程遍历从零开始的序号，不是线程指针。两次请求得到相同的 tid，不足以认定记录属于同一个线程。

固定版本依据（2 处）
  • os_mgmt.c · L329–344 · a5c6d164bf88
  • os_mgmt.c · L350–358 · a5c6d164bf88

译校注

K05-U03 · cswcnt 为零不等于没有上下文切换

在所核实现中，cswcnt、last_checkin 和 next_checkin 依配置省略或填零。不能把 cswcnt 的零值当作已测得的上下文切换次数。

说明

日期与时间命令

此命令可读取表示设备当前日期与时间的字符串，也可设置新的时间。读与写均使用以下格式：

“yyyy-MM-dd’T’HH:mm:ss.SSSSSSZZZZZ”

译校注

K05-U05 · 读取格式与写入解析分开看

所核实现读出的日期时间精确到秒；启用毫秒选项才追加三位小数，输出不附时区。客户端不应因设备未返回六位小数或时区就拒收。写入由另一段代码解析，也不能反推所有带后缀的输入必定失败。

系统复位

此命令使系统复位。设备应先返回响应再复位，以便 SMP 客户端得知命令已被接受。默认在所有条件下都接受此命令。但如果启用 CONFIG_MCUMGR_GRP_OS_RESET_HOOK 且应用注册了回调，收到命令时就会调用此回调。回调既可在模块重启前执行必要的清理，也可直接拒绝复位并返回错误。详见MCUmgr 回调。

译校注

K05-U07 · force 的类型和作用

启用所核复位钩子时，force 按 CBOR 布尔值解码，默认 false。整数 1 与布尔值 true 不是同一类型；即使发送 true，也不保证应用钩子会接受复位请求。

操作系统／应用信息

用于查询当前运行的镜像，功能类似 Linux 的 uname 命令。可返回内核名称、内核版本、构建日期和时间、处理器类型以及应用自定义的信息。用 CONFIG_MCUMGR_GRP_OS_INFO 启用此功能。

其中：

“format”

指定响应的输出格式。字段按自身索引升序追加，而不是按命令收到的字符顺序排列。格式说明符：
* s 内核名称
* n 节点名称
* r 内核发行版本
* v 内核版本信息
* b 构建日期与时间（需要 CONFIG_MCUMGR_GRP_OS_INFO_BUILD_DATE_TIME）
* m 机器
* p 处理器
* i 硬件平台
* o 操作系统
* a 全部字段（上述所有选项的简写）
如未提供此选项，默认采用 s，即内核名称。

表示参数查询的字符串。查询的具体形式不受限制，由引导程序后端解释。若未提供查询，响应将返回标识引导程序的字符串。

引导程序信息响应

引导程序信息响应的帧头：

OP

Group ID

Command ID

1

0

8

请求未提供“query”时，响应的 CBOR 数据如下：

{
    (str)"bootloader"      : (str)
}

其中：

“bootloader”

表示引导程序名称的字符串。

提供“query”时：

{
    (str,opt)<response>   : ()
    ...
}

其中：

<response>

对“query”的答复。此字段可选；查询没有答案时可省略，预期返回 SMP 版本 2 错误码 OS_MGMT_ERR_QUERY_YIELDS_NO_ANSWER。响应可含多个参数，也可以是一个映射，取决于引导程序后端和查询内容。

…

参数的特征信息。

参数还可能附带特有的补充信息，以关键字及其值表示。

出错时，CBOR 数据采用以下格式：

{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}

{
    (str)"rc"       : (int)
}

其中：

“err” -> “group”

组专属错误码所属的 mcumgr_group_t 管理组。仅在使用 SMP 版本 2 且返回错误时出现。

“err” -> “rc”

组专属错误码的索引。在 SMP 版本 2 中，仅当该值非零（表示错误）时出现。

“rc”

mcumgr_err_t，仅在值非零（表示错误）时出现；适用于 SMP 版本 1，或 SMP 版本 2 中 SMP 自身的错误。

引导程序信息：MCUboot

如果应用的引导程序是 MCUboot，空请求将得到以下响应：

{
    (str)"bootloader"      : (str)"MCUboot"
}

MCUboot 目前支持查询工作模式：

{
    (str)"query"           : (str)"mode"
}

对“mode”查询的响应为：

{
    (str)"mode"                     : (int)
    (str,opt)"no-downgrade"         : (bool)
}

其中“mode”取以下值之一：

-1

未知的 MCUboot 模式。

0

MCUboot 处于单应用模式。

1

MCUboot 使用暂存分区（scratch partition）交换镜像。

2

MCUboot 处于覆盖模式（仅升级）。

3

MCUboot 在不使用暂存分区的情况下交换镜像。

4

MCUboot 处于不支持回退的直接就地执行（DirectXIP）模式。

5

MCUboot 处于支持回退的直接就地执行（DirectXIP）模式。

6

MCUboot 处于 RAM 加载模式。

no-downgrade 是一个标志，为真时一定会发送，表示 MCUboot 启用了防降级。若上传镜像的版本低于当前运行的应用，MCUboot 不会用它更新应用。

在此配置下，MCUmgr 可能拒绝版本较低的镜像。
