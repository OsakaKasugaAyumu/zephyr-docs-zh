Zephyr 中的“槽位”和“镜像”

“槽位”（slot）与“镜像”（image）的术语来自 MCUboot。这里一个镜像对应两个槽位：主槽位（primary）和次槽位（secondary）。在这里描述的布局中，应用按设计从主槽位运行，升级镜像按设计上传至次槽位；启动时由 MCUboot 负责交换两个槽位。也就是说，每对槽位用于一个可升级的应用。Zephyr 的设备树命名容易混淆：专供一个应用的 fixed-partitions 或 zephyr,mapped-partition 分区，节点标签分别为“slot0_partition”和“slot1_partition”，名称却分别是“image-0”和“image-1”。

目前 Zephyr 最多支持两个镜像，此时映射关系如下：

镜像

槽位标签

槽位名称

1

“slot0_partition” “slot1_partition”

“image-0” “image-1”

2

“slot2_partition” “slot3_partition”

“image-2” “image-3”

K06-U01 · 镜像数量不是协议编号

表中列举的是两对槽位，不是通用上限。所核 CONFIG_MCUMGR_GRP_IMG_UPDATABLE_IMAGE_NUMBER 范围为 1–3，实际数量还须与引导程序及分区匹配。状态响应中的 image 从 0 编号，不要将表中“第 1、2 个镜像”直接编码成 1、2。

OP

说明

在下面的响应定义中，“image”标为可选（opt）。若目标应用仅支持一个镜像，响应可不含此字段；若支持多个应用镜像，此字段必填，以标识列出的是哪个镜像的信息。

响应仅含有效镜像的信息；无法识别为有效的镜像会被跳过。

成功响应的 CBOR 数据：

{
    (str)"images" : [
        {
            (str,opt)"image"        : (uint)
            (str)"slot"             : (uint)
            (str)"version"          : (str)
            (str,opt*)"hash"        : (byte str)
            (str,opt)"bootable"     : (bool)
            (str,opt)"pending"      : (bool)
            (str,opt)"confirmed"    : (bool)
            (str,opt)"active"       : (bool)
            (str,opt)"permanent"    : (bool)
        }
        ...
    ]
    (str,opt)"splitStatus" : (int)
}

出错时，CBOR 数据采用以下格式：

{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}

{
    (str)"rc"       : (int)
    (str,opt)"rsn"  : (str)
}

其中：

“image”

有条件可选的镜像编号：运行中的应用只支持一个镜像时，可省略。

“slot”

“image”内的槽位编号。每个镜像有两个槽位：主槽位（运行中的槽位）为 0，次槽位（用于双区 DFU）为 1。

“version”

镜像版本字符串，由 imgtool 设置。

“hash”

镜像头和镜像体的 SHA256 哈希，不等同于整个文件的 SHA256。这是 MCUboot 的 TLV 区中用于签名验证的数据哈希。仅在使用 MCUboot 串口恢复功能且只有一对镜像槽位时，此字段才可选；此配置下可以禁用 Kconfig 选项 CONFIG_BOOT_SERIAL_IMG_GRP_HASH 来移除对哈希的支持。运行于应用中的 MCUmgr 必须支持发送哈希。

说明

参见下方 MCUboot 镜像格式文档中的 IMAGE_TLV_SHA256。

“bootable”

若已设置镜像的可引导标志，则为 true；为 false 时可不出现。

“pending”

若已将镜像标记为下次交换的目标，则为 true；为 false 时可不出现。

“confirmed”

若镜像已确认，则为 true；为 false 时可不出现。

“active”

若该镜像就是当前活动的应用，则为 true；为 false 时可不出现。

“permanent”

若镜像在下次启动后应留在主槽位，则为 true；为 false 时可不出现。

“splitStatus”

表示拆分镜像的加载程序是否与应用部分兼容；Zephyr 不使用此字段。

“err” -> “group”

组专属错误码所属的 mcumgr_group_t 管理组。仅在使用 SMP 版本 2 且返回错误时出现。

“err” -> “rc”

组专属错误码的索引。在 SMP 版本 2 中，仅当该值非零（表示错误）时出现。

“rc”

mcumgr_err_t，仅在值非零（表示错误）时出现；适用于 SMP 版本 1，或 SMP 版本 2 中 SMP 自身的错误。

“rsn”

可选字符串，用于补充说明错误原因；当 rc 为 MGMT_ERR_EUNKNOWN 时尤为有用。

译校注

K06-U02 · 状态 hash 与上传 sha 覆盖范围不同

在所核 MCUboot 哈希路径中，镜像头、镜像体以及存在时的受保护 TLV 区都参与计算。状态字段 hash 对应镜像 TLV 中的摘要；上传字段 sha 针对整个待传文件，两者不能互换。

K06-U05 · 试启动与回退发生在不同的复位上

在支持测试和回退的交换模式中，标记测试后的第一次复位尝试启动新镜像。若试启动成功但未确认，后续复位才会回退；若已确认，就不会仅因这次测试而回退。这个顺序不适用于所有升级模式。

设置镜像状态的响应

响应格式与获取镜像状态的响应相同。

上传镜像

镜像上传命令用于更新应用镜像。

镜像上传请求

每个待上传的镜像块都要发送一个上传请求，直至整个镜像上传至设备。

镜像上传请求的帧头字段：

OP

Group ID

Command ID

2

1

1

请求的 CBOR 数据：

{
    (str,opt)"image"    : (uint)
    (str,opt)"len"      : (uint)
    (str)"off"          : (uint)
    (str,opt)"sha"      : (byte str)
    (str)"data"         : (byte str)
    (str,opt)"upgrade"  : (bool)
}

其中：

“image”

可选的镜像编号，可以完全不出现在请求中；省略时默认为 0。此字段只应在“off”为 0 时出现。

“len”

可选的镜像长度；当“off”为 0 时必须出现。

“off”

此请求携带的镜像块的偏移量。

“sha”

本次上传的 SHA256 哈希，用于标识上传会话（例如恢复中断的会话），并用于校验镜像。必须提供对整个待上传镜像计算的完整 SHA256；若无法取得哈希，则不要发送此字段，此时不能续传或校验镜像。此字段只应在“off”为 0 时出现。

“data”

要写入指定偏移位置的镜像数据。

“upgrade”

可选标志，表示只允许升级。若待上传软件的版本不高于设备已有版本，则拒绝上传。Zephyr 默认比较主版本号、次版本号和修订号（x.y.z）；设置 CONFIG_MCUMGR_GRP_IMG_VERSION_CMP_USE_BUILD_NUMBER 后还会比较构建号。此字段只应在“off”为 0 时出现。

说明

没有单列“data”中数据块大小的字段，因为“data”字段自身已经包含这一信息。

说明

服务端可能以“off”为 0 响应上传：例如另一传输通道开始了上传（甚至在 MCUmgr 之外开始），设备重启，或丢了一个包。遇到这种情况，客户端必须重发原首包中已发送的全部必填和可选字段，以便服务端重建上传状态；缺少这些原始字段就无法继续上传。

译校注

K06-U06 · 上传首块还须容纳固定镜像头

在所核应用端，off=0 时不仅必须提供 len，首块 data 的长度还须至少达到 sizeof(struct image_header)。即使字段齐全，首块太短也会被拒绝；并不要求整个受保护区都在首块内。

固定版本依据（1 处）
  • zephyr_img_mgmt.c · L691–705 · 1fc916a2b607

MCUmgr 库用“sha”标识进行中的更新会话，以便中断后恢复，也用于校验上传内容。如果请求的“off”为零，库会检查状态中保存的“sha”；若匹配，则向更新客户端返回应从何处继续的偏移量。若不能取得哈希（例如文件正以流式传输），就不得提供此字段；此时不能校验镜像，也不能恢复上传会话。

译校注

K06-U07 · off 是下一次续写位置

客户端应将响应的 off 直接用作下一次请求的偏移量。从 0 开始成功处理 16 字节后，最后一个字节下标为 15，返回的 off 却是 16；不要再加一。偏移不符时，设备也可返回它期望的位置。

可选字段，仅在启用 CONFIG_MCUMGR_GRP_IMG_DIRECT_UPLOAD 允许直接上传镜像时出现。它指定外部工具向此槽位上传镜像时应使用的镜像 ID。

“max_image_size”

可选字段，仅在启用 CONFIG_MCUMGR_GRP_IMG_TOO_LARGE_SYSBUILD 或 CONFIG_MCUMGR_GRP_IMG_TOO_LARGE_BOOTLOADER_INFO 时出现。它指定向该镜像编号上传的应用最大可有多大。

“err” -> “group”

组专属错误码所属的 mcumgr_group_t 管理组。仅在使用 SMP 版本 2 且返回错误时出现。

“err” -> “rc”

组专属错误码的索引。在 SMP 版本 2 中，仅当该值非零（表示错误）时出现。

“rc”

mcumgr_err_t，仅在值非零（表示错误）时出现；适用于 SMP 版本 1，或 SMP 版本 2 中 SMP 自身的错误。

译校注

K06-U10 · upload_image_id 不能单独用来判断模式

直接上传模式按物理槽索引加一报告 upload_image_id；关闭直接上传时，所核实现仍可为非活动槽返回按镜像编号计算的同名字段。应读取目标的槽位信息，不能仅凭字段是否存在推断模式。
