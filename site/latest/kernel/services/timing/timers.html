定时器（Timers）

非官方简体中文译本 · E05 · 英文基线 4.5.99 · 全站目录（94 篇） · E 批目录 · 本页英文原文

定时器（timer）是利用内核系统时钟测量时间流逝的内核对象。到达指定时限时，可执行应用定义的动作，也可只记录本次到期，等待应用读取状态。

基本概念

可以定义任意数量的定时器，只受可用 RAM 限制。每个定时器通过其内存地址引用。

定时器有以下关键属性：

  • 首次到期时长（duration）：从启动到首次到期的间隔，以 k_timeout_t 表示，可用不同时间单位初始化。

  • 周期（period）：首次到期后，相邻两次预定到期之间的间隔，也是非负的 k_timeout_t 值。K_NO_WAIT（零）或 K_FOREVER 表示只触发一次便停止。例如，首次时长 200 ms、周期 75 ms 时，先在 200 ms 后到期，再每隔 75 ms 到期一次。

  • 到期函数（expiry function）：定时器每次到期时，由系统时钟中断处理程序执行。不需要到期处理时可指定 NULL。

  • 停止函数（stop function）：运行中的定时器提前停止时，由使其停止的线程执行。不需要停止处理时可指定 NULL。

  • 状态计数（status）：记录自上次读取状态以来定时器到期了多少次。

定时器必须先初始化才能使用。初始化指定到期函数和停止函数，将状态计数清零，并使定时器进入停止态。

指定首次到期时长和周期即可启动定时器。状态计数清零，定时器进入运行态，开始向首次到期倒计时。

说明

首次时长是相对于启动时刻的最短延迟；周期是相对于上一次“预定到期时刻”的最短延迟。因此周期定时器相对于系统定时器不会漂移，但两次实际处理之间的间隔可能短于或长于指定周期。

若要保证从本次处理到下次到期之间至少间隔指定时长，应在到期函数（expiry function）内或本次到期后重新启动定时器。

延迟的波动来自中断处理延迟、之前的定时器处理程序执行时间等系统因素。

运行中的定时器到期时，状态计数加一；若有到期函数则执行，并解除等待该定时器的线程的阻塞。若周期为零则停止；否则，从本次预定到期时刻算出下一个周期到期点，按剩余时间重新开始倒计时。

可以在倒计时途中停止定时器。状态计数不变，定时器进入停止态；若有停止函数则执行，并解除等待线程的阻塞。允许停止未运行的定时器，但不会产生效果。

也可以在倒计时途中重启。状态计数清零，再按新指定的首次时长和周期重新倒计时；等待该定时器的线程继续等待。

随时可直接读取状态，得到自上次读取以来的到期次数；读取会将计数清零。也可读取距到期的剩余时间；返回零表示定时器已停止。

线程也可与定时器同步来间接读取状态。线程会阻塞到状态非零（已到期至少一次）或定时器停止。若调用时已经满足其中之一，则不必等待。同步操作返回状态并清零。

说明

每个定时器应只由一个使用者检查状态，因为直接或间接读取都会改变状态值。同一时刻也应只有一个线程与某个定时器同步。ISR 不得等待定时器同步，因为 ISR 不能阻塞。

定时器观察者

启用 CONFIG_TIMER_OBSERVER 后，代码可以注册定时器观察者（timer observers），接收系统内所有定时器的生命周期事件。观察者由一组可选回调组成，分别在初始化、启动、停止或到期时调用。这样跟踪、性能分析、电源管理等外部模块无需修改内核或各个定时器，就能响应其活动。

用 K_TIMER_OBSERVER_DEFINE 静态定义观察者，传入 on_init、on_start、on_stop、on_expiry 回调的指针。不需要的回调可传 NULL。到期回调在中断上下文执行，因此必须简短且不能阻塞。

实现

定义定时器

用 k_timer 类型的变量定义定时器，再调用 k_timer_init() 初始化。

下列代码定义并初始化一个定时器。

struct k_timer my_timer;
extern void my_expiry_function(struct k_timer *timer_id);

k_timer_init(&my_timer, my_expiry_function, NULL);

也可以用 K_TIMER_DEFINE 在编译时定义并初始化定时器。

以下代码与上面的代码片段效果相同。

K_TIMER_DEFINE(my_timer, my_expiry_function, NULL);

使用定时器到期函数

下例使用定时器周期性执行一项较复杂的操作。由于这项工作不适合中断上下文，到期函数将工作项提交到系统工作队列（system workqueue），由它的线程执行。

void my_work_handler(struct k_work *work)
{
    /* do the processing that needs to be done periodically */
    ...
}

K_WORK_DEFINE(my_work, my_work_handler);

void my_timer_handler(struct k_timer *dummy)
{
    k_work_submit(&my_work);
}

K_TIMER_DEFINE(my_timer, my_timer_handler, NULL);

...

/* start a periodic timer that expires once every second */
k_timer_start(&my_timer, K_SECONDS(1), K_SECONDS(1));

读取定时器状态

下例直接读取状态，判断定时器是否已经到期。

K_TIMER_DEFINE(my_status_timer, NULL, NULL);

...

/* start a one-shot timer that expires after 200 ms */
k_timer_start(&my_status_timer, K_MSEC(200), K_NO_WAIT);

/* do work */
...

/* check timer status */
if (k_timer_status_get(&my_status_timer) > 0) {
    /* timer has expired */
} else if (k_timer_remaining_get(&my_status_timer) == 0) {
    /* timer was stopped (by someone else) before expiring */
} else {
    /* timer is still running */
}

通过定时器状态同步

下例通过定时器状态同步，让线程在等待时做其他有用工作，同时保证两个协议操作至少间隔规定的时间。

K_TIMER_DEFINE(my_sync_timer, NULL, NULL);

...

/* do first protocol operation */
...

/* start a one-shot timer that expires after 500 ms */
k_timer_start(&my_sync_timer, K_MSEC(500), K_NO_WAIT);

/* do other work */
...

/* ensure timer has expired (waiting for expiry, if necessary) */
k_timer_status_sync(&my_sync_timer);

/* do second protocol operation */
...

说明

如果线程没有其他工作，直接在两个协议操作之间睡眠即可，不必使用定时器。

建议用法

用定时器在指定时间后启动异步操作。

用定时器判断指定时间是否已经过去。尤其是当 k_sleep() 和 k_usleep() 无法满足所需精度或时间单位要求时，应使用定时器。

带有时限的操作进行期间，可借助定时器让线程执行其他工作。

说明

若线程只需测量某操作耗时，可直接读取系统时钟或硬件时钟，无须使用定时器。
