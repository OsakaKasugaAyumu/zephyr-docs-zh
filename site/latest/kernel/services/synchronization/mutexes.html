互斥锁（Mutexes）

非官方简体中文译本 · E07 · 英文基线 4.5.99 · 全站目录（94 篇） · E 批目录 · 本页英文原文

互斥锁（mutex）是实现传统可重入互斥锁语义的内核对象。它保证同一时刻只有一个线程能访问相应资源，从而让多个线程安全地共享硬件或软件资源。

基本概念

可以定义任意数量的互斥锁，只受可用 RAM 限制。每个互斥锁通过其内存地址引用。

互斥锁有以下关键属性：

  • 加锁计数（lock count）表示持有线程已对该锁加锁多少次。计数为零表示锁已完全释放。

  • 持有线程（owning thread）标识当前持有这把锁的线程。

互斥锁须先初始化才能使用。初始化将加锁计数置零。

线程使用共享资源前，须先对相应的互斥锁加锁，取得独占访问权。如果其他线程已经持有这把锁，请求线程可选择等待解锁。

取得锁后，线程可以在所需时间内安全地使用资源；但应尽量缩短持锁时间，以免影响其他线程。不再需要资源时，线程必须解锁，让其他线程也能使用它。

锁仍被持有或有线程正在等待时，不得释放互斥锁所在的内存，也不得将内存挪作他用。若锁嵌在动态分配的对象中，释放对象之前须先解锁，否则持有线程仍会追踪一把位于已不属于它的内存中的锁。

任意数量的线程都可同时等待一把锁。解锁后，最高优先级的等待线程中，等待最久者取得该锁。

说明

互斥锁不适用于 ISR。

可重入加锁

同一线程可对已经持有的互斥锁再次加锁。因此在线程执行到某处需要访问资源时，不必事先区分自己是否已持有锁。

同一线程重复加锁多少次，就必须对应解锁多少次；在完全释放之前，其他线程不能取得该锁。

优先级继承

持锁线程可以获得优先级继承（priority inheritance）。当优先级更高的线程开始等待锁时，内核会暂时提高持有者的优先级，使它能以等待者的优先级更快地完成工作并释放锁。解开该锁后，线程恢复到取得它之前的优先级。

说明

CONFIG_PRIORITY_CEILING 限制内核因优先级继承而能提升到的最高优先级。默认值 -128 表示不限制；设为等于或低于空闲线程的优先级即可禁用。

第一次因互斥锁而提升优先级时，原优先级保存在持有线程自身。线程用专属链表跟踪持有的每一把锁。每次出现更高优先级等待者，内核都会调整持有者的优先级。持有者释放某把锁或高优先级等待者超时后，内核重新扫描剩余锁，以仍在等待其中任一把锁的最高优先级线程为依据重新计算；没有等待者则恢复原优先级。因此，无论多把锁以何种顺序释放，结果都正确。

如果持有者自己又阻塞在另一把互斥锁上，优先级提升会沿持有关系链逐级传播，让阻碍等待线程前进的每个持有者依次获益。每次加锁最多追溯多少级由实现决定；超出上限的持有者暂时保留提升前的优先级，直到后续加锁操作再次遍历该链。

实现

定义互斥锁

用 k_mutex 类型的变量定义互斥锁，再调用 k_mutex_init() 初始化。

下例定义并初始化一把互斥锁。

struct k_mutex my_mutex;

k_mutex_init(&my_mutex);

也可用 K_MUTEX_DEFINE 在编译时定义并初始化互斥锁。

以下代码与上面的代码片段效果相同。

K_MUTEX_DEFINE(my_mutex);

获取互斥锁

调用 k_mutex_lock() 获取互斥锁。

延续上例，如果其他线程已经持锁，就一直等待，直到该锁可用。

k_mutex_lock(&my_mutex, K_FOREVER);

下例最多等待 100 毫秒；若互斥锁仍不可用，则发出警告。

if (k_mutex_lock(&my_mutex, K_MSEC(100)) == 0) {
    /* mutex successfully locked */
} else {
    printf("Cannot lock XYZ display\n");
}

释放互斥锁

调用 k_mutex_unlock() 释放互斥锁。

延续上例，线程释放先前由自己取得的锁。

k_mutex_unlock(&my_mutex);

建议用法

用互斥锁为物理设备等资源提供独占访问。

Futex API 参考

k_futex 是一种轻量互斥原语，旨在尽量减少内核介入。无竞争时只需对共享内存执行原子访问。k_futex 不是内核对象，不使用内核对象权限管理；它们位于用户内存，任何有该内存读写权限的线程均可使用。
