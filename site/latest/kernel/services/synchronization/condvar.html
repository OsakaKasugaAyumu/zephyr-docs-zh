条件变量（Condition Variables）

非官方简体中文译本 · F03 · 英文基线 4.5.99 · 全站目录（94 篇） · F 批目录 · 本页英文原文

条件变量（condition variable）是一种同步原语，使线程能够等待某一特定条件成立。

基本概念

条件变量的数量仅受可用 RAM 限制，每个条件变量通过内存地址引用。

线程可以使用条件变量等待某个条件变为真。

条件变量本质上是一个等待线程队列。执行状态尚未满足条件时，线程可通过等待操作将自己加入队列。k_condvar_wait() 以原子方式执行以下步骤：

  1. 释放最近获取的互斥锁。

  2. 将当前线程加入条件变量的等待队列。

译校注 · F03-01

调用线程应持有传给 k_condvar_wait() 的那把 mutex。实际进入等待时释放、返回前重新获取的都是这个参数所指的锁，而不是内核自动寻找的“最近一把”。K_NO_WAIT 路径不释放该锁；超时限制的是条件等待，不含之后重新获取互斥锁所花的时间。

固定版本依据：Zephyr 1b1b2e0cdca4

condvar.c：105–135

其他线程改变上述状态后，可通过 k_condvar_signal() 或 k_condvar_broadcast() 通知一个或多个等待线程继续执行。被唤醒的线程随后：

  1. 重新获取此前释放的互斥锁。

  2. 从 k_condvar_wait() 返回。

无论等待因收到信号、超时还是请求不阻塞而结束，k_condvar_wait() 返回时，调用线程一定已重新持有相关互斥锁。

条件变量须先初始化再使用。

实现

定义条件变量

用 k_condvar 类型定义条件变量，再调用 k_condvar_init() 初始化。

下面定义了一个条件变量：

struct k_condvar my_condvar;

k_condvar_init(&my_condvar);

也可调用 K_CONDVAR_DEFINE 在编译期定义并初始化条件变量。

以下代码与上面的代码片段效果相同。

K_CONDVAR_DEFINE(my_condvar);

等待条件变量

线程可调用 k_condvar_wait() 等待条件成立。

以下代码在条件变量上等待。

K_MUTEX_DEFINE(mutex);
K_CONDVAR_DEFINE(condvar)

int main(void)
{
    k_mutex_lock(&mutex, K_FOREVER);

    /* block this thread until another thread signals cond. While
     * blocked, the mutex is released, then re-acquired before this
     * thread is woken up and the call returns.
     */
    k_condvar_wait(&condvar, &mutex, K_FOREVER);
    ...
    k_mutex_unlock(&mutex);
}

向条件变量发信号

调用 k_condvar_signal() 可通知一个线程，调用 k_condvar_broadcast() 可通知多个线程。

以下代码接续上例。

void worker_thread(void)
{
    k_mutex_lock(&mutex, K_FOREVER);

    /*
     * Do some work and fulfill the condition
     */
    ...
    ...
    k_condvar_signal(&condvar);
    k_mutex_unlock(&mutex);
}

建议用法

结合互斥锁使用条件变量，可将状态（条件）的改变通知另一个线程。条件变量不是条件本身，也不是事件；真正的条件由周围的程序逻辑决定。

互斥锁本身不是通知机制，其作用是保证对共享资源的互斥访问。
