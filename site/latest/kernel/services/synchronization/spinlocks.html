自旋锁（Spinlocks）

自旋锁（spinlock）是 Zephyr 最底层的互斥原语，用于保护短临界区：同一时刻只有一个执行上下文可以访问共享资源。发现锁已被占用的上下文不会阻塞并让出 CPU，而是忙等，直到锁可用。因此自旋锁只适用于短临界区。

获取自旋锁还会在持锁期间屏蔽本 CPU 的中断。因此线程与中断处理程序可以安全地共用这把锁：同一 CPU 上的 ISR 不能抢占持锁者，其他 CPU 也不能取得同一把锁，两者都不能在数据更新到一半时读到或破坏它。正因如此，Zephyr 内核主要用 k_spinlock 保护自己的核心数据结构。

译校注 · F02-01

这里的 ISR 指常规中断锁能屏蔽的中断。在支持且启用零延迟中断的架构上，此类中断仍可能抢占当前 CPU；不能在其处理程序里依赖这把锁保护普通内核上下文正在修改的数据，也不能去获取同一把已持有的锁。

固定版本依据：Zephyr 1b1b2e0cdca4

spinlock.h：197–206；interrupts.rst：163–182

应用也可以直接使用自旋锁，但一般优先考虑 k_mutex、k_sem 等较高层的同步原语。

用法

为每项需单独保护的资源声明一个 k_spinlock。用 k_spin_lock() 获取锁，它返回的 k_spinlock_key_t 必须传回 k_spin_unlock() 才能释放锁：

static struct k_spinlock lock;

void update_shared_state(void)
{
        k_spinlock_key_t key = k_spin_lock(&lock);

        /* critical section: exclusive access */

        k_spin_unlock(&lock, key);
}

K_SPINLOCK 在代码块开始时获取锁，在退出代码块时自动释放锁。

K_SPINLOCK(&lock) {
        /* critical section: exclusive access */
}

代码块必须正常执行至末尾，或通过 K_SPINLOCK_BREAK 退出。直接使用 break、goto 或 return 会跳过解锁，使锁一直被占用：

K_SPINLOCK(&lock) {
        if (nothing_to_do) {
                K_SPINLOCK_BREAK;
        }

        /* critical section: exclusive access */
}

不自旋地尝试获取锁

k_spin_trylock() 只尝试获取一次锁，失败就返回而不等待，适合调用者还有其他工作或不能停顿的情况。成功时会保存键值，解锁方法与 k_spin_lock() 相同：

k_spinlock_key_t key;

if (k_spin_trylock(&lock, &key) == 0) {
        /* critical section: exclusive access */
        k_spin_unlock(&lock, key);
} else {
        /* lock is held elsewhere, do something else */
}

使用规则

使用自旋锁时应遵守下列规则：

  • 尽量缩短临界区。持锁期间本 CPU 的中断被屏蔽，其他 CPU 也可能正在忙等这把锁。

  • 持有自旋锁期间，绝不能执行可能阻塞或休眠的操作。

  • 不要递归获取同一把自旋锁；持锁者再次获取它会死锁。可以嵌套获取不同的自旋锁，但必须遵守一致的加锁顺序，以免死锁。

单处理器上的自旋锁

若构建内核时禁用 CONFIG_SMP，自旋锁实际上不会自旋。单 CPU 上没有其他 CPU 与之争用，k_spin_lock() 只需屏蔽本 CPU 的中断。这样 ISR 和发生上下文切换后的代码都不会看到更新到一半的数据，足以保证单处理器上的互斥。

自旋锁使用检查

启用 CONFIG_SPIN_VALIDATE 可检测下列自旋锁误用：

  • 递归获取同一把自旋锁

  • 释放并非当前上下文持有的锁

  • 违反嵌套顺序解锁（仍持有内层锁时释放外层锁）

  • 持有自旋锁或通过嵌套的 irq_lock() 屏蔽中断时切换上下文

在单处理器上，只有递归加锁检查有意义。没有其他 CPU 争用，且持锁时中断被屏蔽，因此其余列出的误用不会发生。

公平自旋锁

默认实现使用单个 atomic_t 变量，不保证竞争者公平获锁：某个 CPU 可能反复抢到锁，使其他 CPU 饥饿。需要公平性时，启用 CONFIG_TICKET_SPINLOCKS 可改用取票机制，按请求先后（FIFO）授予锁，代价是锁对象稍大。

适用场景

线程与中断处理程序之间，或 SMP 系统的不同 CPU 之间共享短临界区时，可用自旋锁保护。

若以下原语更合适，应优先选用：

  • k_mutex：临界区较长或可能阻塞、休眠时使用。只有线程可以获取互斥锁。

  • k_sem：用于上下文之间的通知，或对资源池的访问进行计数。

  • 原子服务：共享状态只有一个机器字且可通过一次原子操作更新时，无须加锁。
