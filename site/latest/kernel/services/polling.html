轮询接口（Polling API）

轮询 API 可以同时等待多个条件，只要其中一个满足即可返回。

基本概念

主要函数 k_poll() 类似于 POSIX 的 poll()，但操作对象是内核对象而不是文件描述符。

单个线程可同时等待一个或多个条件成立，无须逐一主动检查。

可等待的条件如下：

  • 信号量可用

  • 内核 FIFO 中有数据可取

  • 内核 LIFO 中有数据可取

  • 内核消息队列中有数据可取

  • 内核管道中有数据可取，或管道已关闭

  • 轮询信号已触发

要等待多个条件，线程须定义轮询事件（poll events）数组，每个条件对应一个元素。

在轮询数组前，必须初始化其中所有事件。

每个事件须指定条件的type；满足相应条件时，事件状态会改变，以指示已就绪。

每个事件须指定要等待哪个内核对象满足条件。

每个事件须指定条件满足时采用的操作态。

事件还可带有可选的标签（tag），供用户将多个事件分组。

除内核对象外，还有一种可直接触发的伪对象：轮询信号（poll signal）。

只要一个条件成立，k_poll() 就返回。但 k_poll() 返回时可能已有多个条件成立：有些在调用 k_poll() 前就已成立，有些是在抢占式多线程运行中成立。调用者须检查数组中所有事件的状态，再决定如何处理。

目前唯一支持的模式只通知就绪，不获取对象。即使 k_poll() 返回且事件显示信号量可用，k_poll() 的调用者仍须调用 k_sem_take() 获取信号量。如果存在竞争，到执行 k_sem_take() 时它不一定还可用。

实现

使用 k_poll()

主要接口 k_poll() 接受 k_poll_event 类型的轮询事件数组。数组中的每个元素代表一个待满足的条件，k_poll() 等待其中的条件就绪。

可用运行时初始化器 K_POLL_EVENT_INITIALIZER()、k_poll_event_init()，或静态初始化器 K_POLL_EVENT_STATIC_INITIALIZER()。传入的对象必须与指定的 type 匹配。态 必须设为 K_POLL_MODE_NOTIFY_ONLY；初始状态必须为 K_POLL_STATE_NOT_READY（初始化器会设置）。用户自定的 标签（tag） 并非必填，API 不解释它，仅供事件分组。静态初始化时可直接传入；出于性能考虑，运行时初始化器没有这个参数，需另行设置 k_poll_event 中的字段。若要暂时忽略数组中的某个事件，可将其类型设为 K_POLL_TYPE_IGNORE。

struct k_poll_event events[4] = {
    K_POLL_EVENT_STATIC_INITIALIZER(K_POLL_TYPE_SEM_AVAILABLE,
                                    K_POLL_MODE_NOTIFY_ONLY,
                                    &my_sem, 0),
    K_POLL_EVENT_STATIC_INITIALIZER(K_POLL_TYPE_FIFO_DATA_AVAILABLE,
                                    K_POLL_MODE_NOTIFY_ONLY,
                                    &my_fifo, 0),
    K_POLL_EVENT_STATIC_INITIALIZER(K_POLL_TYPE_MSGQ_DATA_AVAILABLE,
                                    K_POLL_MODE_NOTIFY_ONLY,
                                    &my_msgq, 0),
    K_POLL_EVENT_STATIC_INITIALIZER(K_POLL_TYPE_PIPE_DATA_AVAILABLE,
                                    K_POLL_MODE_NOTIFY_ONLY,
                                    &my_pipe, 0),
};

或者在运行时

struct k_poll_event events[4];
void some_init(void)
{
    k_poll_event_init(&events[0],
                      K_POLL_TYPE_SEM_AVAILABLE,
                      K_POLL_MODE_NOTIFY_ONLY,
                      &my_sem);

    k_poll_event_init(&events[1],
                      K_POLL_TYPE_FIFO_DATA_AVAILABLE,
                      K_POLL_MODE_NOTIFY_ONLY,
                      &my_fifo);

    k_poll_event_init(&events[2],
                      K_POLL_TYPE_MSGQ_DATA_AVAILABLE,
                      K_POLL_MODE_NOTIFY_ONLY,
                      &my_msgq);

    k_poll_event_init(&events[3],
                      K_POLL_TYPE_PIPE_DATA_AVAILABLE,
                      K_POLL_MODE_NOTIFY_ONLY,
                      &my_pipe);

    // tags are left uninitialized if unused
}

事件初始化后即可将数组传给 k_poll()。可以指定最长等待时间，也可用 K_NO_WAIT 表示不等待，或用 K_FOREVER 表示一直等到至少一个条件就绪。

每个信号量或 FIFO 都维护自己的轮询等待者列表，应用可按需让多个事件在此等待。它们按先到先服务的顺序处理，而非按优先级处理。

成功时 k_poll() 返回 0，超时返回 -EAGAIN。

// assume there is no contention on this semaphore and FIFO
// -EADDRINUSE will not occur; the semaphore and/or data will be available

void do_stuff(void)
{
    rc = k_poll(events, ARRAY_SIZE(events), K_MSEC(1000));
    if (rc == 0) {
        if (events[0].state == K_POLL_STATE_SEM_AVAILABLE) {
            k_sem_take(events[0].sem, 0);
        } else if (events[1].state == K_POLL_STATE_FIFO_DATA_AVAILABLE) {
            data = k_fifo_get(events[1].fifo, 0);
            // handle data
        } else if (events[2].state == K_POLL_STATE_MSGQ_DATA_AVAILABLE) {
            ret = k_msgq_get(events[2].msgq, buf, K_NO_WAIT);
            // handle data
        } else if (events[3].state == K_POLL_STATE_PIPE_DATA_AVAILABLE) {
            bytes_read = k_pipe_read(events[3].pipe, buf, bytes_to_read, K_NO_WAIT);
            if (bytes_read == -EPIPE) {
                // pipe is closed
            } else {
                // handle data
            }
        }
    } else {
        // handle timeout
    }
}

循环调用 k_poll() 时，用户必须将各事件状态重置为 K_POLL_STATE_NOT_READY。

void do_stuff(void)
{
    for(;;) {
        rc = k_poll(events, ARRAY_SIZE(events), K_FOREVER);
        if (events[0].state == K_POLL_STATE_SEM_AVAILABLE) {
            k_sem_take(events[0].sem, 0);
        }
        if (events[1].state == K_POLL_STATE_FIFO_DATA_AVAILABLE) {
            data = k_fifo_get(events[1].fifo, 0);
            // handle data
        }
        if (events[2].state == K_POLL_STATE_MSGQ_DATA_AVAILABLE) {
            ret = k_msgq_get(events[2].msgq, buf, K_NO_WAIT);
            // handle data
        }
        if (events[3].state == K_POLL_STATE_PIPE_DATA_AVAILABLE) {
            bytes_read = k_pipe_read(events[3].pipe, buf, bytes_to_read, K_NO_WAIT);
            if (bytes_read == -EPIPE) {
                // closed pipe stays ready; stop polling it
                events[3].type = K_POLL_TYPE_IGNORE;
            } else {
                // handle data
            }
        }
        events[0].state = K_POLL_STATE_NOT_READY;
        events[1].state = K_POLL_STATE_NOT_READY;
        events[2].state = K_POLL_STATE_NOT_READY;
        events[3].state = K_POLL_STATE_NOT_READY;
    }
}

使用 k_poll_signal_raise()

K_POLL_TYPE_SIGNAL 是一种可以直接触发轮询事件的类型，可看作只允许一个线程等待的轻量二值信号量。

轮询信号是独立的 k_poll_signal 类型对象。与信号量或 FIFO 一样，须将它与 k_poll_event 关联，并先通过 K_POLL_SIGNAL_INITIALIZER() 或 k_poll_signal_init() 初始化。

struct k_poll_signal signal;
void do_stuff(void)
{
    k_poll_signal_init(&signal);
}

调用 k_poll_signal_raise() 触发信号。用户参数 结果值（result） 对 API 不透明解析，可用它向等待该事件的线程传递额外信息。

struct k_poll_signal signal;

// thread A
void do_stuff(void)
{
    k_poll_signal_init(&signal);

    struct k_poll_event events[1] = {
        K_POLL_EVENT_INITIALIZER(K_POLL_TYPE_SIGNAL,
                                 K_POLL_MODE_NOTIFY_ONLY,
                                 &signal),
    };

    k_poll(events, 1, K_FOREVER);

    int signaled, result;

    k_poll_signal_check(&signal, &signaled, &result);

    if (signaled && (result == 0x1337)) {
        // A-OK!
    } else {
        // weird error
    }
}

// thread B
void signal_do_stuff(void)
{
    k_poll_signal_raise(&signal, 0x1337);
}

在循环中轮询信号时，每轮若信号已触发，都须完成两项重置：将事件状态重置为 K_POLL_STATE_NOT_READY，并且用 k_poll_signal_reset() 重置其 result。

struct k_poll_signal signal;
void do_stuff(void)
{
    k_poll_signal_init(&signal);

    struct k_poll_event events[1] = {
        K_POLL_EVENT_INITIALIZER(K_POLL_TYPE_SIGNAL,
                                 K_POLL_MODE_NOTIFY_ONLY,
                                 &signal),
    };

    for (;;) {
        k_poll(events, 1, K_FOREVER);

        int signaled, result;

        k_poll_signal_check(&signal, &signaled, &result);

        if (signaled && (result == 0x1337)) {
            // A-OK!
        } else {
            // weird error
        }

        k_poll_signal_reset(&signal);
        events[0].state = K_POLL_STATE_NOT_READY;
    }
}

轮询信号没有内部同步。系统中任何代码调用 k_poll_signal_raise() 后，等待该信号的 k_poll() 即会返回。但若其他代码用 k_poll_signal_init() 管理和重置信号，应用检查时事件状态可能已不再是 K_POLL_STATE_SIGNALED，从而漏掉事件。最好只在运行 k_poll() 循环的线程内重置信号，或使用能保留事件计数的类型：就这点而言，信号量和 FIFO 在机制上不会漏掉事件。

建议用法

使用 k_poll() 可将原来分别等待各个对象的多个线程合并，节省可能相当可观的栈空间。

若只有一个线程等待，可把轮询信号用作轻量二值信号量。

说明

只有当没有其他线程正在等待对象可用时，才会向轮询者报告就绪；同一特定对象也只能由一个线程轮询。因此轮询最适合没有多线程争抢对象的情况，例如由单个线程担任多个对象的服务者或分派者，且只有该线程尝试获取它们。
