邮箱（Mailboxes）

非官方简体中文译本 · F09 · 英文基线 4.5.99 · 全站目录（94 篇） · F 批目录 · 本页英文原文

邮箱（mailbox）是比普通消息队列功能更丰富的内核对象，允许线程同步或异步收发任意大小的消息。

基本概念

邮箱数量仅受可用 RAM 限制，每个邮箱通过其内存地址引用。

邮箱有以下关键属性：

  • 发送队列：存放已发送、尚未被接收的消息。

  • 接收队列：存放等待接收消息的线程。

邮箱须先初始化再使用，其两个队列最初均为空。

只有线程可以通过邮箱交换消息，ISR 不可以。发出消息的是发送线程，接收消息的是接收线程。每条消息只交给一个线程，不支持点对多点或广播。

邮箱交换不是匿名的：双方都能得知甚至指定对方的线程身份。

消息格式

消息描述符（message descriptor）记录消息数据位于何处，以及邮箱应如何处理它。收发双方访问邮箱时各提供一个描述符；邮箱据此匹配双方并交换消息。交换时邮箱还会更新其中部分字段，使双方了解交换结果。

邮箱消息包含零个或多个字节的消息数据。大小与格式均由应用定义，不同消息可各不相同。

消息缓冲区是收发线程提供的一块内存，通常可以使用数组或结构体变量。

不含任何形式消息数据的消息称为空消息（empty message）。

说明

如果消息缓冲区存在，只是实际数据长度为零，则它不是空消息。

消息生命周期

发送线程将消息交给邮箱时，消息就创建了；在交给接收线程之前，它归邮箱所有。接收线程可在接收消息时获取数据，也可在第二次邮箱操作中再获取。只有在数据获取结束后，邮箱才删除消息。

收发线程的匹配条件

发送线程可指定目标线程地址，或指定 K_ANY 表示任何线程都可接收。接收线程也可指定来源线程地址，或用 K_ANY 表示接受任意来源。只有收发双方的筛选条件都满足，才会交换消息；这时称两个线程相互匹配（compatible）。

例如 A 只向 B 发送消息。B 若等待来自 A 或任意线程的消息，就可收到；若 B 只等 C，则不会交换。即使 C 等待来自 A 或任意来源的消息，C 也不可能收到这一条。

消息流量控制

邮箱交换可同步地或异步地进行。同步时发送线程阻塞，直到接收线程处理完整条消息。异步时发送线程无须等到有人接收即可继续：在消息交付并处理完成之前，即可做其他工作，例如收集下一条消息的数据。交换方式由发送线程决定。

同步交换隐含流量控制：发送者不会比接收者消耗消息更快地持续发送。异步交换则允许显式控制流量，例如发送下一条消息前先判断先前那条是否仍在邮箱中。

实现

定义邮箱

用 k_mbox 类型定义邮箱，再调用 k_mbox_init() 初始化。

以下代码定义并初始化一个空邮箱。

struct k_mbox my_mailbox;

k_mbox_init(&my_mailbox);

也可调用 K_MBOX_DEFINE 在编译期定义并初始化邮箱。

以下代码与上面的代码片段效果相同。

K_MBOX_DEFINE(my_mailbox);

消息描述符

消息描述符是 k_mbox_msg 类型的结构体。只应使用下列字段，其余字段仅供邮箱内部使用。

info（信息值）

由收发双方交换的 32 位值，含义由应用定义。每次交换时发送方都可传值给接收方；同步交换时接收方也可反向传值。

大小

消息数据大小，以字节计。发送空消息或发送有缓冲区但无实际数据的消息时都设为零。接收时设为需要的最大长度；不需要数据则设为零。收到消息后，邮箱将它更新为实际交换的字节数。

tx_data

发送线程的消息缓冲区指针。发空消息时设为 NULL；接收时不必初始化此字段。

tx_target_thread

期望的接收线程地址。设为 K_ANY 可允许任意线程接收。接收消息时不必初始化；收到后邮箱会写入实际接收者地址。

rx_source_thread

期望的发送线程地址。设为 K_ANY 可接受任意来源。发送时不必初始化；消息放入邮箱时，邮箱会写入实际发送者地址。

发送消息

发送线程首先准备消息数据（如果有）。

然后按照上一节的说明创建消息描述符，描述准备发送的消息。

最后调用邮箱发送 API 发起交换。如有匹配的接收线程在等待，消息会立即交给它；否则消息加入邮箱的发送队列。

发送队列可同时容纳任意数量的消息。先按发送线程优先级排序；优先级相同时，最早的消息先被接收。

同步发送通常要等接收线程既收到消息、又取走数据才结束。如果在发送者指定的期限内无人接收，消息会从发送队列移除，发送失败。成功后，发送者可检查描述符，了解接收者身份、实际交换的字节数，以及接收者提供的应用自定义 info 值。

说明

即使指定最大等待时间，同步发送也可能无限期阻塞。超时只限制等待其他线程接收消息的阶段。一旦被接收，接收线程取走数据、解除发送线程阻塞所用的时间就没有上限。

异步发送始终立即返回，无论消息是马上交付还是加入发送队列，发送方都可继续执行。可以指定一个信号量：邮箱在删除消息时（例如接收者已收到并取走数据后）释放该信号量。这样就能实现流量控制，保证任一时刻邮箱中来自某个或某些发送线程的消息数量不超过应用指定的上限。

译校注 · F09-02

异步发送不等待接收线程取走或处理消息，但内部异步消息描述符由 CONFIG_NUM_MBOX_ASYNC_MSGS 限量，且各邮箱共用。描述符耗尽时，k_mbox_async_put() 可能等待可用描述符，因而不能承诺总是立即返回。

固定版本依据：Zephyr 1b1b2e0cdca4

mailbox.c：36–51；mailbox.c：364–385；Kconfig：649–658

说明

异步发送的线程无法据此得知哪一线程接收了消息、实际交换了多少数据，也无法得到接收方指定的 info 值。

发送空消息

此例用邮箱把 4 字节随机值同步交给需要它的任一消费线程。所需信息能完全放进 info 字段，因此不使用消息数据区。

void producer_thread(void)
{
    struct k_mbox_msg send_msg;

    while (1) {

        /* generate random value to send */
        uint32_t random_value = sys_rand32_get();

        /* prepare to send empty message */
        send_msg.info = random_value;
        send_msg.size = 0;
        send_msg.tx_data = NULL;
        send_msg.tx_target_thread = K_ANY;

        /* send message and wait until a consumer receives it */
        k_mbox_put(&my_mailbox, &send_msg, K_FOREVER);
    }
}

用消息缓冲区发送数据

此例通过邮箱将生产线程的变长请求同步交给任一消费线程。双方用 info 字段交换自己能处理的消息缓冲区最大容量。

void producer_thread(void)
{
    char buffer[100];
    int buffer_bytes_used;

    struct k_mbox_msg send_msg;

    while (1) {

        /* generate data to send */
        ...
        buffer_bytes_used = ... ;
        memcpy(buffer, source, buffer_bytes_used);

        /* prepare to send message */
        send_msg.info = buffer_bytes_used;
        send_msg.size = buffer_bytes_used;
        send_msg.tx_data = buffer;
        send_msg.tx_target_thread = K_ANY;

        /* send message and wait until a consumer receives it */
        k_mbox_put(&my_mailbox, &send_msg, K_FOREVER);

        /* info, size, and tx_target_thread fields have been updated */

        /* verify that message data was fully received */
        if (send_msg.size < buffer_bytes_used) {
            printf("some message data dropped during transfer!");
            printf("receiver only had room for %d bytes", send_msg.info);
        }
    }
}

接收消息

接收者先创建描述符，说明期望的消息，再调用邮箱接收 API。邮箱在发送队列中寻找第一个相容的发送者并取出其消息。找不到时可选择等待；期限内仍无匹配则接收失败。成功后，可从描述符了解发送者身份、交换字节数及发送者提供的自定义 info 值。

接收队列上可同时有任意数量的线程等待。按优先级排序；优先级相同时，等待最久者先接收。

说明

受线程匹配条件限制，接收顺序未必是 FIFO。例如 A 先等待来自 X 的消息，B 随后等待来自 Y 的消息。Y 如向任意线程发送，消息交给 B，A 继续等待。

接收者决定读取多少数据以及保存到哪里：可以取全部、只取开头一段，或完全不取；也可指定自己的缓冲区作为复制目的地。

下面介绍接收线程获取数据的几种方法。

接收时立即取数据

最直接的方法是接收时提供消息缓冲区：线程须指定非 NULL 的缓冲区地址及大小。

邮箱在接收操作中将数据复制到缓冲区。缓冲区太小，未能复制的部分会丢失；消息太短，缓冲区剩余部分保持原状。不论哪种情况，邮箱都会将实际复制的字节数（可能为零）写回接收者的描述符。

收到时立即复制最适合大小上限已知的小消息。

下例立即取得数据，处理任一生产线程提交的变长请求。双方用 info 字段交换各自能处理的缓冲区最大容量。

void consumer_thread(void)
{
    struct k_mbox_msg recv_msg;
    char buffer[100];

    int i;
    int total;

    while (1) {
        /* prepare to receive message */
        recv_msg.info = 100;
        recv_msg.size = 100;
        recv_msg.rx_source_thread = K_ANY;

        /* get a data item, waiting as long as needed */
        k_mbox_get(&my_mailbox, &recv_msg, buffer, K_FOREVER);

        /* info, size, and rx_source_thread fields have been updated */

        /* verify that message data was fully received */
        if (recv_msg.info != recv_msg.size) {
            printf("some message data dropped during transfer!");
            printf("sender tried to send %d bytes", recv_msg.info);
        }

        /* compute sum of all message bytes (from 0 to 100 of them) */
        total = 0;
        for (i = 0; i < recv_msg.size; i++) {
            total += buffer[i];
        }
    }
}

稍后用消息缓冲区取数据

接收线程可先收消息、稍后再把数据取入缓冲区。为此，接收时将缓冲区地址指定为 NULL，大小设为愿意在稍后获取的最大数据量。

此时邮箱不复制数据，但仍更新接收者的描述符，指出有多少字节可取。

接下来，接收线程必须按下列情况处理：

  • 描述符中的大小为零，表示发送方没有数据或接收方不需要数据。此时邮箱已结束数据获取并删除消息，接收线程无须再操作。

  • 大小非零且仍要获取数据时，必须调用 k_mbox_data_get() 并提供足够大的缓冲区。邮箱将数据复制进去，随后删除消息。

  • 大小非零但接收线程不想获取数据时，仍必须调用 k_mbox_data_get()，并将缓冲区设为 NULL。此时邮箱不复制数据，直接删除消息。

不宜立即提取数据时，可采用延后获取。例如内存受限，接收者不可能总是提供足以容纳最大消息的缓冲区。

下例仅在消息符合条件时才从生产线程获取数据，避免不必要的复制。接收方按发送者提供的 info 字段将消息分类。

void consumer_thread(void)
{
    struct k_mbox_msg recv_msg;
    char buffer[10000];

    while (1) {
        /* prepare to receive message */
        recv_msg.size = 10000;
        recv_msg.rx_source_thread = K_ANY;

        /* get message, but not its data */
        k_mbox_get(&my_mailbox, &recv_msg, NULL, K_FOREVER);

        /* get message data for only certain types of messages */
        if (is_message_type_ok(recv_msg.info)) {
            /* retrieve message data and delete the message */
            k_mbox_data_get(&recv_msg, buffer);

            /* process data in "buffer" */
            ...
        } else {
            /* ignore message data and delete the message */
            k_mbox_data_get(&recv_msg, NULL);
        }
    }
}

建议用法

消息队列的能力不足以满足线程间传输需求时，可改用邮箱。
