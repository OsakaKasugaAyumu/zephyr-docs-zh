内存堆（Memory Heaps）

非官方简体中文译本 · G04 · 英文基线 4.5.99 · 全站目录（79 篇） · G 批目录 · 本页英文原文

Zephyr 提供一组工具，供线程动态分配内存。

带同步机制的堆分配器

创建堆

最简单的方式是用 K_HEAP_DEFINE 静态定义堆。该宏创建一个指定名称的静态 k_heap 变量，用来管理指定大小的内存区域。

也可使用 k_heap_init() 创建堆，管理由应用控制的任意内存区域。

分配内存

调用 k_heap_alloc() 时传入堆对象地址和所需字节数。它类似标准 C 的 malloc()，分配失败时返回 NULL 指针。

堆支持阻塞等待，缺少可用内存时线程可休眠。最后一个参数是 k_timeout_t 类型的最长等待时间，也可以是常量 K_NO_WAIT 或 K_FOREVER。

需要特定对齐时，用 k_heap_aligned_alloc() 分配。块的起始地址是指定对齐值的倍数；该值必须为 2 的幂。k_heap_calloc() 则分配数组并将其清零。

用 k_heap_realloc() 可调整已分配块的大小，并保留新旧大小中较小者所覆盖的原内容。与标准 C 的 realloc() 一样，返回地址可能改变。

释放内存

用 k_heap_alloc() 分配的内存必须用 k_heap_free() 释放。与标准 C 的 free() 类似，传入的指针必须是 NULL，或是此前从同一堆通过 k_heap_alloc() 返回的指针。释放 NULL 不产生任何效果。

枚举堆

用 K_HEAP_DEFINE 静态定义的堆位于专用链接段，可在运行时枚举。k_heap_array_get() 返回堆数组的地址和条目数量，主要用于需检查系统中每个堆的监测和诊断工具。

底层堆分配器

k_heap 底层使用名为 sys_heap 的数据结构。分配语义相同，但后者没有内核同步机制，适合在同步不可用或不便实现的环境（如用户空间）自主管理内存。不同于 k_heap，调用者必须使同一堆上的所有 sys_heap 操作串行执行，不允许不同线程同时访问。

实现

sys_heap 将内存划分成 8 字节的小单元（chunk），每次分配占用连续的若干单元。每个已分配块或空闲块的首单元包含块头：记录本块长度、物理地址上左侧相邻块的长度、占用标志，以及空闲链表中前后块的单元索引。

为减少碎片，空闲块按大小分桶。相邻桶的容量界限约相差一倍，如 3–4、5–8、9–16 个单元。这样能优先使用可容纳请求的较小碎块。归还内存时，还会与相邻的空闲块自动合并。

包括各桶链表头在内的元数据都保存在连续堆内存的起始处；桶头列表长度随堆大小变化。外部只需存放 sys_heap 结构本身。

sys_heap 不负责同步。调用者必须防止并发访问；同一时刻只能有一个上下文在某个 API 中操作同一堆。

sys_heap 的所有 API 均保证在常数时间内完成，在典型架构上耗时 1–200 个周期。为避免无界链表搜索，在最小候选桶中查找可能容纳请求的块时，迭代次数有编译期上限，代价是抑制碎片的能力略有下降。可在构建时设置 CONFIG_SYS_HEAP_ALLOC_LOOPS，默认值为 3。

多堆封装工具

sys_heap 只能管理单个连续区域。复杂微控制器应用仍可能需要以堆的方式使用多个不连续区域：它们的缓存特性、性能或功耗可能不同，外设也可能仅能对特定区域执行 DMA。

为此，Zephyr 提供 sys_multi_heap，它封装一个或多个 sys_heap。先初始化子堆，再调用 sys_multi_heap_init() 初始化多堆，用 sys_multi_heap_add_heap() 逐个加入子堆。与 sys_heap 一样，没有专门的销毁接口；应先确保所有分配都已释放（或绝不会再使用），再将底层内存改作他用。

分配入口为 sys_multi_heap_alloc() 和 sys_multi_heap_aligned_alloc()，与 sys_heap 的同名类函数相似，只是额外接受配置指针。多堆实现不解释其内容，而会把它交给初始化时注册的应用回调；回调可据此决定使用哪个子堆，并完成实际分配。

要扩大或缩小缓冲区，可用 sys_multi_heap_realloc() 或 sys_multi_heap_aligned_realloc()。若原堆无法扩展，配置参数允许的其他堆也可用于此次分配。

不再需要已分配的块时，可用 sys_multi_heap_free() 释放，无须提供配置参数。从任一受管理的 sys_heap 对象分配的内存均可按此方式归还。

系统堆

系统堆（system heap）是预定义分配器，允许线程以类似 malloc() 的方式从公共区域动态分配内存。

系统堆只有一个；不同于其他堆或内存池，它不能直接通过内存地址引用。

系统堆大小可按需配置，但受实际可用空间限制。

线程调用 k_malloc() 可动态分配一块内存，返回地址按指针大小的倍数对齐。找不到合适空间则返回 NULL。

线程用完后，调用 k_free() 归还给系统堆。

定义堆内存池

用 CONFIG_HEAP_MEM_POOL_SIZE 配置堆内存池的大小。

默认大小为零字节，表示内核不定义该对象。最大值取决于系统的可用内存；无法容纳所配容量时，构建会在链接阶段失败。

板级支持、驱动、库等子系统可借助以 HEAP_MEM_POOL_ADD_SIZE_ 开头的 Kconfig 选项声明需求（单位：字节）。多个子系统的需求之和构成最小值；若应用配置低于该值，设置会被忽略，改用最小值。

若已能准确确定特定应用所需的堆大小，可启用 CONFIG_HEAP_MEM_POOL_IGNORE_MIN，强制采用比上述最小值更小的值。

分配内存

调用 k_malloc() 分配一块堆内存。

下例分配 200 字节并清零；分配失败时发出警告。

char *mem_ptr;

mem_ptr = k_malloc(200);
if (mem_ptr != NULL)) {
    memset(mem_ptr, 0, 200);
    ...
} else {
    printf("Memory not allocated");
}

释放内存

调用 k_free() 释放一块堆内存。

下例分配 75 字节，不再需要时将其释放。

char *mem_ptr;

mem_ptr = k_malloc(75);
... /* use memory block */
k_free(mem_ptr);

建议用法

使用堆内存池可以按类似 malloc() 的方式动态分配内存。

相关配置选项：
