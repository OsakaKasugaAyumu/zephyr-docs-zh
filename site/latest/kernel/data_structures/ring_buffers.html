环形缓冲区（Ring Buffers）

非官方简体中文译本 · G06 · 英文基线 4.5.99 · 全站目录（79 篇） · G 批目录 · 本页英文原文

环形缓冲区（ring buffer）以循环方式使用存储空间，按先进先出顺序保存数据。

当应用需要以异步数据流的方式复制数据时，Zephyr 提供 struct ring_buf 来管理数据在共享缓冲区中的写入和读取。

基本概念

环形缓冲区的数量仅受可用 RAM 限制，每个缓冲区通过内存地址引用。

环形缓冲区的关键属性如下：

  • 按字节存储的数据缓冲区，包含已经写入但尚未取出的原始数据。

  • 以字节计的数据缓冲区大小，决定最多能存放多少数据。

环形缓冲区必须先初始化再使用，初始化后数据区为空。

struct ring_buf 可放在用户可访问的任何内存位置。使用前须调用 ring_buf_init()，并提供一段由用户管理的内存作为实际缓冲区。注意：传入的大小可能以字节或机器字为单位，取决于随后的用法。也可使用宏在一次静态声明中完成两步。RING_BUF_DECLARE 按指定字节数声明并静态初始化环形缓冲区。

向 ring_buf_put() 传入数据指针和字节数，即可按顺序复制数据，空间不足时只复制放得下的部分。返回实际复制的字节数，可能少于请求值。相应地，ring_buf_get() 按写入顺序将数据复制到用户提供的缓冲区，返回实际传输字节数。

为避免多次复制，可用零拷贝指针接口。ring_buf_put_ptr() 返回可直接写入的位置及该处的连续可写长度；若剩余空间跨越末端，连续长度可能小于总空闲空间。用户可直接写入（例如由 DMA 写入），不必先拼成连续数据。结束后用 ring_buf_commit() 提交实际写入的字节数，再开始下一次传输。读取时，ring_buf_get_ptr() 提供可直接访问的内部地址，无须额外复制；用 ring_buf_consume() 告知已消费的字节数后即可继续。

旧的 ring_buf_put_claim()／ring_buf_put_finish() 和 ring_buf_get_claim()／ring_buf_get_finish() 也提供类似功能，但在操作结束前会保留申领的区域，增加代码体积和运行开销。这些接口已弃用，未来版本将移除；新代码应使用上文的 _ptr、_commit、_consume 变体。

可通过 ring_buf_space_get() 查询剩余可写字节数，或用 ring_buf_is_empty() 判断是否为空；二者均不修改缓冲区。

调用 ring_buf_reset() 会立即清空缓冲区的跟踪状态、丢弃已有数据记录，但不会改写底层内存的内容。

创建与使用

使用 RING_BUF_DECLARE() 声明实例，通过 ring_buf_put_ptr()、ring_buf_commit()、ring_buf_get_ptr()、ring_buf_consume()、ring_buf_put() 和 ring_buf_get() 访问。

可将数据复制到缓冲区（见 ring_buf_put()），也可直接访问内部内存。后者分三步：

  1. 调用 ring_buf_put_ptr() 取得下一可写位置的指针及该处的连续可写长度。

  2. 由用户写入数据（例如通过 DMA 写入）。

  3. 用 ring_buf_commit() 告知实际写入量。提交的字节数可以小于或等于 ring_buf_put_ptr() 提供的连续长度。

可通过复制（见 ring_buf_get()）取出数据，也可使用地址直接访问。后者分三步：

  1. 用 ring_buf_get_ptr() 取得下一可读位置的指针，以及该处的连续可读长度。

  2. 处理数据。

  3. 用 ring_buf_consume() 告知缓冲区数据已消费。消费量可以小于或等于 ring_buf_get_ptr() 提供的连续可读长度。

并发访问

环形缓冲区不提供内部并发控制。根据并发读写者的数量等因素，应用可能需要用互斥锁保护访问，或用信号量通知消费者已有数据可读。

若只有一个生产者和一个消费者，即使分属不同执行上下文（例如两个线程，或一个线程和一个 ISR），也可无需额外加锁地并发使用同一缓冲区。生产者只更新 put 索引，消费者只更新 get 索引，双方不会写同一字段。复制接口（ring_buf_put()、ring_buf_get()）和零拷贝申领接口（ring_buf_put_claim()／ring_buf_put_finish()、ring_buf_get_claim()／ring_buf_get_finish()）均如此。

若同时存在多个生产者或多个消费者，必须在外部将相应访问串行化，例如使用互斥锁或禁止抢占。

内部工作原理

字节按顺序写入，达到缓冲区末尾后回到首元素，因而形成环。struct ring_buf 保存缓冲区指针和大小，以及标记下次读写位置的头、尾索引。

普通 put/get 接口会隐藏回绕边界。但申领接口无法返回横跨末端的一段连续地址；靠近末端的传输可能必须调用两轮 claim/finish，影响性能。

实现

定义环形缓冲区

用 ring_buf 类型定义环形缓冲区，再调用 ring_buf_init() 初始化。

在文件作用域可使用宏于编译期定义并初始化环形缓冲区；宏同时定义管理结构和数据区。

下例定义环形缓冲区：

#define MY_RING_BUF_BYTES 93
RING_BUF_DECLARE(my_ring_buf, MY_RING_BUF_BYTES);

写入数据

调用 ring_buf_put() 将字节复制到环形缓冲区。

uint8_t my_data[MY_RING_BUF_BYTES];
uint32_t ret;

ret = ring_buf_put(&ring_buf, my_data, MY_RING_BUF_BYTES);
if (ret != MY_RING_BUF_BYTES) {
    /* not enough room, partial copy. */
    ...
}

也可直接访问缓冲区内存写入数据。例如：

uint32_t size;
uint32_t rx_size;
uint8_t *data;

/* Get pointer to writable area within the ring buffer memory. */
size = ring_buf_put_ptr(&ring_buf, &data, 0);

/* Work directly on a ring buffer memory. */
rx_size = uart_rx(data, size);

/* Indicate amount of valid data. rx_size must be equal or less than size. */
ring_buf_commit(&ring_buf, rx_size);

读取数据

调用 ring_buf_get() 将字节从环形缓冲区复制出来。例如：

uint8_t my_data[MY_DATA_BYTES];
size_t  ret;

ret = ring_buf_get(&ring_buf, my_data, sizeof(my_data));
if (ret != sizeof(my_data)) {
    /* Fewer bytes copied. */
} else {
    /* Requested amount of bytes retrieved. */
    ...
}

也可直接访问缓冲区内存读取数据。例如：

uint32_t size;
uint32_t proc_size;
uint8_t *data;

/* Get pointer to readable data within the ring buffer memory. */
size = ring_buf_get_ptr(&ring_buf, &data, 0);

/* Work directly on a ring buffer memory. */
proc_size = process(data, size);

/* Indicate amount of data that has been consumed. proc_size must be equal
 * or less than size.
 */
ring_buf_consume(&ring_buf, proc_size);

配置选项

相关配置选项：

  • CONFIG_RING_BUFFER：恢复已弃用的旧接口（claim/finish 和定长数据项 API）。环形缓冲区本身仅依赖头文件，始终可用，常规使用不需要启用该选项。

  • CONFIG_RING_BUFFER_LARGE：将缓冲区的最大尺寸从 32 KB 提高到 1 GB。
