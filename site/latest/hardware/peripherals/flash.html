闪存设备接口（Flash）

非官方简体中文译本 · J02 · 英文基线 4.5.99 · 全站目录（94 篇） · J 批目录 · 本页英文原文

概述

闪存偏移量（flash offset）的基准

用户 API 的偏移量均相对于闪存的起始地址。对于闪存控制器管理的常规存储区，只要可以通过页布局 API 查询其布局（见 CONFIG_FLASH_PAGE_LAYOUT），就应遵守这条规则。

厂商为特定用途预留的闪存区域可以例外；页布局 API 本身就不涵盖这类区域。

闪存模拟器（Flash Simulator）

概述

闪存模拟器以 RAM 模拟闪存设备，主要用于在没有物理闪存的目标上开发和测试，例如 native_sim 和 qemu_x86。

模拟器实现了 Zephyr 标准闪存 API，应用可以像操作实际硬件控制器一样读取、写入和擦除数据。

配置

设备树（Devicetree）

要使用闪存模拟器，请在设备树（devicetree）中定义一个与 zephyr,sim-flash 兼容的节点。

使用标准设备树属性描述模拟闪存的物理特性，例如容量和块大小：

flash0: flash_simulator@0 {
         compatible = "zephyr,sim-flash";
         reg = <0x00000000 DT_SIZE_K(1024)>;
         erase-block-size = <1024>;
         write-block-size = <4>;
         erase-value = <0xff>;
};

译校注 · J02-U01

模拟器的设备树层级

在所核驱动中，模拟器实例提供 erase-value；闪存的基址、容量、erase-block-size 和 write-block-size 则取自闪存子节点。上例把这些属性写在同一节点，使用时应对照目标板的设备树层级。

  • reg：模拟闪存的基地址及总容量。

  • erase-block-size：一个可擦除块的大小，以字节为单位。

  • write-block-size：写入操作的最小对齐要求，以字节为单位。

  • erase-value：存储单元擦除后的值，通常是 0xff 或 0x00。

  • memory-region（可选）：指向某个内存区域的节点句柄（phandle）。指定后，启动时不会清空这片内存。

Kconfig 选项

模拟器提供以下 Kconfig 选项，用于模拟实际硬件的行为：

  • CONFIG_FLASH_SIMULATOR：启用闪存模拟器驱动。

  • CONFIG_FLASH_SIMULATOR_EXPLICIT_ERASE：要求写入前显式擦除，用来模拟必须先擦除才能翻转相应数据位的实际闪存。

  • CONFIG_FLASH_SIMULATOR_SIMULATE_TIMING：模拟硬件访问时序。

  • CONFIG_FLASH_SIMULATOR_MIN_READ_TIME_US：一次读取操作的模拟延迟。

  • CONFIG_FLASH_SIMULATOR_MIN_WRITE_TIME_US：一次写入操作的模拟延迟。

  • CONFIG_FLASH_SIMULATOR_MIN_ERASE_TIME_US：一次擦除操作的模拟延迟。

  • CONFIG_FLASH_SIMULATOR_STATS：通过 Zephyr 统计子系统收集操作统计信息。

译校注 · J02-U02

显式擦除的前提

显式擦除约束的是目标编程单元的状态，不是每调用一次写入就要先擦一次。单元已处于擦除态时可以编程；能否重复写入、允许改变哪些位，还取决于模拟器的擦除值和配置。擦除按块进行，可能影响同块内的其他数据。

微秒延迟不是超时

启用 CONFIG_FLASH_SIMULATOR_SIMULATE_TIMING 后，上述三个 MIN_*_TIME_US 选项分别设置读、写、擦除的模拟最短耗时，单位是微秒（µs）。它们不是请求超时，也不是最长完成时间。
