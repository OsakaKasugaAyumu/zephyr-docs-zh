CAN 控制器（CAN Controller）

概述

控制器局域网（CAN）是一种双线串行总线，见 Bosch CAN 规范、Bosch 可变数据速率 CAN（CAN FD）规范及 ISO 11898-1:2003 标准。CAN 最为人熟知的用途是车载通信，也用于家庭自动化、工业自动化等产品。

警告

只有检测到连续至少 11 个隐性位的总线空闲状态，CAN 控制器才能初始化。因此务必使 CAN RX 至少短时间保持高电平；环回模式同样需要满足此条件。

ISO 11898-1:2003 中定义的位时序如下：

官方原图：CAN 位时序：同步段、传播段、相位段与采样点

一个位分成四段。

  • Sync_Seg（同步段）：节点在同步段的边沿同步。此段固定为一个时间量子（TQ）。

  • Prop_Seg（传播段）：补偿总线信号传播延迟，以及收发器和节点带来的其他延迟。

  • Phase_Seg1 和 Phase_Seg2（相位段 1、2）：二者确定采样点。采样在 Phase_Seg1 结束时进行。

位时间等于（Sync_Seg + Prop_Seg + Phase_Seg1 + Phase_Seg2）乘以单个时间量子的时长。位速率是位时间的倒数。

采样点位于 Phase_Seg1 与 Phase_Seg2 之间，需要由用户选择。原文给出的 CiA 建议值是一个位时间的 87.5%。

再同步跳转宽度（SJW）以时间量子为单位，规定因再同步而移动采样点时最多可移动多少。

初始时序由设备树设置，可以在运行时用时序 API 修改。参数可以用 SJW、位速率和采样点表示，也可用位速率、Prop_Seg、Phase_Seg1 和 Phase_Seg2 表示。

CAN 用标识符标记帧，而非用地址标记节点。标准（基本）帧的标识符为 11 位，扩展帧为 29 位；Zephyr 可同时支持二者。帧以显性的帧起始位开头，之后发送标识符，进入仲裁。此时允许多个节点同时发送：显性位会覆盖隐性位。节点一边发送一边监测总线，发现自己的位被覆盖便退出本轮发送，因此数值较小的标识符具有较高的仲裁优先级。

过滤器只放行本节点关心的标识符，不匹配任何过滤器的帧会被忽略。利用掩码可要求全部或部分位匹配。标准标识符 11 位或扩展标识符 29 位的掩码若全部为 1，就必须完全匹配；掩码为 0 的位不参与比较。多数控制器的硬件过滤器数量有限，Kconfig 也设置数量上限以节约内存。

节点发现帧错误时，会用错误帧覆盖当前帧的一部分。控制器根据状态发送被动或主动错误帧。错误主动状态的节点会发送连续六个显性位，这违反位填充规则，所有节点都能检测到；发送者随后可以重发。

初始化后，节点可能处于以下状态之一：

  • 错误主动（error-active）

  • 错误被动（error-passive）

  • 总线关闭（bus-off）

初始化后，节点处于错误主动状态，可以发送主动错误帧、ACK 和过载帧。每个节点都有接收和发送错误计数器；任一计数超过 127，就进入错误被动状态，不能再发送主动错误帧。冻结英文页将发送错误计数进一步增大至 255 描述为进入总线关闭状态；此时节点不得在总线上发送显性位。检测到 128 次「连续 11 个隐性位」后，处于总线关闭状态的节点可恢复。【译校注】英文页此处写作「增至 255」。请区分寄存器能显示的最大值和进入 bus-off 的判据：例如 Microchip 控制器文档规定发送错误计数 TEC 超过 255 才进入 bus-off。参见厂商错误处理说明（英文）。

进一步介绍请参见维基百科 CAN 条目。

Zephyr 支持以下 CAN 功能：

  • 标准和扩展标识符

  • 带掩码的过滤器

  • 环回模式和静默模式

  • 远程请求

发送

以下代码片段演示如何发送数据。

下例发送标识符为 0x123、携带 8 字节数据的标准帧。回调传 NULL 时，发送函数会阻塞，直到帧已发出并被至少一个其他节点确认，或发生错误。超时只影响获取发送邮箱的等待；一旦分配邮箱，发送就不能取消。

struct can_frame frame = {
        .flags = 0,
        .id = 0x123,
        .dlc = 8,
        .data = {1,2,3,4,5,6,7,8}
};
const struct device *const can_dev = DEVICE_DT_GET(DT_CHOSEN(zephyr_canbus));
int ret;

ret = can_send(can_dev, &frame, K_MSEC(100), NULL, NULL);
if (ret != 0) {
        LOG_ERR("Sending failed [%d]", ret);
}

本例发送标识符为 0x1234567、含 2 字节数据的扩展帧。发送完成或发生错误时调用提供的回调。将超时设为 K_FOREVER 会一直等待分配发送邮箱或出错，但不像上例那样等到消息发出才返回。

void tx_callback(const struct device *dev, int error, void *user_data)
{
        char *sender = (char *)user_data;

        if (error != 0) {
                LOG_ERR("Sending failed [%d]\nSender: %s\n", error, sender);
        }
}

int send_function(const struct device *can_dev)
{
        struct can_frame frame = {
                .flags = CAN_FRAME_IDE,
                .id = 0x1234567,
                .dlc = 2
        };

        frame.data[0] = 1;
        frame.data[1] = 2;

        return can_send(can_dev, &frame, K_FOREVER, tx_callback, "Sender 1");
}

接收

只接收匹配过滤器的帧。以下代码演示如何添加过滤器并接收帧。

以下是配合 can_add_rx_filter() 使用的接收回调。用户数据参数在添加过滤器时提供。

void rx_callback_function(const struct device *dev, struct can_frame *frame, void *user_data)
{
        ... do something with the frame ...
}

下例添加带回调的过滤器。这是最高效、但对时序要求也最严格的接收方式：回调在中断上下文中执行，必须尽量简短，且绝不能阻塞。用户空间不能添加回调函数。

本例过滤器精确匹配标识符 0x123。

const struct can_filter my_filter = {
        .flags = 0U,
        .id = 0x123,
        .mask = CAN_STD_ID_MASK
};
int filter_id;
const struct device *const can_dev = DEVICE_DT_GET(DT_CHOSEN(zephyr_canbus));

filter_id = can_add_rx_filter(can_dev, rx_callback_function, callback_arg, &my_filter);
if (filter_id < 0) {
  LOG_ERR("Unable to add rx filter [%d]", filter_id);
}

下例用 can_add_rx_filter_msgq() 同步接收帧。用户空间也可调用此函数；消息队列容量应足以容纳预计积压的帧数。

本例过滤器精确匹配扩展标识符 0x1234567。

const struct can_filter my_filter = {
        .flags = CAN_FILTER_IDE,
        .id = 0x1234567,
        .mask = CAN_EXT_ID_MASK
};
CAN_MSGQ_DEFINE(my_can_msgq, 2);
struct can_frame rx_frame;
int filter_id;
const struct device *const can_dev = DEVICE_DT_GET(DT_CHOSEN(zephyr_canbus));

filter_id = can_add_rx_filter_msgq(can_dev, &my_can_msgq, &my_filter);
if (filter_id < 0) {
  LOG_ERR("Unable to add rx msgq [%d]", filter_id);
  return;
}

while (true) {
  k_msgq_get(&my_can_msgq, &rx_frame, K_FOREVER);
  ... do something with the frame ...
}

用 can_remove_rx_filter() 移除指定的过滤器。

can_remove_rx_filter(can_dev, filter_id);

设置位速率

运行时设置初始位速率与采样点。应用可用 can_set_timing() 修改，或用 can_calc_timing() 根据位速率和以千分数表示的采样点计算时序。下例设置为 250 kbit/s，采样点为 87.5%。

struct can_timing timing;
const struct device *const can_dev = DEVICE_DT_GET(DT_CHOSEN(zephyr_canbus));
int ret;

ret = can_calc_timing(can_dev, &timing, 250000, 875);
if (ret > 0) {
  LOG_INF("Sample-Point error: %d", ret);
}

if (ret < 0) {
  LOG_ERR("Failed to calc a valid timing");
  return;
}

ret = can_stop(can_dev);
if (ret != 0) {
  LOG_ERR("Failed to stop CAN controller");
}

ret = can_set_timing(can_dev, &timing);
if (ret != 0) {
  LOG_ERR("Failed to set timing");
}

ret = can_start(can_dev);
if (ret != 0) {
  LOG_ERR("Failed to start CAN controller");
}

支持 CAN FD 的控制器也有计算和设置数据相位时序的接口，见 can_set_timing_data()、can_calc_timing_data()。

SocketCAN

Zephyr 还提供 SocketCAN，即 Zephyr CAN API 的 BSD 套接字实现，可通过熟悉的 BSD Socket API 访问 CAN。它兼容 Linux SocketCAN，后者是许多高层 CAN 项目的基础。注意：帧经网络协议栈转发，而非直接递交，因此有一定计算和内存开销。
