CAN 命令行（CAN Shell）

概述

CAN 命令行为命令行（shell）模块提供 can 命令及一组子命令。无须专门编写应用，就能交互式探索和测试CAN 控制器（CAN Controller）驱动 API。也可在已有应用中启用，以交互方式排查 CAN 问题。

CAN 命令行可访问多数控制器功能，包括查看状态、配置、收发帧和总线恢复。

要使用 CAN 命令行，必须启用以下 Kconfig 选项：

  • CONFIG_SHELL

  • CONFIG_CAN

  • CONFIG_CAN_SHELL

以下 Kconfig 选项可为 can 命令启用额外的子命令和功能：

  • CONFIG_CAN_FD_MODE：启用 CAN FD 专用子命令，例如设置 CAN FD 数据相位时序。

  • CONFIG_CAN_RX_TIMESTAMP：打印收到的 CAN 帧的时间戳。

  • CONFIG_CAN_STATS：在 can show 子命令中打印控制器统计信息，还须同时启用 CONFIG_STATS。

  • CONFIG_CAN_MANUAL_RECOVERY_MODE：启用 can recover 子命令。

例如，为 FRDM-K64F 构建 Hello World 示例，同时启用 CAN 命令行和统计功能：

# From the root of the zephyr repository
west build -b frdm_k64f samples/hello_world -- -DCONFIG_SHELL=y -DCONFIG_CAN=y -DCONFIG_CAN_SHELL=y -DCONFIG_STATS=y -DCONFIG_CAN_STATS=y

关于如何连接和操作命令行，见命令行（shell）文档。除非禁用了 CONFIG_SHELL_HELP，否则可向 can 或其任意子命令传入 -h 或 --help 查看内置帮助。所有子命令的参数也支持 Tab 补全。

提示

所有 CAN 子命令的首个参数都是控制器名称，支持 Tab 补全。启用 CONFIG_DEVICE_SHELL 后，可通过 device list 列出可用设备。下例均使用设备名 can@0。

查看控制器状态

用 can show 可查看指定控制器的信息，包括核心 CAN 时钟频率、最大位速率、接收过滤器数量、能力、当前模式与状态、错误计数器和时序限制等：

uart:~$ can show can@0
core clock:      144000000 Hz
max bitrate:     5000000 bps
max std filters: 15
max ext filters: 15
capabilities:    normal loopback listen-only fd
mode:            normal
state:           stopped
rx errors:       0
tx errors:       0
timing:          sjw 1..128, prop_seg 0..0, phase_seg1 2..256, phase_seg2 2..128, prescaler 1..512
timing data:     sjw 1..16, prop_seg 0..0, phase_seg1 1..32, phase_seg2 1..16, prescaler 1..32
transceiver:     passive/none
statistics:
  bit errors:    0
    bit0 errors: 0
    bit1 errors: 0
  stuff errors:  0
  crc errors:    0
  form errors:   0
  ack errors:    0
  rx overruns:   0

说明

仅在启用 CONFIG_CAN_STATS 时打印统计信息。

配置

CAN 命令行可以设置控制器模式和时序，并启动或停止 CAN 帧的处理。

说明

只有控制器处于停止状态时才能修改模式和时序。上电初始就是停止状态，初始模式为 normal；初始时序由设备树（Devicetree）的 bitrate、sample-point、bitrate-data、sample-point-data 属性决定。

计时

可用 can bitrate 设置经典 CAN 位速率或 CAN FD 仲裁相位位速率。单位为 bit/s。

uart:~$ can bitrate can@0 125000
setting bitrate to 125000 bps

启用 CONFIG_CAN_FD_MODE 后，可用 can dbitrate 设置数据相位位速率。单位为 bit/s。

uart:~$ can dbitrate can@0 1000000
setting data bitrate to 1000000 bps

这两个子命令还支持两个可选位置参数：以千分数表示的采样点，以及以时间量子表示的（再）同步跳转宽度（SJW）。详细用法见交互式帮助。

也可以用 can timing、can dtiming 直接配置底层位时序，所需参数详见各子命令的交互式帮助。

模式

通过 can mode 设置控制器模式，下面演示如何启用环回模式。

uart:~$ can mode can@0 loopback
setting mode 0x00000001

可在同一行指定多个模式，例如 can mode can@0 fd loopback 同时启用 CAN FD 与环回。厂商专用模式可用十六进制值表示。

启动与停止

时序和模式配置完毕后，用 can start 启动控制器，启用 CAN 帧收发：

uart:~$ can start can@0
starting can@0

要重新配置时序或模式，须先用 can stop 停止控制器：

uart:~$ can stop can@0
stopping can@0

接收

要接收帧，须至少配置一个 CAN 接收过滤器。用 can filter add 添加，传入十六进制 CAN ID，还可给出十六进制掩码来指定哪些 ID 位必须匹配。可用参数详见子命令的交互帮助。

uart:~$ can filter add can@0 010
adding filter with standard (11-bit) CAN ID 0x010, CAN ID mask 0x7ff, data frames 1, RTR frames 0, CAN FD frames 0
filter ID: 0

移除过滤器时使用这里返回的过滤器 ID（上例为 0）。

命中已添加过滤器的帧会打印到命令行。例如：

# Dev Flags    ID   Size  Data bytes
can0  --       010   [8]  01 02 03 04 05 06 07 08
can0  B-       010  [08]  01 02 03 04 05 06 07 08
can0  BP       010  [03]  01 aa bb
can0  --  00000010   [0]
can0  --       010   [1]  20
can0  --       010   [8]  remote transmission request

各列含义如下：

  • 设备（Dev）

    • 接收该帧的设备名称。

  • 标志（Flags）

    • B：帧设置了 CAN FD 位速率切换（BRS）标志。

    • P：帧设置了 CAN FD 错误状态指示（ESI）标志；发送节点处于错误被动状态。

    • -：该标志未置位。

  • ID

    • 010：以十六进制表示的标准（11 位）CAN ID，此例为 10h。

    • 00000010：以十六进制表示的扩展（29 位）CAN ID，此例为 10h。

  • 大小（Size）

    • [8]：数据字节数（十进制）；此例为 8 数据字节的经典 CAN 帧。

    • [08]：数据字节数（十进制）；此例为 8 数据字节的 CAN FD 帧。

  • 数据字节

    • 01 02 03 04 05 06 07 08：以十六进制表示的数据字节，此例是 1 至 8。

    • remote transmission request：这是远程传输请求（RTR）帧，不携带数据字节。

提示

启用 CONFIG_CAN_RX_TIMESTAMP 时，每行前面会显示来自控制器自由运行计数器的时间戳。

已配置的接收过滤器可用 can filter remove 移除，使用 can filter add 返回的过滤器 ID（下例为 0）。

uart:~$ can filter remove can@0 0
removing filter with ID 0

也可以使用 can dump：它添加能匹配任意接收帧的标准（11 位）和扩展（29 位）过滤器，启动控制器，并将所有接收帧打印到命令行：

uart:~$ can dump can@0
dumping CAN RX frames on device can@0, press Ctrl+C to exit

按 Ctrl+C 退出 can dump 后，会自动移除刚添加的过滤器并再次停止控制器。

发送

用 can send 将待发送的帧加入发送队列。传入十六进制 CAN ID，也可附带若干十六进制数据字节。其他参数详见子命令的交互帮助。

uart:~$ can send can@0 010 1 2 3 4 5 6 7 8
enqueuing CAN frame #2 with standard (11-bit) CAN ID 0x010, RTR 0, CAN FD 0, BRS 0, DLC 8
CAN frame #2 successfully sent

总线恢复

可用 can recover 手动从总线关闭（bus-off）状态恢复：

uart:~$ can recover can@0
recovering, no timeout

可选参数是以毫秒计的恢复超时。未指定时会一直等待恢复成功。

说明

只有启用 CONFIG_CAN_MANUAL_RECOVERY_MODE 后才有 recover 子命令。
