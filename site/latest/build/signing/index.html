二进制文件签名（Signing Binaries）

非官方简体中文译本 · 英文基线 4.5.99 · D04（构建时自动签名） · 全站目录（94 篇） · D 批目录 · 本页英文原文

可以用 CMake 代码在构建时自动为二进制文件签名，也可以使用 west sign。本页介绍前者；后者见二进制文件签名（Signing Binaries）。

MCUboot / imgtool

Zephyr 构建系统专门支持使用 MCUboot 引导程序开发者提供的 imgtool 为镜像签名。设置相应的 Kconfig 选项后，即可一步完成应用的构建和签名，随后 west flash 将使用已签名的文件。

以下流程同时构建并烧写 MCUboot 和由它链式加载的 Hello World 应用。请在按入门指南（Getting Started Guide）创建的 zephyrproject 工作区中运行以下命令。

west build -b YOUR_BOARD zephyr/samples/hello_world --sysbuild -d build-hello-signed -- \
     -DSB_CONFIG_BOOTLOADER_MCUBOOT=y

west flash -d build-hello-signed

上述命令的几点说明：

  • 将 YOUR_BOARD 替换为自己的开发板目标。

  • 示例采用 MCUboot 提供的默认签名密钥。它不安全，仅供开发和测试使用。

  • 可将 hello_world 应用目录替换成 MCUboot 能够加载的其他应用，例如 SMP 服务端 示例。

以下是这些选项及相关配置项的说明：

  • SB_CONFIG_BOOTLOADER_MCUBOOT：按可由 MCUboot 加载的方式构建应用。

  • SB_CONFIG_BOOT_SIGNATURE_KEY_FILE：用于镜像签名的密钥文件，或逗号分隔的密钥文件列表。如果使用自己的密钥，请相应修改；用绝对路径或 ${APP_DIR} 等 CMake 变量指定文件的方式见签名密钥文件。传入列表时，MCUboot 会嵌入每把密钥的公钥，可接受由其中任意一把签名的镜像。第一项还用于给应用签名；第一项之后的每个条目都必须是仅含公钥的 PEM 文件，且对 imgtool 而言签名类型须相同。

  • CONFIG_MCUBOOT_EXTRA_IMGTOOL_ARGS：传给 imgtool 的可选额外命令行参数。

  • CONFIG_MCUBOOT_GENERATE_CONFIRMED_IMAGE：额外生成已确认（confirmed）的镜像。与默认可用于 OTA 的镜像相比，已确认镜像可能更适合生产烧写。

  • 在 Windows 上若遇到“Access denied”，建议运行 pip3 install imgtool，然后在干净的构建目录中重试。

如需了解多密钥引导程序在 QEMU 中进行端到端验证的完整示例，见 tests/boot/mcuboot_multiple_keys 测试。

如果 west flash 的执行后端（runner）使用 imgtool 支持的镜像格式，执行 west flash -d build-hello-signed 时应能在设备的串口控制台看到类似输出：

west flash 是否支持这一流程取决于所选后端。nrfjprog 与 pyocd 都支持上述流程。要让其他后端支持它，可以提交补丁或提出功能请求。

签名密钥文件

使用 sysbuild 构建时，SB_CONFIG_BOOT_SIGNATURE_KEY_FILE 指定签名密钥。它的值会传给两个镜像：

  • 在应用镜像侧成为 CONFIG_MCUBOOT_SIGNATURE_KEY_FILE，由 imgtool 用来给应用签名；

  • 在 MCUboot 镜像侧成为 CONFIG_BOOT_SIGNATURE_KEY_FILE，其公钥部分会编入引导程序，用来验证该签名。

警告

默认值指向 MCUboot 随附的不安全开发密钥（如 root-ec-p256.pem）。这些密钥随每份 Zephyr 和 MCUboot 源码分发，任何人都能取得，因此只适合开发和测试。其他场景须生成自己的密钥，切勿把私钥放在不受自己控制的仓库或构建目录中。

sysbuild 如何解析密钥文件路径

SB_CONFIG_BOOT_SIGNATURE_KEY_FILE 的值先经 CMake 的 string(CONFIGURE) 处理，其中的 ${VARIABLE} 引用会作为 CMake 变量展开。展开后，绝对路径直接使用；相对路径则由两个镜像各自解析：

镜像

相对路径的查找顺序

应用（CONFIG_MCUBOOT_SIGNATURE_KEY_FILE）

先查 APPLICATION_CONFIG_DIR，再查 west 工作区顶层目录（WEST_TOPDIR）

MCUboot（CONFIG_BOOT_SIGNATURE_KEY_FILE）

先查 APPLICATION_CONFIG_DIR，再查 MCUboot 模块目录

警告

两个镜像解析相对路径的基准不同，单写相对路径会指向不同文件，通常导致构建失败。不要这样写；应使用绝对路径，或用 CMake 变量指定明确的起点。

推荐以 ${APP_DIR}（主应用的源码目录）为起点。这样密钥可存放在自己的应用中，且两个镜像解析到同一文件。也可使用在展开时可用的其他 CMake 变量：

# sysbuild.conf
SB_CONFIG_BOOT_SIGNATURE_KEY_FILE="${APP_DIR}/keys/my-signing-key.pem"

可选的加密密钥文件（CONFIG_MCUBOOT_ENCRYPTION_KEY_FILE）同样遵循上述路径解析规则。

使用外部脚本扩展签名流程

可以扩展或替换 west flash 流程中使用的签名脚本，以调整功能或引入其他签名机制。默认启用 MCUboot 时，Zephyr 通过 cmake/mcuboot.cmake 添加构建后命令，生成签名镜像。可在 sysbuild 作用域（如使用 sysbuild）或 Zephyr／Zephyr 模块作用域中替换脚本。优先级依次为：

  • 系统构建（Sysbuild）

  • Zephyr 属性

  • 默认 MCUboot 脚本（如已启用）

在 sysbuild 中，-D<target>_SIGNING_SCRIPT 可为特定镜像指定脚本，-DSIGNING_SCRIPT 则为全部镜像指定脚本。例如：

west build -b <board> <application> -DSIGNING_SCRIPT=<file>

要使用 Zephyr 属性方式，应修改 zephyr_property_target 的 SIGNING_SCRIPT 属性，最好由模块按如下方式设置：

if(CONFIG_BOOTLOADER_MCUBOOT)
  set_target_properties(zephyr_property_target PROPERTIES SIGNING_SCRIPT ${CMAKE_CURRENT_LIST_DIR}/custom_signing.cmake)
endif()

此后，启用 MCUboot 签名的工程在构建时会包含自定义 CMake 文件，而非 Zephyr 默认文件。要开发新的签名系统或扩展默认行为，可以参考 Zephyr 自带的 MCUboot 签名文件。
