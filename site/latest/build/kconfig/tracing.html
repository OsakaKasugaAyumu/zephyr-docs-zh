追溯配置值的来源

非官方简体中文译本 · 英文基线 4.5.99 · C11 · 全站目录（94 篇） · C 批目录 · 本页英文原文

保存在 zephyr/.config 中的合并配置，是把用户配置应用到整棵 Kconfig 定义树后的结果。有些值很难追踪，尤其是定义树中其他位置隐式选中了不可见符号时。可使用 traceconfig 目标，在构建目录生成报告，逐个说明各符号为何取得最终值。

照常构建 Zephyr 项目后，运行下面任一命令即可生成 Kconfig 追踪报告：

west build -t traceconfig

ninja traceconfig

说明

只有从干净构建开始，报告才有参考价值；否则已有的 .config 会把各项设置固定在先前的值上（见配置值被固定的符号）。因此建议生成报告前先进行干净构建（pristine build）。

输出位于构建目录的 zephyr/kconfig-trace.md。最好在支持 Markdown 的 IDE 中查看，以便使用表格、高亮和可点击链接；普通文本编辑器也可以阅读。

报告分为三个部分：

  1. 可见符号

  2. 不可见符号

  3. 未设置的符号

前两部分以表格列出符号的类型、名称和当前值。第四列指出哪种语句使该值生效，可取以下值：

  • assigned（显式赋值）：从配置文件中读到了形如 CONFIG_xxx=y 的显式赋值；

  • default（默认值）：用户没有赋值，但在 Kconfig 定义树中读到了适用的默认值；

  • selected（被选中） 或 implied（隐式建议）：另一个符号的 select 或 imply 语句使本符号取得该值。

第五列追溯源语句。对前两类来源，给出确切的文件名和行号；对后两类，则列出使符号取得该值的表达式。

第三部分只列出所有未获得值的符号。由于以上各条途径均未为它们赋值，因此没有更多来源信息。
