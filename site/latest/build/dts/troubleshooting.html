设备树故障排查

非官方简体中文译本 · 英文基线 4.5.99 · C06 · 全站目录（79 篇） · C 批目录 · 本页英文原文

以下步骤用来排查与设备树有关的代码问题。

其他操作指南见设备树操作指南。

从干净的构建目录重试

重要

遇到问题，先尝试这一步，再做其他检查。

示例见干净构建（pristine build）。也可以完全删除构建目录后重试。

这条通用建议对设备树尤其重要：输出文件是在 CMake 配置阶段生成的，输入文件更改后不一定会自动重新生成。

使用设备树诊断工具（DT Doctor）

可选的设备树诊断工具可以协助定位问题。向 west build 传入 -DZEPHYR_SCA_VARIANT=dtdoctor 即可启用。

详见设备树诊断工具（dtdoctor）。

确认已包含 <devicetree.h>

与 Kconfig 符号不同，使用设备树 API 必须显式包含 devicetree.h。

许多 Zephyr 头文件依赖设备树，因此其他 API 的头文件有时会间接包含 devicetree.h，但不能依赖这种行为。

对 __device_dts_ord_<N> 的未定义引用

此错误通常出现在类似下面的代码行：

const struct device *dev = DEVICE_DT_GET(NODE_ID);

其中 NODE_ID 是有效的节点标识符，但没有驱动为该节点分配 struct device。因为试图获取未定义设备的指针，链接器就会报错。

要修复此问题，请确认以下两点：

  1. 节点已启用，即设有 status = "okay";。

    （没有 status 属性等价于 status = "okay";。关于 status 的说明，见重要属性。）

  2. 负责分配 struct device 的设备驱动已经启用，也就是说，使构建系统将驱动源文件编入应用的 Kconfig 选项必须为 y。

    （Kconfig 选项的设置方法见设置 Kconfig 配置值。）

下文用 <build> 表示构建目录。

确认节点已启用:

从链接错误中取出编号 <N>，再到 <build>/zephyr/include/generated/zephyr/devicetree_generated.h 开头的节点列表中查找。例如，若 <N> 为 15，且 devicetree_generated.h 内容如下，对应的节点就是 /soc/i2c@deadbeef：

/*
 * Generated by gen_defines.py
 *
 * DTS input file:
 *   zephyr.dts.pre
 *
 * Directories with bindings:
 *   $ZEPHYR_BASE/dts/bindings
 *
 * Node dependency ordering (ordinal and path):
 *   0   /
 *   1   /aliases
[...]
 *   15  /soc/i2c@deadbeef
[...]

接着在 <build>/zephyr/zephyr.dts 中查找该节点，这是本次构建使用的最终设备树。（说明和示例见查看最终设备树和生成的头文件。）

若在 zephyr.dts 中看到该节点为 status = "disabled";，则需将其设为 status = "okay"; 来启用，通常通过覆盖文件（overlay）完成。例如，若 zephyr.dts 如下：

i2c0: i2c@deadbeef {
        status = "disabled";
};

在覆盖文件中加入如下内容，然后从干净的构建目录重试：

&i2c0 {
        status = "okay";
};

重新构建后，确认 zephyr.dts 中出现了 status = "okay";。

确认设备驱动已启用:

先确定哪个驱动负责此节点并为它分配设备。根据节点的 compatible 属性，查找为该 compatible 值创建 struct device 实例的驱动。

若不熟悉基于 compatible 分配设备的过程，可从 ZDS 2021 的演讲《深入了解 Zephyr 2.5 的设备模型》和设备驱动模型文档入手。compatible 的更多说明见重要属性及设备树规范。

目前没有文档完整列出每个驱动与 compatible 的对应关系；需要阅读源码确认：

  • 在 drivers 下面，找到对应设备 API 的子目录。

  • 查看其中的相关文件，直到辨明是哪个驱动，或确定没有现成驱动。

通常可以查找设置了 DT_DRV_COMPAT 的文件：其值应等于节点的 compatible 转为小写、特殊字符变成下划线的结果。例如，若 compatible 为 vnd,foo-device，查找包含下面这行的文件：

#define DT_DRV_COMPAT vnd_foo_device

重要

这种方法并不总是有效，因为不是所有驱动都使用 DT_DRV_COMPAT。

找到驱动后，还要确认控制其编译的 Kconfig 选项已启用。如果没有驱动，且确认 compatible 无误，就需要编写驱动；具体方法不在本页范围内。

接上例，假设你的节点现在是这样：

i2c0: i2c@deadbeef {
        compatible = "nordic,nrf-twim";
        status = "okay";
};

在 drivers/i2c 中查找处理 nordic,nrf-twim 的驱动文件，本例为 drivers/i2c/i2c_nrfx_twim.c。即使驱动没有设置 DT_DRV_COMPAT，其文件名等信息也可作为线索。

找到要启用的驱动后，必须确认其 Kconfig 选项为 y。请在驱动子目录的 CMakeLists.txt 中查找类似下面的一行。接上例，drivers/i2c/CMakeLists.txt 中有：

zephyr_library_sources_ifdef(CONFIG_NRFX_TWIM       i2c_nrfx_twim.c)

这意味着 <build>/zephyr/.config 中的 CONFIG_NRFX_TWIM 必须设为 y。

若驱动的 Kconfig 值不是 y，需查明如何使它生效。通常启用设备树节点就会自动启用驱动；有时还需在应用的 prj.conf 中添加下面一行，然后从干净的构建目录重试：

CONFIG_FOO=y

其中 CONFIG_FOO 是 CMakeLists.txt 据以决定是否编译驱动的选项。

也可能存在未满足的 Kconfig 依赖，需要先启用这些依赖，才能启用驱动。

请查阅定义 CONFIG_FOO 的 Kconfig 文件，将 FOO 替换为自己驱动对应的名称。

确认名称拼写正确

请区分下面两种写法：

  • 在 C/C++ 中，设备树名称必须用小写，特殊字符需改为下划线。Zephyr 生成头文件时会按此规则把 DTS 名称转换为 C 记号，供基于预处理器的 <devicetree.h> API 使用。

  • 在覆盖文件中，应沿用 DTS 的节点名和属性名，不做上述转换。Zephyr 的覆盖文件本质上就是 DTS 片段。

例如，要在 C/C++ 中读取路径 /soc/i2c@12340000 对应节点的 clock-frequency 属性：

/*
 * foo.c: lowercase-and-underscores names
 */

/* Don't do this: */
#define MY_CLOCK_FREQ DT_PROP(DT_PATH(soc, i2c@1234000), clock-frequency)
/*                                           ^               ^
 *                                        @ should be _     - should be _  */

/* Do this instead: */
#define MY_CLOCK_FREQ DT_PROP(DT_PATH(soc, i2c_1234000), clock_frequency)
/*                                           ^               ^           */

如果在设备树覆盖文件中设置同一个属性，则写成：

/*
 * foo.overlay: DTS names with special characters, etc.
 */

/* Don't do this; you'll get devicetree errors. */
&{/soc/i2c_12340000/} {
     clock_frequency = <115200>;
};

/* Do this instead. Overlays are just DTS fragments. */
&{/soc/i2c@12340000/} {
     clock-frequency = <115200>;
};

查看预处理器输出

要保存预处理器输出，启用 CONFIG_COMPILER_SAVE_TEMPS。例如，用 west 构建 Hello World 并开启该选项：

west build -b BOARD samples/hello_world -- -DCONFIG_COMPILER_SAVE_TEMPS=y

构建目录中会为每个源文件 foo.c 生成名为 foo.c.i 的预处理输出文件。

在构建目录下找到该文件，即可查看设备树宏的展开结果。例如，在 macOS 或 Linux 上用 find 查找 main.c.i：

$ find build -name main.c.i
build/CMakeFiles/app.dir/src/main.c.i

打开前，先用格式化工具整理文件会更易读。例如，用 clang-format 就地格式化：

clang-format -i build/CMakeFiles/app.dir/src/main.c.i

之后即可在编辑器中查看预处理后的 C 代码。

关闭宏展开跟踪

设备树错误的编译信息有时很长，往往是因为一个宏经过多次中间展开，编译器为每一步都打印了消息。

禁用 CONFIG_COMPILER_TRACK_MACRO_EXPANSION 可关闭这种跟踪，通常每个错误就只打印一条消息。

例如，用 west 构建 Hello World 并关闭此选项：

west build -b BOARD samples/hello_world -- -DCONFIG_COMPILER_TRACK_MACRO_EXPANSION=n

验证属性

读取节点属性时若出现编译错误，应检查节点标识符和属性。例如，以下代码在构建时报错：

int baud_rate = DT_PROP(DT_NODELABEL(my_serial), current_speed);

可将下面的代码加入文件，再次编译以验证节点：

#if !DT_NODE_EXISTS(DT_NODELABEL(my_serial))
#error "whoops"
#endif

若重新构建时出现“whoops”，该标识符没有指向有效节点。请查看最终设备树和生成的头文件，从生成的文件开始排查。

若未出现“whoops”，接着检查以下几项：

  • 是否已确认名称拼写正确？

  • 该属性存在吗？

  • 节点是否有匹配的绑定？

  • 绑定是否定义了这个属性？

检查是否缺少绑定

绑定的用法见设备树绑定（bindings）；Zephyr 内置绑定见绑定索引。

如果构建时无法为节点查找设备树绑定，原因可能是没有设置 compatible，或者没有匹配该值的绑定。若已设置，检查名称拼写。在设备树源文件中，compatible 应类似 "vnd,some-device"；参见确认名称拼写正确。

若绑定文件不在 zephyr/dts 下，可能需要设置 DTS_ROOT。详见绑定的存放位置。

DT_INST_() API 相关错误

使用 DT_INST_PROP() 等 API 时，必须将 DT_DRV_COMPAT 定义为所需 compatible 的小写加下划线形式。参见方式一：使用实例编号创建设备。
