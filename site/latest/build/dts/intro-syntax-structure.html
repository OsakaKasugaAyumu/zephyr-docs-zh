语法与结构

非官方简体中文译本 · 英文基线 4.5.99 · C03 · 全站目录（94 篇） · C 批目录 · 本页英文原文

顾名思义，设备树是一棵树。它的人类可读文本格式称为设备树源文件格式（DTS，devicetree source），由设备树规范（Devicetree Specification）定义。

本页以比规范更循序渐进的方式介绍设备树。遇到具体细节时，仍可能需要查阅规范。

示例

下面是一个 DTS 文件示例：

/dts-v1/;

/ {
        a-node {
                subnode_nodelabel: a-sub-node {
                        foo = <3>;
                };
        };
};

/dts-v1/; 表示本文件采用 DTS 语法第 1 版，早期的第 0 版现已废弃。

节点

与其他树形数据结构一样，设备树由按层级排列的节点（nodes）组成。上例有三个节点：

  1. 根节点：/

  2. 名为 a-node 的节点，是根节点的子节点；

  3. 名为 a-sub-node 的节点，是 a-node 的子节点。

节点可以有节点标签（node labels）：它们是指向该节点的唯一简写。在上例中，a-sub-node 的节点标签为 subnode_nodelabel。节点可以没有标签，也可以有一个或多个；在设备树其他位置可通过标签引用它。

设备树通过路径（paths）标识节点的位置。与 Unix 文件路径类似，各部分用斜杠（/）分隔。根节点路径只有一个斜杠：/。其他节点的路径由各级祖先和节点自身的名字依次拼接而成。例如，a-sub-node 的完整路径是 /a-node/a-sub-node。

属性

设备树节点还可具有属性（properties），它们是名称和值的组合。值可以是任意字节序列，有时是一组单元（cells），每个单元是一个 32 位无符号整数。

节点 a-sub-node 有一个名为 foo 的属性，值为一个数值等于 3 的单元。在 DTS 中，foo 的值由尖括号（< 和 >）括起，据此可知其大小和类型。

更多属性值的例子见下文编写属性值。

设备树如何反映硬件结构

实际使用中，节点通常对应硬件，节点层级反映硬件的物理连接。例如，下面这块开发板有三个 I2C 外设，连接到 SoC 中的同一个 I2C 总线控制器：

设备树为 I2C 总线控制器和每个外设分别设置节点。为了反映硬件连接，三个外设都是总线控制器的子节点。表示其他硬件时也有类似的约定。

对应的 DTS 大致如下：

/dts-v1/;

/ {
        soc {
                i2c-bus-controller {
                        i2c-peripheral-1 {
                        };
                        i2c-peripheral-2 {
                        };
                        i2c-peripheral-3 {
                        };
                };
        };
};

实际硬件中的属性

属性通常用于描述或配置节点所代表的硬件。例如，I2C 外设节点有一个属性，其值为该设备在总线上的地址。

下图仍是同一个例子，但换成了开发 I2C 设备时可能遇到的实际节点名和属性。

对应的 DTS 如下：

/dts-v1/;

/ {
        soc {
                i2c@40003000 {
                        compatible = "nordic,nrf-twim";
                        reg = <0x40003000 0x1000>;

                        apds9960@39 {
                                compatible = "avago,apds9960";
                                reg = <0x39>;
                        };
                        ti_hdc@43 {
                                compatible = "ti,hdc", "ti,hdc1010";
                                reg = <0x43>;
                        };
                        mma8652fc@1d {
                                compatible = "nxp,fxos8700", "nxp,mma8652fc";
                                reg = <0x1d>;
                        };
                };
        };
};

单元地址（unit address）

除实际名称和属性外，此例还引入了单元地址（unit address），即节点名中 @ 后面的部分。例如，i2c@40003000 中的 40003000 和 apds9960@39 中的 39 都是单元地址。它不是必需的：soc 节点就没有单元地址。

单元地址给出节点在父节点地址空间中的地址。不同硬件对它的解释如下。

内存映射外设

外设寄存器映射的基地址。例如，i2c@40003000 表示寄存器基地址为 0x40003000 的 I2C 控制器。

I2C 外设

外设在 I2C 总线上的地址。例如，上一节中 I2C 控制器的子节点 apds9960@39 的地址为 0x39。

SPI 外设

外设片选线的编号；没有片选线时用 0。

内存

物理起始地址。例如，memory@2000000 表示从物理地址 0x2000000 开始的 RAM。

内存映射闪存

与 RAM 一样，使用物理起始地址。例如，flash@8000000 表示物理起始地址为 0x8000000 的闪存设备。

固定闪存分区

当设备树用于保存闪存分区表时，单元地址是分区起点相对于闪存起点的偏移量。例如：

flash@8000000 {
    /* ... */
    partitions {
            partition@0 { /* ... */ };
            partition@20000 {  /* ... */ };
            /* ... */
    };
};

partition@0 的偏移量为 0，因此基地址为 0x8000000；同理，partition@20000 的基地址为 0x8020000。

重要属性

设备树规范定义了多种标准属性。以下几项尤为重要：

compatible

节点所代表的硬件设备名称。

建议使用 "vendor,device" 格式，如 "avago,apds9960"，也可以列出多个值，如 "ti,hdc", "ti,hdc1010"。其中 vendor 是厂商简称，dts/bindings/vendor-prefixes.txt 列出了通用的 vendor 名称；device 通常取自数据手册。

对于具有通用行为的硬件，也可使用 gpio-keys、mmio-sram 或 fixed-clock 之类的值。

构建系统根据 compatible 为节点查找适用的绑定（bindings）。设备驱动通过 devicetree.h 找到具有相应 compatible 值的节点，从而确定可以管理哪些硬件。

compatible 可有多个值。如果设备是某个通用系列的具体型号，可以依次列出由具体到通用的值，让系统按此顺序匹配驱动。

在 Zephyr 的绑定语法中，此属性的类型为 string-array。

reg

用于寻址设备的信息。其含义因设备而异，具体取决于 compatible 属性。

reg 是一系列 (address, length) 对；每一对称为一个寄存器块（register block）。通常用十六进制书写。

常见用法如下：

  • 对于通过内存映射 I/O 寄存器访问的设备（如 i2c@40003000），address 通常是寄存器区的基地址，length 是寄存器占用的字节数。

  • 对于 I2C 设备（如 apds9960@39 及其兄弟节点），address 是 I2C 总线上的从设备地址，没有 length 值。

  • 对于 SPI 设备，address 是片选线编号，没有 length。

reg 与上文的单元地址相似并非巧合：相比单元地址，reg 更详细地描述了设备内部可寻址的资源。

status

一个字符串，用来表示节点是否启用。

规范允许五种取值："okay"、"disabled"、"reserved"、"fail" 和 "fail-sss"。Zephyr 将除 "okay" 以外的已设值一律视为禁用。"reserved" 表示节点存在，但由别处启用（例如多域应用中的另一个核或域）；edtlib 将它视同 "disabled"。Zephyr 目前不使用其余两个值（"fail" 和 "fail-sss"）。

当 status 为 "okay" 或根本未定义（源文件中没有此属性）时，节点视为启用。设为 "disabled" 则显式禁用。对于物理设备，只有启用节点，Zephyr 驱动模型才会分配并初始化对应的 struct device。

禁用父节点并不会自动禁用子节点；如需禁用子节点，必须单独显式设置。

interrupts

描述设备产生的中断，编码为含一个或多个中断说明符（interrupt specifiers）的数组。每个说明符由若干单元组成。详见设备树规范 v0.3第 2.4 节“中断与中断映射”。

Zephyr 的设备树绑定语言允许为中断说明符的每个单元命名。

说明

早期 Zephyr 经常使用 label 属性。它与标准的节点标签（node label）不是一回事。不建议在新绑定中再使用 label property，也不建议在新代码中使用 DT_LABEL 宏。部分现有绑定和覆盖文件因历史原因保留了 label 属性；编写新绑定或实现新设备时不应沿用。

编写属性值

本节说明如何以 DTS 格式编写属性值。下表中各类型的详细定义见设备树绑定（bindings）。

为便于入门，这里省略了部分细节；需要了解完整规则时，请查阅设备树规范。

属性类型

写法

示例

string

用双引号括起

a-string = "hello, world!";

int

用尖括号（< 和 >）括起

an-int = <1>;

boolean

表示 true 时只写属性名，不赋值；要表示 false，使用 /delete-property/。

my-true-boolean;

array

用尖括号（< 和 >）括起，各项以空格分隔

foo = <0xdeadbeef 1234 0>;

uint8-array

写成十六进制，不加前缀 0x，并用方括号（[ 和 ]）括起。

a-byte-array = [00 01 ab];

string-array

用逗号分隔

a-string-array = "string one", "string two", "string three";

phandle

用尖括号（< 和 >）括起

a-phandle = <&mynode>;

phandles

用尖括号（< 和 >）括起，各项以空格分隔

some-phandles = <&mynode0 &mynode1 &mynode2>;

phandle-array

用尖括号（< 和 >）括起，各项以空格分隔

a-phandle-array = <&mynode0 1 2>, <&mynode1 3 4>;

补充说明：

  • 关于 phandle、phandles 和 phandle-array 的值，详见节点引用（phandle）。

  • 布尔属性存在即为真，不应赋值。只有当 DTS 中完全不存在该属性时，其值才为假。

  • 上例的 foo 属性有三个单元（cells），依次为 0xdeadbeef、1234 和 0。十六进制和十进制可混用。Zephyr 会将 DTS 转为 C 源码，这里无需指定单个单元的字节序。

  • 64 位整数写成两个按大端顺序排列的 32 位单元。例如 0xaaaa0000bbbb1111 应写成 <0xaaaa0000 0xbbbb1111>。

  • a-byte-array 包含三个字节，依次为 0x00、0x01 和 0xab。

  • 可以使用括号、算术和位运算符。下面的 bar 属性只含一个值为 64 的单元：

    bar = <(2 * (1 << 5))>;

    注意：整个表达式都要放在括号内。

  • 如果括号表达式结果为负（例如 <(-1)> 或 <(4 - 6)>），对于 int 和 array 类型的属性，该单元保留为有符号值。正的十进制或十六进制字面量（包括 0xffffffff），以及结果非负的表达式，仍按无符号值处理。

  • 属性值可通过phandles引用其他节点。写法为 &foo，其中 foo 是一个节点标签（node label）。例如：

    foo: device@0 { };
device@1 {
        sibling = <&foo 1 2>;
};

    节点 device@1 的 sibling 属性依次包含三个单元：

    1. device@0 节点的 phandle，这里写作 &foo，因为 device@0 的节点标签为 foo；

    2. 数值 1；

    3. 数值 2。

    在设备树中，phandle 占一个单元，即一个 32 位无符号整数；不过，Zephyr 设备树 API 一般将其呈现为节点标识符。详见从 C/C++ 访问设备树。

  • 数组及类似类型的值可拆成多个 <> 块，如下所示：

    foo = <1 2>, <3 4>;                         // Okay for 'type: array'
foo = <&label1 &label2>, <&label3 &label4>; // Okay for 'type: phandles'
foo = <&label1 1 2>, <&label2 3 4>;         // Okay for 'type: phandle-array'

    如果子值在逻辑上可以分组，建议使用这种写法以便阅读。

别名（aliases）与选定节点（chosen nodes）

除节点标签（node labels）外，还可用别名或选定节点指向特定节点，而无需写出完整路径。

以下设备树同时使用了两种方式：

/dts-v1/;

/ {
     chosen {
             zephyr,console = &uart0;
     };

     aliases {
             my-uart = &uart0;
     };

     soc {
             uart0: serial@12340000 {
                     ...
             };
     };
};

/aliases 和 /chosen 不代表实际硬件，它们用来指向树中的其他节点。

上例中，my-uart 是路径为 /soc/serial@12340000 的节点的别名。同一节点也通过标签 uart0 被选作 zephyr,console 的值。

Zephyr 示例有时通过别名约定硬件角色，使应用无须写死某个设备。例如，Blinky：LED 闪烁 通过 led0 别名指明要闪烁的 LED。

/chosen 节点的属性用于指定系统或整个子系统使用的值。详见选定节点（chosen nodes）。
