输入与输出文件

非官方简体中文译本 · 英文基线 4.5.99 · C04 · 全站目录（79 篇） · C 批目录 · 本页英文原文

本节详细说明适用范围与用途示意图中各个输入与输出文件的用途。

输入文件

设备树有四类输入文件：

  • 源文件（.dts）

  • 包含文件（.dtsi）

  • 覆盖文件（.overlay）

  • 绑定文件（.yaml）

zephyr 目录中的设备树文件组织如下：

boards/<ARCH>/<BOARD>/<BOARD>.dts
dts/common/skeleton.dtsi
dts/<ARCH>/.../<SOC>.dtsi
dts/bindings/.../binding.yaml

一般而言，每块受支持的开发板都有一个描述硬件的 BOARD.dts。例如，reel_board 的对应文件为 boards/phytec/reel_board/reel_board.dts。

BOARD.dts 引入一个或多个 .dtsi 文件。这些 .dtsi 文件描述 Zephyr 运行的 CPU 或 SoC，也可能进一步引入其他 .dtsi 文件，或描述多块开发板共用的硬件。除共用部分外，BOARD.dts 还描述本板独有的硬件。

dts/common 目录下的 skeleton.dtsi 是定义完整设备树所需的最小包含文件。各体系结构目录（dts/<ARCH>）中的 CPU 或 SoC 描述（.dtsi）在 skeleton.dtsi 基础上扩展。

C 预处理器会处理所有设备树文件，展开宏引用。尽管 DTS 有 /include/ "<filename>" 语法，实际包含文件一般使用 #include <filename> 指令。

可用覆盖文件（overlays）扩展或修改 BOARD.dts。覆盖文件也是 DTS 文件，.overlay 扩展名只是为了标明用途。它们可针对不同用途调整基础设备树：

  • 例如，应用可以通过覆盖文件启用默认禁用的外设，或为特定用途选择板上的传感器。结合配置系统（Kconfig），可以不改源码就重新配置内核和设备驱动。

  • 定义Shields时也会使用覆盖文件。

构建系统会自动采用特定位置的 .overlay 文件，也可以通过 CMake 变量 DTC_OVERLAY_FILE 显式列出要包含的文件。详见设置设备树覆盖文件。

构建系统先放 BOARD.dts，再按顺序拼接各 .overlay 文件。DTS 允许合并同一节点的多处定义，因此最后的 .overlay 可以覆盖 BOARD.dts。示例见示例：FRDM-K64F 与 Hexiwear K64（该例使用 .dtsi 文件，但原理相同）。

设备树绑定（bindings）采用 YAML 格式，起衔接作用：它们解释设备树源文件、包含文件和覆盖文件的内容，使构建系统能够生成驱动和应用可用的 C 宏。绑定存放于 dts/bindings 目录。

脚本与工具

下面位于 scripts/dts/ 的库和脚本根据输入生成输出文件。其源码中附有详细文档。

dtlib.py

底层 DTS 解析库。

edtlib.py

构建在 dtlib 上的库。它通过 dtlib 解析 DTS，再结合绑定解释属性，从而提供更高层次的设备树表示。

gen_defines.py

通过 edtlib 从设备树和绑定生成 C 预处理器宏。

此外，如果系统安装了标准设备树编译器 dtc，构建系统会对最终设备树运行它，仅用来发现错误或警告，不使用其输出。某些开发板需要向 dtc 传递额外选项，例如抑制警告；可在开发板目录下的 pre_dt_board.cmake 中设置，如下：

list(APPEND EXTRA_DTC_FLAGS "-Wno-simple_bus_reg")

扩展板目录可提供 pre_dt_shield.cmake，作用与上述 pre_dt_board.cmake 相同。

输出文件

这些文件生成在应用的构建目录中。

警告

不要直接包含生成的头文件。正确用法见从 C/C++ 访问设备树。

<build>/zephyr/zephyr.dts.pre

预处理后的 DTS 源文件。这是中间产物，作为 gen_defines.py 的输入，用来生成 zephyr.dts 和 devicetree_generated.h。

<build>/zephyr/include/generated/zephyr/devicetree_generated.h

包含生成的宏及说明设备树的注释。由 devicetree.h 包含。

<build>/zephyr/zephyr.dts

合并后的最终设备树，由 gen_defines.py 输出。遇到问题时可以查阅。若已安装设备树编译器 dtc，也会对该文件再运行一次以发现其他警告或错误。
