设备树与 Kconfig 的分工

非官方简体中文译本 · 英文基线 4.5.99 · C07 · 全站目录（79 篇） · C 批目录 · 本页英文原文

除了设备树，Zephyr 也使用 Kconfig 配置源代码。面对具体问题时，两者的边界有时不直观。本节说明如何选择。

简而言之：

  • 用设备树描述硬件及其启动时配置，例如板上有哪些外设、启动时使用的时钟频率、中断线等。

  • 用 Kconfig 选择要编入最终镜像的软件支持，例如是否提供网络功能、应用需要哪些驱动等。

换句话说，设备树主要描述硬件，Kconfig 主要配置软件。

例如，一块开发板的 SoC 带有两个 UART（串口）实例。

  • 设备树通过两个 UART 节点描述这些硬件，用 compatible 属性指明 UART 的类型，用 reg 属性给出外设寄存器在内存中的地址范围等信息。

  • UART 的启动时配置也由设备树描述，例如接收中断（RX IRQ）的优先级和串口波特率。这些值在运行时可能可以修改，但启动时采用的值在设备树中指定。

  • 对应用代码而言，两个 UART 可以互换；具体使用哪个只取决于板级设计。这完全属于硬件配置，应在设备树中处理。

  • 是否将 UART 的软件支持编入固件则由 Kconfig 控制。即使设备树仍列有 UART 节点，不使用串口的应用也可以通过 Kconfig 将驱动源码排除在构建之外。

再看一台带 2.4 GHz 多协议无线电的设备：同一硬件既支持低功耗蓝牙，也支持 802.15.4。

  • 设备树应描述这套无线电硬件的存在、与哪些驱动兼容等信息。

  • 无线电的启动时配置也应由设备树指定，例如以 dBm 为单位的发射功率。

  • 应用采用哪种协议，运行的代码就不同，但使用的是同一套硬件。这属于软件配置。

  • 由 Kconfig 决定为无线电编译哪些软件功能，例如选择 BLE 协议栈还是 802.15.4 协议栈。

另一个例子：以往用于启用驱动特定实例的 Kconfig 选项已被移除。驱动本身仍由 Kconfig 启用，各硬件实例则通过对应设备树节点的 status 分别选择。

这些规则也有例外：

  • Kconfig 不便分别控制各实例的某些驱动参数（如内部缓冲区大小），这类参数可定义在设备树中。为表明它们专属于 Zephyr 驱动，而非硬件描述或配置，应为属性加上 zephyr, 前缀。例如以太网通用设备树属性中的 zephyr,random-mac-address。

  • 设备树的 chosen 用于指定承担某一用途的硬件实例，例如选择某个 UART 作为系统控制台。

从设备树自动生成的 Kconfig 符号

处理设备树时，CMake 运行 scripts/dts/gen_driver_kconfig_dts.py，扫描所有DTS 根目录目录（包括 dts/bindings），并将 Kconfig.dts 写入本次构建的 KCONFIG_BINARY_DIR（例如 <build>/zephyr，使用系统构建（Sysbuild）时则为 <build>/<image>/zephyr）。对绑定中出现的每个 compatible = "vendor,chip"，生成的文件都包含以下内容：

DT_COMPAT_VENDOR_CHIP := vendor,chip

config DT_HAS_VENDOR_CHIP_ENABLED
        def_bool $(dt_compat_enabled,$(DT_COMPAT_VENDOR_CHIP))

这条赋值保留了 compatible 的原始字符串，供自定义 Kconfig 预处理函数所述的函数使用，因此 Kconfig 文件可以调用 $(dt_compat_on_bus,$(DT_COMPAT_<compatible>),i2c) 等辅助函数。创建符号名时，-、, 和 @ 等字符会变成下划线。

Kconfig 运行后，该隐藏的布尔符号对应 CONFIG_DT_HAS_<compatible>_ENABLED。其值表示当前设备树中是否至少有一个节点具有指定的 compatible 且 status 为 okay。控制驱动启用的符号几乎都应使用 default y，并声明 depends on CONFIG_DT_HAS_<compatible>_ENABLED。例如：

config SENSOR_VENDOR_CHIP
        bool "Vendor Chip sensor"
        default y
        depends on DT_HAS_VENDOR_CHIP_ENABLED

这些符号是自动生成的。因此只需新增一个含 compatible 属性的绑定，Kconfig 就能使用对应的 DT_HAS_<compatible>_ENABLED 和 DT_COMPAT_<compatible>。
