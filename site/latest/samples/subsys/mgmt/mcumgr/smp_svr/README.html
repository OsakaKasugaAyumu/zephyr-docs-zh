SMP 服务端示例（SMP server）

非官方简体中文译本 · K07 · 英文基线 4.5.99 · K 批目录 · 本页英文原文

在 GitHub 上浏览源码

概述

本示例实现一个简单管理协议（Simple Management Protocol，SMP）服务端。SMP 为 MCUmgr 管理协议提供基本的传输编码。关于 MCUmgr 和 SMP，请参阅设备管理总览（Device Management）。

此示例应用默认支持以下 MCUmgr 传输方式：

  • 命令行（Shell）

  • 蓝牙（Bluetooth）

  • UDP

前置条件

使用客户端工具

要远程访问设备的管理子系统，需要客户端工具。管理子系统文档的工具与库页列出了可用作 Zephyr MCUmgr SMP 服务端客户端的工具。

构建 BLE 控制器

说明

本节仅适用于 Linux 用户。

如果你想通过低功耗蓝牙（BLE）尝试无线设备固件升级（DFU），但没有内置或外接的 BLE 无线设备，可按配合 BlueZ 使用控制器中的步骤构建并使用一个控制器。

构建示例应用

以下步骤说明如何在 Zephyr 中构建和运行包含 MCUboot 的 smp_svr 示例。smp_svr 提供多种构建方式。

构建蓝牙示例：

west build -b nrf52dk/nrf52832 --sysbuild samples/subsys/mgmt/mcumgr/smp_svr -- -DEXTRA_CONF_FILE="bt.conf"

构建支持文件系统管理和 Shell 管理的串口示例：

west build -b frdm_k64f --sysbuild samples/subsys/mgmt/mcumgr/smp_svr -- -DEXTRA_CONF_FILE="serial.conf;fs.conf;shell-mgmt.conf"

说明

原始 UART 模式直接经 UART 设备发送 MCUmgr 数据包，不使用经控制台传输的 SMP 协议。传输的是二进制数据；例如，在同一 UART 上启用 Shell 时就不能使用这种模式。

构建支持文件系统管理的原始 UART（串口）示例：

west build -b nrf52840dk/nrf52840 --sysbuild samples/subsys/mgmt/mcumgr/smp_svr -- -DEXTRA_CONF_FILE="raw-serial.conf;fs.conf"

构建采用 USB CDC_ACM 后端的串口示例：

west build -b nrf52840dk/nrf52840 --sysbuild samples/subsys/mgmt/mcumgr/smp_svr -- -DEXTRA_CONF_FILE="cdc.conf" -DEXTRA_DTC_OVERLAY_FILE="usb.overlay"

说明

如果使用 CDC 覆盖文件构建并准备测试，请务必连接到开发板上直接接至 MCU 的那个 USB 端口。

构建 Shell 示例：

west build -b frdm_k64f --sysbuild samples/subsys/mgmt/mcumgr/smp_svr -- -DEXTRA_CONF_FILE="shell.conf"

SMP 的 UDP 传输同时支持 IPv4 和 IPv6。本示例的 UDP 配置同时启用了两者；IPv4 和 IPv6 也可分别启用或禁用。

构建 UDP 示例：

west build -b frdm_k64f --sysbuild samples/subsys/mgmt/mcumgr/smp_svr -- -DEXTRA_CONF_FILE="udp.conf"

构建使用 802.15.4 Sub-GHz 网络的 UDP 示例：

west build -b beagleconnect_freedom --sysbuild samples/subsys/mgmt/mcumgr/smp_svr -- -DEXTRA_CONF_FILE="udp.conf;802154-subg.conf"

构建支持 DTLS 的 UDP 示例：

west build -b bl5340_dvk/nrf5340/cpuapp --sysbuild samples/subsys/mgmt/mcumgr/smp_svr -- -DEXTRA_CONF_FILE="udp-dtls.conf"

烧写示例镜像

初始应用按 slot-0 构建；闪存分区细节见闪存映射（flash map）。同时烧写 MCUboot 和示例应用：

west flash

示例镜像：hello world!

现在可以运行 smp_svr。复位开发板，再用所选工具的 echo 功能测试应用：该功能向远端目标设备发送一个字符串，让设备原样返回。

J-Link 虚拟大容量存储设备（MSD）与串口的相互影响

有些板载 J-Link（J-Link OB）同时支持 CDC 和 MSC（虚拟大容量存储设备，也称拖放功能）。在这类板上（例如 Nordic 的 nrf52840dk），J-Link 固件的 USB 端点配置会限制最大包长，因此 MSD 功能可能使经 CDC UART 端口发送的 mcumgr 命令失效；使用镜像管理命令更新固件时最容易遇到。按禁用大容量存储设备功能中的说明禁用 J-Link 设备的 MSD 功能即可解决。

设备固件升级（DFU）

现在板上已经运行 SMP 服务端，客户端也能与其通信，可以尝试通常称为“OTA DFU”的无线设备固件升级。蓝牙（BT）和 UDP 都支持这一过程。

DFU 的一般步骤如下：

  • 用 sysbuild 构建启用 MCUboot 的应用，见构建示例应用。

  • 用 MCUmgr 客户端上传已签名的镜像。

  • 用 MCUmgr 客户端列出设备上的镜像。

  • 用 MCUmgr 客户端将上传的镜像标记为测试。

  • 用 MCUmgr 客户端远程复位设备。

  • 用 MCUmgr 客户端确认上传的镜像（可选）。

直接上传镜像及其与 MCUboot 槽位的映射

MCUmgr 目前支持 4 个直接上传目标，其中前两个分别映射到 MCUboot 的主槽位（slot-0）和次槽位（slot-1）。

下面列出 DTS 标签、槽位与 <image> 参数的对应关系：

-n <image>

slot-0

1

“image-1”

slot-1

0, 1

“image-2”

“image-3”

译校注

K07-U02 · 直接上传 ID 不是物理槽号

在所核直接上传模式中，显式上传 ID 是物理槽索引加一：槽 0、1、2、3 若存在，分别对应 ID 1、2、3、4。在所核单镜像自动选槽路径中，0 表示自动选择，并非槽 1 的别名。有 ID 也不代表该槽一定可写；应核对目标的槽位信息。

利用槽位信息命令，可查看所有槽位的信息，并取得更新特定槽位时应使用的上传 image ID。详见槽位信息。

上传已签名的镜像

查阅所选工具的文档，选择要上传的新固件文件，然后开始上传已签名的镜像。

说明

上传开始时，目标设备可能先擦除镜像槽位；在某些设备上，这一步可能需要几十秒。

列出镜像

现在可用所选工具列出远端设备上已有的镜像（slot-0 和 slot-1），工具应显示每个已有镜像的状态和哈希值。

测试镜像

要让 MCUboot 交换镜像，先将新镜像标记为测试，以验证它能否启动；操作方法见所选工具的说明。重启后，MCUboot 将切换到新镜像。

说明

有些工具无需上传镜像就能列出其哈希。也可用 imgtool 的 dumpinfo 命令查看已签名更新文件的镜像哈希，输出格式为 C 语言十六进制数组。例如：

远程复位

可以远程复位设备，从控制台输出观察 MCUboot 如何交换镜像，具体操作见所选工具的文档。复位时 MCUboot 会交换 slot-0 和 slot-1。

确认新镜像

新镜像现已载入 slot-0；除非确认该镜像，否则下次复位时它会被换回 slot-1。请使用所选工具确认镜像。

说明

如果尝试上传与 slot-0 中已烧写镜像完全相同的镜像，两个槽位的哈希值将相同，流程不会成功完成。

译校注

K07-U04 · 上传完成与按哈希标记测试是两步

“流程不会成功”不等于上传命令必定失败。启用相应校验、提供完整文件哈希且目标内容已匹配时，上传可直接报告完成。随后按哈希选择要测试的镜像，可能先匹配到活动槽，因而无法标记测试；不能据此断定所有板卡和工具都在同一步失败。

从文件系统下载文件或向其上传文件

SMP 服务端支持与设备上的文件系统互传文件。例如，文件系统日志后端将文件存入非易失性存储器时，这项功能很有用。使用 sysbuild 构建并烧写 smp_svr，然后用所选工具从文件系统下载文件。必须知道并使用该文件在设备上的完整路径。
